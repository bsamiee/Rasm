1. **`FromUnsafe` contradicts the interface contract and reopens the invalid state the section closes.**
   - Location: the `Age` code block under "Make invalid inputs unrepresentable", and the sentence after it.
   - Claim: `public static Age FromUnsafe(int repr) => new(repr);` and "`FromUnsafe` skips the check and is
     for a value that already passed it."
   - Evidence: the decompile of `LanguageExt.Traits.Domain.DomainType` (arity two) declares
     `static virtual SELF FromUnsafe(REPR repr) { return From(repr).ThrowIfFail(); }`, documented as
     "Either throws an exception or returns a validly constructed `SELF`". The doc overrides that default
     with an unchecked construction, so `Age.FromUnsafe(200)` returns an `Age` outside the domain. The
     positional record struct also publishes `new Age(200)`. A section titled "Make invalid inputs
     unrepresentable" therefore ships a type whose invalid values are representable through two doors.
   - Correction: replace the type header, the constructor, and `FromUnsafe` (probe built with zero
     diagnostics and ran to exit 0 under the repo analyzers; `Try.lift(() => Age.FromUnsafe(200)).Run()`
     returned `Fail`; `default(Age)` is `Value` 0 and stays valid):

     ```csharp
     internal readonly record struct Age : DomainType<Age, int> {
         private Age(int value) => Value = value;

         public int Value { get; }

         public static Fin<Age> From(int repr) => IsValid(repr) ? new Age(repr) : new InvalidAge();

         public static Age FromUnsafe(int repr) => From(repr).ThrowIfFail();
     ```

     The rest of the block (`To`, `IsValid`, the four operators) is unchanged. Replace the prose sentence
     with: "`FromUnsafe` throws when the value is invalid, so it reports a defect in the calling code and
     not an expected input outcome." The lab (`F03/Age.cs`) changes with it; `F03/Samples.cs` calls
     `FromUnsafe` only with valid values and still runs.

2. **A book teaching point was dropped where the replacement code could have kept it true.**
   - Location: the paragraph after the `Age` block.
   - Claim (book, removed): "Callers cannot bypass the invariant" and "The private constructor retains a

   - Correction: restore the first clause as "Callers cannot bypass the invariant, and consumers neither
     repeat validation nor inspect the underlying integer." Restore the design rule bullet as "Keep the
     constructor private so every value passes through `From`." Keep the `IsType`/`HasCode` sentence as it
     stands.

3. **The file never places `Match` at the host.**
   - Location: "Represent possible absence with `Option<A>`" (the `Greetings` block) and the design rule
     "Use `Match` when a concrete result must be selected from the `None` and `Some` cases."
   - Claim: `Match` is presented as ordinary case selection with no boundary named.
   - Evidence: the global ruling makes `Match` a host operation, and `21-languageext-result-types.md` lists
     "`Match` in the middle of a pipeline unwraps a value that the next step lifts again" as a defect. The
     file already names the null boundary for `Optional` but names no boundary for `Match`, so a reader
     building on it puts `Match` inside domain code. `Totality.AgeOf` shows the correct alternative
     (`Bind`) without saying why.
   - Correction: add one sentence after the `Greetings` block: "`Match` belongs at the host, where a result
     type becomes a rendered value; inside the domain `Bind` and `Map` carry the `Some` case forward."

4. **A project built on this file needs `IComparable<Age>` before `Age` becomes a key or is sorted.**
   - Location: the `Age` block (the `<` and `>` operators).
   - Evidence: probe run under the repo analyzers -
     `Try.lift(() => Map((Age.FromUnsafe(30), "a"), (Age.FromUnsafe(40), "b")).Count).Run()` returned
     `Fail(At least one object must implement IComparable.)`. `Map<K, V>` and `Set<K>` order keys through
     `OrdDefault<K>`, which reaches `Comparer<Age>.Default`. `HashMap<Age, V>` works, because the record
     supplies `Equals` and `GetHashCode`.
   - Correction: no doc change is required for the chapter's teaching point. Record in `NOTES/F03.md`
     (which already names the gap) that the failure is a run-time throw, not a compile error, so a package
     that keys on a domain type declares `IComparable<SELF>` and `CompareTo` beside the operators.
