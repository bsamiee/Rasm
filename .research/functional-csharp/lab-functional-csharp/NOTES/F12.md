## Members verified

- `OptionExtensions.Apply(this Option<Func<A, B>> mf, K<Option, A> ma) : Option<B>` returns the concrete `Option<B>` with no `.As()`.

- `FunctorExtensions` extension on `Func<A, B, C>`: `Map(K<F, A>) : K<F, Func<B, C>>`, chained into `Apply` then `.As()`.
- `Prelude.fun<T1, T2, R>(Func<T1, T2, R>)` gives a static lambda its delegate type in place.
- `Prelude.Pure(A)` converts implicitly to `Option<Func<int, int, int>>`.
- `FunctorLaw<Option>.validate(Some(1))`, `ApplicativeLaw<Option>.validate()`, `MonadLaw<Fin>.validate()` : `Validation<Error, Unit>`, all `IsSuccess`.
- `Option<A>.SelectMany` and `Validation<F, A>.SelectMany` (ternary shape) drive the two-`from` queries; `Option`, `Fin`, and `Validation` declare instance `Select`.
- `Option<A>.ToValidation<Error>(Error)` with a `sealed record NotANumber() : Expected("not a number", 1200)`.
- `Validation<Error, A>` implicit lifts from `A` and from an `Expected` subclass inside a target-typed conditional expression.

## Corrections to the plan

- The plan's row names `Gen.Int.Select(...)` for the `Option` generator. It compiles, but the unbounded `int` product overflows under the repo's checked arithmetic, and `Sample` reports `Arithmetic operation resulted in an overflow` as a counterexample after shrinking. The doc uses `Gen.Int[-1000, 1000]`.
- `Seq(...).Contains(x)` is ambiguous (CS0121) between `FoldableExtensions.Contains` and `Enumerable.Contains`. `Set(...).Contains(x)` is an instance method and resolves.
- `Gen.Select(option, option)` compiles but fails RCS1196; the instance form `option.Select(option)` is the accepted spelling.
- `type is "mobile" or "home"` fails MA0127 (string pattern); the smart enum lookup replaces it, and its string key compares case-insensitive, so `"MOBILE"` is accepted (checked).
- `MonadLaw<IO>.validate` is not named in the doc (it throws inside the library, per LAB-NOTES).

## Integration changes

- `NumberType` is a `[SmartEnum<string>]` with `Mobile` and `Home`; `CountryCode` and `Number` are `[ValueObject<string>]` structs with their rule in `ValidateFactoryArguments` and both `ComparerAccessors.StringOrdinal` attributes (`TTRESG048`).
- The three `Expected` records implement `IValidationError<X>` and each type carries `[ValidationError<X>]`, so `Validate` returns the typed error and the validators only change the shape to `Validation<Error, T>`.
- `new NumberType("fax")` and `new CountryCode("gb")` no longer compile: the constructors are generated and private.
- The smart enum adapter spells `item!` because the generated `out NumberType? item` carries no flow annotation tied to a `null` return; the struct adapters need no `!`.
- Prose: the paragraph before the fence names the smart enum, the value objects, `IValidationError<T>`, and `Validate`.
- `Samples.cs`: two checks added (upper-case key accepted, lower-case country rejected with `InvalidCountryCode`).
