## Corrections to the plan

- The plan named `TryAdd` then `Find` for the registry. `AtomHashMap<K, V>.FindOrAdd(K key, V value) : V` is the same double check in one atomic step and returns the registered process directly. `TryAdd` then `Find` would return `Option<V>` for a key that is always present after the add, and the `None` branch would be unreachable. The doc and the lab use `FindOrAdd` and the doc names the double check as that call.
- A losing registration leaves a forked reducer waiting on an inbox that nobody posts to. The lab completes that inbox inside the lookup (`ReferenceEquals(resolved, started) ? IO.pure(unit) : started.Inbox.Complete()`), and the doc states it in one sentence.
- `commute` returns the in-transaction value. `atomic(Func<R>)` passes `returnRefId = long.MinValue`, so `CommitCommutes` never substitutes the committed value into the transaction result; the uncontended probe cannot tell them apart. Only `atomic(Func<CommuteRef<R>>)` returns the committed value. The `Ref`/`atomic` sample now lives only in the collections addendum, and this lab no longer compiles `Transfers.Move`.
- A persistence failure must reach the caller. `Handle` catches the failure of `persist` and posts the `Error` to `command.Replies` before the reducer ends, otherwise the caller waits on a reply conduit that the dead reducer will never fill.
