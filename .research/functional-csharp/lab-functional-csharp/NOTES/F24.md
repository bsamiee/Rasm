## Corrections with evidence

- CORRECTION to the API document and to the plan: `AtomHashMap<K, V>.FindOrMaybeAdd(K, Func<Option<V>>)` returns `Some(default(V))` when the factory returns `None` and `V` is a value type. Decompile: the method deconstructs `Items.FindOrMaybeAddWithLog(key, None)` into `V val` and returns `val` through the implicit `V -> Option<V>` conversion; `TrieMap.FindOrMaybeAddWithLog` returns `option.Value` of a `None` option (`default`) on the declined path. Run: `registry.FindOrMaybeAdd("d", () => Option<int>.None)` returned `Some(0)` with nothing added. The instance `TrackingHashMap`/`Map` `FindOrMaybeAdd` return `(Map, Option<V> Value)` and do not share this path. The doc leaves `FindOrMaybeAdd` out.
- Confirmed the API document: `FoldM` walks tail to head (`Seq(1, 2, 3).FoldM("", (t, x) => Some(t + x))` is `Some("321")`) and `FoldBackM` walks head to tail (`Some("123")`).
- `FoldWhile` and `FoldUntil` test the predicate before each step with the state so far and the next element: `Seq(4, 4, 4, 4).FoldWhile(0, +, p => p.State < 10)` is `12`, `Seq(1, 2, -1, 5).FoldUntil(0, +, p => p.Value < 0)` is `3`.
- `Exists` over `Seq(1, 2, 3, 4)` visited two elements before the first even; `ForAll` over `Seq(1, -1, 3, 4)` visited two elements before the first negative. Counted with an `Atom<int>` swapped inside the predicate.
- Seedless `Fold()` over `Seq(Seq(1), Seq(2, 3))` is `[2, 3, 1]`, matching the F05 correction.
- `FoldM`/`FoldBackM` need typed lambda parameters (`static (string text, int x) => Some(...)`) so that `M` infers from the lambda return type.
- Analyzer rulings met here: CS0104 `HashSet<int>` is ambiguous between `System.Collections.Generic.HashSet<T>` and `LanguageExt.HashSet<A>` under the implicit usings, so a declared hash set type is `LanguageExt.HashSet<int>` (the `HashSet(3, 1, 2)` constructor call resolves). VSTHRD200 treats `Iterable<A>` as an awaitable return type and demands an `Async` suffix, so the `Iterable` is a local inside `Doubled` and the method returns `Seq<int>`. IDE0048 rejects `a * 0 + x * x` without parentheses; the memo witness uses a block-bodied lambda instead.
- `memoK<IO, int>(...)` needs explicit type arguments; the lambda alone does not infer `F`.
