## Corrections and findings

- `Classify` takes the raw `string` and returns the case: `string.IsNullOrWhiteSpace(text) ? new UserInput.NoInput() : parseInt(text).Match<UserInput>(...)`, so no `switch` and no re-classification of an already classified value.
- `IO.lift(() => Classify(console()))` infers `IO<UserInput>` because `Classify` returns the base type; no cast to `UserInput` is needed.
- Analyzer rulings hit in this lab: IDE0130 requires the namespace to match the folder, so the flagged `Customer` record (which shares its name with the union base) lives in `F10/Flagged/Customer.cs` under `namespace Lab.F10.Flagged;`; MA0007 requires a trailing comma after the last `switch` expression arm (the doc blocks carry that comma); CA1508 rejects `local is Case { ... }` on a local whose static type already proves the pattern, so the sample tests the cases through `Seq<Customer>.Exists`; MA0127 rejects `is TextInput { Input: "abc" }` on a string, so the check uses `string.Equals(..., StringComparison.Ordinal)`.
- Records with non-nullable reference properties need `required` or a positional constructor; the book's bare `{ get; init; }` on `string`/`Location` does not compile under nullable warnings-as-errors. The offerings keep `init` properties with `required`; the customer, person, and input cases are positional.
- The API document row for `OptionT<M, A>` ("`Option` stacked over any `M`") holds; nothing in this lab contradicts it.
