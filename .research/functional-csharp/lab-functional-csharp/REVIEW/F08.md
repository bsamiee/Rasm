1. **Location** line 97-101 (the `Age` block), with lines 94, 106-110.
   **Claim** "`internal readonly record struct Age(int Value) { public static Option<Age> From(int value) => value is >= 0 and < 120 ? new Age(value) : Option<Age>.None; }`" and "`Age.From` returns `Option<Age>`".
   **Evidence** `21-languageext-result-types.md:89` and `03-signatures-and-types.md:42` both declare `internal readonly record struct Age(int Value) : DomainType<Age, int>` with `public static Fin<Age> From(int repr)`. The global ruling row for domain values fixes a smart constructor at `DomainType<SELF, REPR>.From : REPR -> Fin<SELF>`, and `03` already shows the boundary conversion `Age.From(value).ToOption()`. One type name owns two incompatible `From` signatures across the corpus.
   **Correction** replace the block with the corpus form and convert at the boundary:
   ```csharp
   internal sealed record InvalidAge() : Expected("age out of range", 1001);

   internal readonly record struct Age(int Value) : DomainType<Age, int> {
       public static Fin<Age> From(int repr) => repr is >= 0 and < 120 ? new Age(repr) : new InvalidAge();

       public static Age FromUnsafe(int repr) => new(repr);

       public int To() => Value;
   }
   ```
   line 94 becomes "`Bind` applies the function and removes that extra layer. `Age.From` returns `Fin<Age>`, and `ToOption` converts the rejection into absence at the boundary:"; the `ParseAge` block becomes
   ```csharp
   public static Option<Age> ParseAge(string input) =>
       parseInt(input).Bind(static value => Age.From(value).ToOption());
   ```
   line 110 becomes "If parsing fails, `Age.From` is skipped. If parsing succeeds but the number is not a valid age, `Age.From` returns `InvalidAge` and `ToOption` maps it to `None`. The composed result remains `Option<Age>`."; `TotalAge` reads `age.To()` in place of `age.Value`. The lab (`F08/Domain.cs`, `CorePatterns.cs`, `Samples.cs`) changes with it.
