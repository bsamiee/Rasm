## Installer payloads

Not obtained. See `installers/NOT-OBTAINED.txt`. Consequences: no bundle ids, no `.InDesignPlugin` or `.aip` file names, no frameworks, no `strings` scan, no Info.plist. What the vendor states about the footprint:

- macOS plug-in folder `/Applications/Adobe InDesign 2020/Plug-Ins/WinSoft/` (FAQ, 2020 wording).
- Uninstaller `ScribeDOOR InDesign 2020 Uninstaller` under `/Library/Application Support/Winsoft Installers/ScribeDOOR InDesign/`, also described as "Application > Utilities > WinSoft installers".
- Windows uninstall through Control Panel > Add or Remove Programs > ScribeDOOR.
- The installer adds fonts ("ScribeDOOR installs WinSoft Pro which supports Roman, Arabic or Hebrew") and macOS keyboard layouts (Khmer, Lao, Sinhala, Urdu, Telugu, reduced to Lao on newer macOS).
- Activation is a serial number entered in a dialog at host launch; the trial build has the serial field disabled.

The 2014 install note describes a `ScribeDOOR-ID_WinMac.zxp` installed through Adobe Extension Manager, which is the CS6 and early CC delivery and no longer matches the 2020+ installer described in the FAQ.

## Engine or UI

Verdict: ScribeDOOR is a user interface over the World-Ready composer that Adobe ships inside every InDesign and Illustrator build, plus a small set of genuine additions (an Arabic spelling dictionary, Hebrew hyphenation, a Selection Helper palette, a Reverse Layout command, fonts and keyboard layouts). It does not add a composer or shaper of its own.

Evidence:

- The vendor's own description of the core feature is "Giving access to the 'WorldReady Composer'", and it attributes the technology to "WRServices technology (a component developed by WinSoft International) which was integrated in most Adobe products". The 2012 datasheet says "WinSoft International co-developed with Adobe the WorldReady composer". WinSoft is describing the engine already inside the host.
- Every control on the InDesign panel maps one-to-one, including option counts and option names, onto a documented InDesign DOM property or enumeration (table below). The seven Justification entries match the seven `ParagraphJustificationOptions` members; the six Diacritic Positioning entries match the six `DiacriticPositionOptions` members; the nineteen Digits entries match the twenty `DigitsTypeOptions` members with only `FULL_FARSI_DIGITS` not shown; the four composers match the four composer key strings; Kashida width 0 to 4 matches `paragraphKashidaWidth` "0 is none, 1 is short, 2 is medium, 3 is long".
- Adobe says the same thing about the host: "Every InDesign version contains all the Middle-Eastern and Chinese–Japanese–Korean functionality" (Kahrel, hosted at CreativePro), and Adobe's help states the shaper is Adobe's: "Starting with the InDesign 19.0 version (October 2023), Harfbuzz is the default text shaping engine of the World Ready Composer."
- The guide never claims any composition behaviour of its own; where it describes justification algorithms it describes what "ScribeDOOR will" do in the same words Adobe uses for the built-in Arabic and Naskh justification.
- Not verifiable without the binary: whether the plug-in bundles a private copy of WRServices or any of HarfBuzz, ICU, Uniscribe or CoreText. The `strings` scan requested in the brief could not run. Given that the panel exposes exactly the host's enumerations and nothing beyond them, a private shaper is unlikely, but that is inference.

## InDesign DOM facts

All rows below were read on 2026-09-11 from the indesignjs.de "indesign-latest" ExtendScript reference (verbatim rows in `sources/dom-extracts/indesign-me-dom.txt`) unless another source is named.

- `composer`: "composer | String | read/write | The text composer to use to compose the text." on Paragraph, ParagraphStyle, Character, Text, Story and TextDefault. The locale-independent values come from Uwe Laubender (Adobe community, 2019): "Paragraph composers: $ID/HL Single, $ID/HL Composer. Adobe World-Ready Composers: $ID/HL Single Optyca, $ID/HL Composer Optyca. Japanese Composers: $ID/HL Single J, $ID/HL Composer J." and "With a German InDesign you could ask with app.findKeyStrings() ... Result is an array that contains "$ID/HL Composer Optyca"". A second community answer maps them as `"$ID/HL Single Optyca" > Adobe World-Ready Single-line Composer`, `"$ID/HL Composer Optyca" > Adobe World-Ready Composer`. Assigning the localized display name fails outside that locale.
- `Document.changeComposer()`: it exists. The brief assumed it did not. The Document page lists it among the methods ("addEventListener, adjustLayout, align, asynchronousExportFile, changeColor, changeComposer, changeGlyph, ...") with the row "undefined changeComposer () Change comoser to optyca" (typo in the source). Adobe's Middle Eastern Scripting Guide, written for InDesign Server: "InDesign Server comes with a document method changeComposer that can be used in a Roman publication to changes the composer for all text frames to the Adobe World-Ready Composer. Adobe Paragraph Composer is changed to Adobe World-Ready Paragraph Composer; Adobe Single-line Composer is changed to Adobe World-Ready Single-line Composer." with the sample `myDocument.changeComposer();`. A Stack Exchange answer reports it working in desktop InDesign: "The Document class does not seem to have this Composer property. However, it has a method called changeComposer(). On applying this method, the composer changed to Adobe World-Ready Paragraph Composer." Not verified in a running host during this research. It converts existing text; it does not change `textDefaults`, which stays a per-property assignment.
- `app.textDefaults` and `Document.textDefaults` (TextDefault) carry the same `composer`, `paragraphDirection`, `characterDirection`, `digitsType`, `kashidas`, `paragraphKashidaWidth`, `diacriticPosition`, `paragraphJustification`, `characterAlignment` properties. Adobe's guide: "myDocument.textDefaults.paragraphDirection = ParagraphDirectionOptions.rightToLeftDirection;" and "myDocument.textDefaults.paragraphJustification = ParagraphJustificationOptions.arabicJustification;".
- `paragraphDirection`: "paragraphDirection | ParagraphDirectionOptions ParagraphDirectionOptions.LEFT_TO_RIGHT_DIRECTION ParagraphDirectionOptions.RIGHT_TO_LEFT_DIRECTION | read/write | Paragraph direction."
- `characterDirection`: "characterDirection | CharacterDirectionOptions CharacterDirectionOptions.DEFAULT_DIRECTION CharacterDirectionOptions.LEFT_TO_RIGHT_DIRECTION CharacterDirectionOptions.RIGHT_TO_LEFT_DIRECTION | read/write | The direction of the character." A sibling `keyboardDirection` uses the same enum.
- `digitsType`: "digitsType | DigitsTypeOptions ... | read/write | The digits type." with 20 members: ARABIC_DIGITS, BENGALI_DIGITS, BURMESE_DIGITS, DEFAULT_DIGITS, DEVANAGARI_DIGITS, FARSI_DIGITS, FULL_FARSI_DIGITS, GUJARATI_DIGITS, GURMUKHI_DIGITS, HINDI_DIGITS, KANNADA_DIGITS, KHMER_DIGITS, LAO_DIGITS, MALAYALAM_DIGITS, NATIVE_DIGITS, ORIYA_DIGITS, TAMIL_DIGITS, TELUGU_DIGITS, THAI_DIGITS, TIBETAN_DIGITS. Enum descriptions are one-liners ("Farsi digits", "Full Farsi digits"); the difference between FARSI and FULL_FARSI is not documented and is unverified.
- `kashidas`: "kashidas | KashidasOptions KashidasOptions.DEFAULT_KASHIDAS KashidasOptions.KASHIDAS_OFF | read/write | Use of Kashidas for justification".
- `paragraphKashidaWidth`: "paragraphKashidaWidth | Number | read/write | Paragraph kashida width. 0 is none, 1 is short, 2 is medium, 3 is long". There is no `ParagraphKashidaWidth` enumeration (the page returns 404); the property is a plain Number. Adobe's UI adds "Stylistic" as a fifth choice, which the guide maps to 4.
- `diacriticPosition`: "diacriticPosition | DiacriticPositionOptions DEFAULT_POSITION LOOSE_POSITION MEDIUM_POSITION OPENTYPE_POSITION OPENTYPE_POSITION_FROM_BASELINE TIGHT_POSITION | read/write | Position of diacriticical characters." plus "xOffsetDiacritic | Number | read/write | The x (horizontal) offset for diacritic adjustment." and "yOffsetDiacritic | Number | read/write | The y (vertical) offset for diacritic adjustment."
- `paragraphJustification`: "paragraphJustification | ParagraphJustificationOptions ARABIC_JUSTIFICATION DEFAULT_JUSTIFICATION NASKH_JUSTIFICATION NASKH_KASHIDA_JUSTIFICATION NASKH_KASHIDA_JUSTIFICATION_FRAC NASKH_TATWEEL_JUSTIFICATION NASKH_TATWEEL_JUSTIFICATION_FRAC | read/write | Paragraph justification." Enum descriptions: NASKH_KASHIDA_JUSTIFICATION "Kashidas. Use naskh justification if you want to also use Justifcation Alternates.", NASKH_KASHIDA_JUSTIFICATION_FRAC "Fractional Kashidas. ...", NASKH_TATWEEL_JUSTIFICATION "Kashidas without Stretched Connections.", NASKH_TATWEEL_JUSTIFICATION_FRAC "Fractional Kashidas without Stretched Connections."
- `Story.storyPreferences.storyDirection`: "storyDirection | StoryDirectionOptions LEFT_TO_RIGHT_DIRECTION RIGHT_TO_LEFT_DIRECTION UNKNOWN_DIRECTION | read/write | The direction of the story." Adobe's guide: "parentStory.storyPreferences.storyDirection = StoryDirectionOptions.leftToRightDirection;".
- `Table.tableDirection`: "tableDirection | TableDirectionOptions LEFT_TO_RIGHT_DIRECTION RIGHT_TO_LEFT_DIRECTION | read/write | The direction of the the table".
- `TextFrame` and `TextFramePreference`: no direction property. Direction lives on the story, the paragraph and the character. `DocumentPreference.columnDirection` (HORIZONTAL or VERTICAL) is the CJK vertical text switch, not bidi.
- `Document.textPreferences` and `Application.textPreferences` (TextPreference): no Middle East preference except "shapeIndicAndLatinWithHarbuzz | Boolean | read/write | If this bool is set to true, shaping of Indic & Latin characters will be done through Harfbuzz Shaping engine, instead of Lipika." The Right to Left preferences Adobe's help describes (Force Neutral Character Direction According to the Keyboard Input, Cursor Movement Visual or Logical, Use Native Digits when typing in Arabic Scripts) have no property on TextPreference, GeneralPreference or Application in the reference; they are unverified as scriptable.
- `characterAlignment`: "characterAlignment | CharacterAlignment ALIGN_BASELINE ALIGN_EM_BOTTOM ALIGN_EM_CENTER ALIGN_EM_TOP ALIGN_ICF_BOTTOM ALIGN_ICF_TOP | read/write | The alignment of small characters to the largest character in the line." This is the CJK character alignment, not a bidi control.
- `DocumentPreference.pageBinding`: "pageBinding | PageBindingOptions DEFAULT_VALUE LEFT_TO_RIGHT RIGHT_TO_LEFT | read/write | The placement of the page binding."
- `SpecialCharacters` members for the ME set: ARABIC_COMMA, ARABIC_KASHIDA, ARABIC_QUESTION_MARK, ARABIC_SEMICOLON, HEBREW_GERESH, HEBREW_GERSHAYIM, HEBREW_MAQAF, HEBREW_SOF_PASUK, LEFT_TO_RIGHT_EMBEDDING, LEFT_TO_RIGHT_MARK, LEFT_TO_RIGHT_OVERRIDE, RIGHT_TO_LEFT_EMBEDDING, RIGHT_TO_LEFT_MARK, RIGHT_TO_LEFT_OVERRIDE, ZERO_WIDTH_JOINER, ZERO_WIDTH_NONJOINER.
- `PageNumberStyle` ME members: ARABIC_ABJAD, ARABIC_ALIF_BA_TAH, HEBREW_BIBLICAL, HEBREW_NON_STANDARD.
- OpenType flags on text objects: `otfJustificationAlternate` "If true, use alternate justification forms in OpenType fonts", `otfStretchedAlternate` "If true, use stretched alternate forms in OpenType fonts", `otfOverlapSwash`, `otfStylisticAlternate`, `ligatures`, `otfDiscretionaryLigature`, `otfContextualAlternate`.

ME edition versus international edition. Adobe's current help: "World-Ready composers let you create and edit text in Middle Eastern and other complex-script languages. To access full right-to-left and typographic support for these languages, install Hebrew or Arabic versions of InDesign through the Creative Cloud desktop app." and the older page: "Arabic and Hebrew supported in a Middle Eastern version with full right-to-left language support, Arabic/Hebrew features, and an English interface; also in a North African French (Français*) version". The ME edition puts these controls in the Paragraph, Character, Story and Table panels and in Edit > Preferences > Right to Left. The international edition hides that UI but the DOM works: Kahrel, "Every InDesign version contains all the Middle-Eastern and Chinese–Japanese–Korean functionality. The script simply exposes the Middle-East functionality and makes it usable." and "Naturally, non-ME versions of InDesign don't expose ME attributes in the Find/Change window, but the Right-to-Left panel can be used for that." Phinney (2009, on CS4): "Because it's only the UI that is missing in regular InDesign CS4 ... In InDesign CS4, all these features are accessible to scripting, and the scripting interface is documented!" and "These features are also open to plug-ins." Everything ScribeDOOR does on the InDesign panel therefore has a documented scripting path in the edition its customers own.

Shaper: Adobe help, "Starting with the InDesign 19.0 version (October 2023), Harfbuzz is the default text shaping engine of the World Ready Composer. You can change the default shaping engine using a script." That script sets `shapeIndicAndLatinWithHarbuzz`.

## Illustrator DOM facts

Rows read on 2026-09-11 from the indesignjs.de "illustrator-latest" ExtendScript reference (verbatim in `sources/dom-extracts/illustrator-me-dom.txt`).

- `ParagraphAttributes.composerEngine`: "composerEngine | ComposerEngineType ComposerEngineType.adornment ComposerEngineType.latinCJKComposer ComposerEngineType.optycaComposer | read/write | Composer engine attribute." Enum values latinCJKComposer 0, optycaComposer 1, adornment 2. `everyLineComposer` (Boolean) chooses every-line versus single-line. So World-Ready Every-Line = `optycaComposer` plus `everyLineComposer = true`.
- `ParagraphAttributes.paragraphDirection`: "paragraphDirection | ParagraphDirectionType LEFT_TO_RIGHT_DIRECTION RIGHT_TO_LEFT_DIRECTION | read/write | Main writing direction attribute."
- `ParagraphAttributes.kashidaWidth`: "kashidaWidth | KashidaWidthType kashidaLong kashidaMedium kashidaNone kashidaSmall kashidaStylistic | read/write | The Kashida Width attribute." Values kashidaNone 0, kashidaSmall 1, kashidaMedium 2, kashidaLong 3, kashidaStylistic 4. This is exactly ScribeDOOR's Illustrator Justification drop-down (None, Short, Medium, Long, Stylistic).
- `ParagraphAttributes.justification`: "justification | Justification CENTER FULLJUSTIFY FULLJUSTIFYLASTLINECENTER FULLJUSTIFYLASTLINELEFT FULLJUSTIFYLASTLINERIGHT LEFT RIGHT | read/write | Paragraph justification." Alignment only; there is no Arabic or Naskh justification enum in Illustrator.
- `CharacterAttributes.kashidas`: "kashidas | KashidasType DEFAULT_KASHIDAS KASHIDAS_OFF KASHIDAS_ON | read/write | Kashidas attribute." (DEFAULT_KASHIDAS and KASHIDAS_ON both carry value 0 in the reference.)
- `CharacterAttributes.digitSet`: "digitSet | DigitSetType ARABIC_DIGITS DEFAULT_DIGITS FARSI_DIGITS HINDI_DIGITS | read/write | Digit set attribute." Four values only (DEFAULT 0, ARABIC 1, HINDI 2, FARSI 3). ScribeDOOR's Illustrator Digits menu shows seventeen entries, so the thirteen South Asian digit sets come from the ATE plug-in API, not from the ExtendScript DOM.
- `CharacterAttributes.diacVPos`: "diacVPos | DiacVPosType DEFAULT_POSITION LOOSE_POSITION MEDIUM_POSITION OPENTYPE_POSITION TIGHT_POSITION | read/write | Diacritics positioning attribute." plus `diacXOffset` and `diacYOffset` (Number). Matches ScribeDOOR's Diacritics Type and X, Y.
- `CharacterAttributes.justificationAlternates`: "justificationAlternates | Boolean | read/write | Justification alternates attribute." plus `ligature`, `contextualLigature`, `discretionaryLigature`, `stylisticAlternates`, `ornaments`.
- `CharacterAttributes.language`: LanguageType includes ARABIC, FARSI, HINDI, BENGALIINDIA, GUJARATI, KANNADA, MALAYALAM, MARATHI, ORIYA, PUNJABI, TAMIL, TELUGU; no HEBREW or URDU member appears in the extracted list (unverified whether the page is complete).
- Character direction: no `characterDirection` property exists anywhere in the Illustrator ExtendScript reference (grep over CharacterAttributes, ParagraphAttributes, TextRange, Story, TextFrameItem, Application, Preferences returned nothing). ScribeDOOR's Character Direction drop-down in Illustrator has no scripting equivalent.
- Story direction: no direction property on Story or TextRange. ScribeDOOR's Story icons in Illustrator have no scripting equivalent.
- `TextFrameItem.orientation`: "orientation | TextOrientation HORIZONTAL VERTICAL | read/write | The orientation of the text in the frame." That is CJK vertical text, not bidi; ScribeDOOR does not touch it.
- Text engine preference: `app.preferences.setIntegerPreference(key, value)` exists but the key for Preferences > Type > Text Engine is not documented in the reference or in any page found; unverified.

Illustrator UI edition facts. Adobe help: "Illustrator supports Arabic and Hebrew in certain versions with full right-to-left language support ... Middle Eastern version with an English interface ... North African French (Français*) version", and "In the Chinese, Japanese, and Korean versions of Illustrator, text direction, digit types, automatic Kashida insertion, and diacritical marks are not available." In the international edition the Preferences > Type option "Show Indic Options" reveals the Middle Eastern & South Asian composers in the Paragraph panel menu but not the rest; a 2020 community report with screenshots: "With Show Indic options activated this is what the panels look like (Illustrator 25.0.1 ...). Only the composer option is available, not text direction or digit options etc." A 2024 thread on Illustrator 28.6 reports that even the "English یدعم العربیه" install lacked RTL and Farsi digit controls until the Creative Cloud app language was switched to English (Arabic); Adobe staff replied "Please switch the language setting to English (Arabic) in the Creative Cloud Desktop app preferences." So in Illustrator the vendor edition matters more than in InDesign, and the ExtendScript DOM covers less of ScribeDOOR's panel than InDesign's does.

## What we build ourselves

Goal: a Persian-first equivalent of the ScribeDOOR InDesign panel, plus a smaller Illustrator script, using only the documented DOM.

Shape:

1. A UXP plug-in for InDesign 2026 with one panel mirroring the ScribeDOOR groups (Binding, Story, Table, Paragraph, Character, Diacritics), reading and writing the properties in the mapping table against `app.selection`, and with nothing selected against `app.activeDocument.textDefaults` (or `app.textDefaults` when no document is open), the same contract Kahrel's panel uses. Adobe's Middle Eastern Scripting Guide is already written in UXP form (`const { app, ParagraphDirectionOptions } = require("indesign")`), so its samples port directly.
2. A style pass: a command that creates or redefines paragraph styles `Persian Body`, `Persian Heading`, `Persian Caption` and character styles `Latin Inline`, `Digits Latin`, setting the properties below, so the "ScribeDOOR Paragraph Format" pane is replaced by styles the user applies. A UXP panel cannot add a pane to Paragraph Style Options; the style objects accept every property directly.
3. A document command equivalent to "Apply Adobe World-Ready Composers": call `document.changeComposer()`, then set `textDefaults.composer` so new frames follow; verify in a running host that `changeComposer()` behaves in desktop InDesign as the Server guide describes.
4. An ExtendScript `.jsx` twin of the panel logic for InDesign 2020 to 2025 hosts and for Illustrator, since Illustrator's text attributes are reachable from ExtendScript only (the Illustrator UXP DOM's text coverage was not checked and is unverified).
5. Find/Change support: set the same properties on `app.findTextPreferences` and `app.changeTextPreferences`, which Kahrel's panel demonstrates works in the international edition.
6. Insert Special Character: a submenu writing `SpecialCharacters.*` members and plain code points (U+25CC dotted circle, U+200C, U+200D, U+200E, U+200F, U+061F, U+060C, U+061B, U+066C, U+066B, U+FDFC rial sign) at the insertion point.

Persian defaults to ship (InDesign):

```js
// UXP, InDesign 2026
const { app, ParagraphDirectionOptions, CharacterDirectionOptions, DigitsTypeOptions,
        KashidasOptions, ParagraphJustificationOptions, DiacriticPositionOptions,
        Justification, StoryDirectionOptions, PageBindingOptions } = require("indesign");

const persianBody = {
  composer: "$ID/HL Composer Optyca",                       // Adobe World-Ready Paragraph Composer
  paragraphDirection: ParagraphDirectionOptions.RIGHT_TO_LEFT_DIRECTION,
  characterDirection: CharacterDirectionOptions.DEFAULT_DIRECTION,
  justification: Justification.RIGHT_ALIGN,                // FULLY_JUSTIFIED for justified body text
  digitsType: DigitsTypeOptions.FARSI_DIGITS,              // FULL_FARSI_DIGITS to be compared in a host
  kashidas: KashidasOptions.DEFAULT_KASHIDAS,
  paragraphKashidaWidth: 1,                                 // 0 none, 1 short, 2 medium, 3 long
  paragraphJustification: ParagraphJustificationOptions.NASKH_KASHIDA_JUSTIFICATION,
  diacriticPosition: DiacriticPositionOptions.OPENTYPE_POSITION,
  otfJustificationAlternate: false,
  hyphenation: false,
  appliedLanguage: "$ID/Arabic"                            // no Persian dictionary exists in InDesign, verify the key string
};
const doc = app.activeDocument;
doc.textDefaults.properties = persianBody;
doc.documentPreferences.pageBinding = PageBindingOptions.RIGHT_TO_LEFT;
for (const story of doc.stories.everyItem().getElements()) {
  story.storyPreferences.storyDirection = StoryDirectionOptions.RIGHT_TO_LEFT_DIRECTION;
}
```

Persian defaults for Illustrator (ExtendScript):

```js
// ExtendScript, Illustrator 2026
var tf = app.activeDocument.selection[0];              // a TextFrameItem
var p = tf.textRange.paragraphAttributes;
p.composerEngine = ComposerEngineType.optycaComposer;  // World-Ready
p.everyLineComposer = true;                            // Every-Line (paragraph) composer
p.paragraphDirection = ParagraphDirectionType.RIGHT_TO_LEFT_DIRECTION;
p.justification = Justification.RIGHT;
p.kashidaWidth = KashidaWidthType.kashidaSmall;
var c = tf.textRange.characterAttributes;
c.digitSet = DigitSetType.FARSI_DIGITS;
c.kashidas = KashidasType.DEFAULT_KASHIDAS;
c.diacVPos = DiacVPosType.OPENTYPE_POSITION;
c.language = LanguageType.FARSI;
```

What the DOM cannot replicate:

| ScribeDOOR item | Why not | Our answer |
| --- | --- | --- |
| Arabic spelling dictionary (ISIS) | Dictionaries are plug-in providers, not DOM state; InDesign has no Persian dictionary at all | Out of scope, or a separate Hunspell dictionary investigation (Adobe help lists "Add or remove Hunspell dictionary") |
| Hebrew hyphenation | Same | Out of scope for Persian |
| Illustrator character direction, story direction, South Asian digit sets | Absent from the Illustrator ExtendScript DOM | Accept the gap; Persian text needs paragraph direction, digits and kashida width, which the DOM has |
| Selection Helper | A palette rendering each glyph of the selection | Re-implementable as a UXP panel over `selection[0].characters`; low priority |
| Reverse Layout | A layout transform, not a property | Script `pageBinding` plus mirrored item geometry as a later task |
| Pane inside Paragraph Style Options | Plug-in SDK only | Styles created by command instead |
| Right to Left preferences (neutral character direction, cursor movement, native digits when typing) | No documented DOM property | Users set them in the ME edition UI; in the international edition they stay at defaults |
| WinSoft Pro fonts, keyboard layouts | Installer payload | Recommend Vazirmatn or Noto Naskh Arabic and the macOS Persian keyboard |
| Hidden-UI editions | The international edition hides the Paragraph panel's composer entries and the ME panels; nothing in the DOM turns that UI on | Our panel is that UI |

Open verifications for the first host session (none were run here because the brief forbids touching Adobe apps): `changeComposer()` on desktop, the `FARSI_DIGITS` versus `FULL_FARSI_DIGITS` rendering, the order-based mapping of the seven justification entries and the six diacritic entries, the `"$ID/Arabic"` language key string, and whether the 2026 UXP `require("indesign")` exposes the same property names as ExtendScript for `xOffsetDiacritic` and `paragraphKashidaWidth`.
