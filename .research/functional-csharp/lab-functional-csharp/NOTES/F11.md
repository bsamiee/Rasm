## Corrections and findings

- CORRECTION: `ManyErrors.IsType<E>()` tests the members, not the container. The decompile reads `Errors.Exists(e => e.IsType<E>())`, so `IsType<ManyErrors>()` on an accumulated error is `false` (run evidence: the check failed), while `IsType<InvalidBic>()` and `IsType<TransferDateIsPast>()` on the same value are both `true`. `ManyErrors.IsExceptional` is `Errors.Exists(e => e.IsExceptional)` and `IsExpected` is `Errors.ForAll(...)`, so a host `Match` on `IsExceptional` classifies an accumulated business failure as expected.

- `Seq<string>.Contains(string)` is ambiguous (CS0121) between `FoldableExtensions.Contains` and `Enumerable.Contains` under the lab's global usings. The stub uses `string.Equals(a, b, StringComparison.Ordinal)` instead.
- `==` between two strings fails MA0006 under the repo analyzers. Every string comparison in a doc block spells `string.Equals(..., StringComparison.Ordinal)`.
- `Catch(int, Func<Error, A>)` (the `Applicative<F>` value overload) resolves without ambiguity when the handler returns the success type. The `K<F, A>`-returning form in `LAB-NOTES.md` is not the only working form.
- The plan's `Try.lift(...).Run()` alternative for exception capture is not shown in the doc. `Save` is an effect, so the file shows one path: `IO.lift` with the capture on the `IO` error channel.
- The plan's `Eff<RT, A>.Run(rt)` host exit is not shown. The file reads no capability, so the effect is a bare `IO<A>` and the host exit is `RunSafe()` then `Match`. A file that reads a capability adds `Eff<RT, A>`.
- The API document's claims used here (`Fin.MapFail`, `Fin.BiMap`, `Fin.IfFail`, `Fin.SelectMany` with `guard`, `ValidationExtensions.ToFin`, `Error.New(string, Error)`, `Error.IsType<E>`, `Error.HasCode`, `IO.lift(Fin<A>)`, the three `Catch` selectors) all held.
