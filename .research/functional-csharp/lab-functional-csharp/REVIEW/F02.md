# REVIEW F02 — `02-purity.md`

Scope checks that passed and are not itemized: all seven `csharp` blocks are verbatim lab text
(`F02/Footprint.cs`, `F02/Concurrency.cs`, `F02/Effects.cs`, modulo the `namespace` line); no cross-file
reference; no banned token; no `IO<Option<`/`IO<Fin<`; no bare `Eff<X>`; 228 lines. `Console<RT>.writeLine`,
`Console<RT>.readLine`, `Eff.runtime<RT>().Map`, two `Has<Eff<Runtime>, T>` traits on one record,
`RT.Ask.Map(f).As()`, `Run(rt)`, `Seq.Zip(Seq<B>, Func<A,B,C>)`, `Fold`, `Filter`, `Exists`, `IO.pure`, and
`Range(int from, int count)` (`Prelude.Range(int from, int count, int step = 1) : Range<int>`, count not bound)
are all in LAB-NOTES or the F02 notes with run evidence. No contradiction with `22-languageext-effects.md` on
runtimes or `Has` was found.

1. Location: line 113.
   Claim: "A pure `Map` over a `Seq` is safe to run in parallel, and the effect type owns that decision:
   `Traverse` under `IO` forks each element."
   Evidence: `Traversable<Seq>.Traverse` folds with `Applicative.lift`, so it reduces to `Applicative<IO>.Apply`
   (decompile of `LanguageExt.Seq`, line 782-786). `Applicative<IO>.Apply` calls `ma.As().ApplyBack(mf.As())`,
   which builds `LanguageExt.DSL.IOApply<A,B,C>`; its `Invoke(EnvIO)` calls `Ff.RunAsync(envIO)` and
   `Fa.RunAsync(envIO)` and only then awaits. There is no `Fork` and no thread per element on that path.
   LAB-NOTES F18 records the same behaviour as overlap, not fork: "IOApply.Invoke starts both operands before
   awaiting, so the tuple Apply on IO overlaps." The F02 probe traverses with `IO.pure`, which completes
   synchronously, so the lab witnesses no parallelism at all. "forks" also collides with
   `22-languageext-effects.md`, where `Fork` is the named member that "starts the effect on one
   `TaskCreationOptions.LongRunning` thread".
   Correction: replace the sentence with
   "A pure `Map` over a `Seq` is safe to run in parallel, and the effect type owns that decision: `Traverse`
   under `IO` starts the element effects before it awaits them, so they overlap."

2. Location: line 210, third sentence.
   Claim: "When retrieving the value early is wasteful, or a later check needs it only after earlier checks
   pass, inject a `Func<Seq<string>>` instead."
   Evidence: BRIEF, "The file shows one path per concern" and "Remove hedges and alternatives ... do not add new
   ones." This sentence offers a second dependency shape for the concern the section already answers with
   `IO<Seq<string>>`, and `Func<Seq<string>>` appears in no block of the file or the lab. The F02 notes confirm
   the delegate form was deliberately left out: "A `Func<Seq<string>>` validator: named in prose as the
   on-demand position; no block."
   Correction: see item 3, which replaces the whole paragraph.

3. Location: line 210, fourth sentence.
   Claim: "The validator remains impure to exactly the extent that the injected function is impure, but the
   effect is explicit, replaceable, and acquired only when needed."
   Evidence: this is Buonanno prose (chapter 2, line 198) written for a validator that holds
   `Func<IEnumerable<string>>`. In the integrated file `BicExistsValidator(Seq<string> validCodes)` receives a
   loaded `Seq<string>` and is pure; nothing impure is injected into it, and line 196 already says so ("so the
   validator is pure"). The sentence is now false, and it also restates the drop-through the file no longer has.
   Separately, the book's reason for the section — the value is acquired only when needed — is dropped from
   line 196 and survives only inside the alternative flagged in item 2, so the section loses the claim its
   heading names.
   Correction: replace the whole of line 210 with
   "Production composition supplies the `IO<Seq<string>>` that queries the codes. A test supplies `IO.pure`. The
   `IO<Seq<string>>` defers the query until `BicExists` binds it, so the codes are read only when the check runs.
   The validator stays pure and the effect is explicit and replaceable. The host runs `BicExists` with
   `RunSafe()` and matches the `Fin<bool>`."

8. Location: line 117.
   Claim: "Purity makes parallelization semantically safe, but the runtime cannot infer that an arbitrary

   pure."
