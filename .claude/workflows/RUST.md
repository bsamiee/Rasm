# [RUST_PRINCIPLES]

Rules a crate-by-crate build of `libs/rust` follows.

1. Each crate builds on whole layers beneath, and a category's crates stack by dependency with no type of an upper crate below it: no rmcp type below MCP (`allowed_hosts` feeds rmcp's host check and stays an MCP option), no axum type below the daemon
2. Composition choices (the route, the filter directives, the resource attributes) are field defaults on one record a caller overrides by field, parsed rows (`listen`) stay clap rows of the layer's `Options`, and a typed layer enters as a parameter
3. Catalog types stand wherever they state the value: `nalgebra::Point3<f64>` and `Isometry3<f64>`, `parry3d_f64::shape::{TriMesh, HeightField}`, `kurbo::BezPath`, `geo_types::Geometry<f64>`, `arrow_array::RecordBatch`, `ndarray::Array2<f64>`, `petgraph` graphs, `jiff::Zoned`, `uom::si::f64::Length`, rmcp's params and results, and a crate record holds a composition the catalog lacks, built from those types. A row sits at the newest release unless the catalog crates exchanging its type link an older one (arrow, parquet and object_store at datafusion's and deltalake's, with serde_arrow on the matching `arrow-*` feature and zarrs_object_store at that object_store; usvg and fontdb at krilla-svg's and typst's; dugong and manatee at merman-render's), and a row no Rasm crate exchanges takes its newest release. Where no release unifies, the value crosses as bytes or slices (font bytes for skrifa across parley, usvg, krilla and hayro; f64 triples across colorimetry's older nalgebra), and each duplicate that leaves sits in `clippy.toml` `allowed-duplicate-crates` with its linkage reason
4. Geometry runs in `f64`: nalgebra values at every crate signature, parry's glamx values inside parry calls, crossing through nalgebra `convert-glam033` for vectors and points and glamx `nalgebra` for poses. An `f32` kernel (fidget's JIT, meshopt's error metric, stl_io, parley layout, sobol_burley, colorgrad) widens on emit and takes its accuracy as a caller parameter. Paper space is `f64` millimeters on kurbo, a CRS transform runs through `proj::Transform` on geo_types values, and a grid samples through ndarray-interp
5. Hosts reach a crate through a process the services crates serve (an MCP endpoint over `rasm-mcp`, a daemon over `rasm-daemon`) or a stdio binary inside the host package. The catalog holds no in-process binding row. App content (presets, looks, captions, host paths, vendor keys, a render queue and its output naming) sits in the app that composes the crate
6. Protocol facts come from rmcp: `ProtocolVersion::KNOWN_VERSIONS` sliced from one declared floor into the `Cow<'static, [ProtocolVersion]>` the handler returns, `LATEST_WITH_INITIALIZE` for the legacy lifecycle, `has_initialize` for a version branch, `ErrorCode` and `ErrorData::invalid_params` for codes. The floor and the notifier's broadcast capacity are the `const`s the crate declares, and `DEFAULT_SUBSCRIPTION_CHANNEL_CAPACITY` sizes a client's `listen` buffer
7. Sessions implement the `ServerHandler` methods their endpoint answers, `get_tool` included where tools exist so `Mcp-Param-*` validation runs, and no macro rebuilds a `ClientRequest` from the parameters rmcp split. One generic instrumented call keyed by the method's `ConstString` type wraps each handler body
8. Elicitation builds its schema through `ElicitationSchema::from_type::<T>()`, asks a client with `initialize` through `Peer::create_elicitation` and a client without it through the parked `InputRequiredResult` with `request_state`, and decodes the answer through `serde_path_to_error` so a malformed answer names its path (`Peer::elicit` returns `Option<T>` and a bare `serde_json::Error`)
9. Calls a client asks to run as a task are `TaskManager` tasks (`CreateTaskResult`, `GetTask`, `UpdateTask`, `CancelTask`, `TaskContext::request_input`). The ledger of destructive calls finished after cancellation is one `watch::Sender<BTreeMap<_, _>>` edited through `send_modify` and read as a resource through `WatchStream::from_changes`. `TaskManager` lists nothing, and its tasks escape the drain
10. Progress is `ProgressNotificationParam` from the first report, held as `watch::Sender<Option<ProgressNotificationParam>>`, and a client routes progress by token through `ProgressDispatcher`
11. Providers stay typed: `SdkTracerProvider`, `SdkMeterProvider` and `SdkLoggerProvider` share no trait, and the tracer, the log bridge and the globals take each by type
12. `clap` rows exist for variables no crate reads: `OTEL_TRACES_EXPORTER`, `OTEL_METRICS_EXPORTER`, `OTEL_LOGS_EXPORTER`, `OTEL_PROPAGATORS`, and `RUST_LOG` merged over program defaults. `OTEL_SERVICE_NAME` keeps a row because `Resource::builder()` lets `OTEL_RESOURCE_ATTRIBUTES` override it and falls back to `unknown_service`. `OTEL_EXPORTER_OTLP_*`, `OTEL_BSP_*`, `OTEL_BLRP_*`, `OTEL_METRIC_EXPORT_*` and `OTEL_TRACES_SAMPLER*` reach the SDK and the exporters untouched
13. Span and metric keys come from `opentelemetry_semantic_conventions::{attribute, metric}`, and a key the crate lacks or marks deprecated is one crate `const` the span and the metric read. The instrumentation scope names the emitting crate
14. Request spans hold `otel.name`, `otel.kind`, the protocol fields and `Empty` slots recorded at the end, their parent extracted from the request meta through `global::get_text_map_propagator`, and the error path matches every `set_parent` case
15. Tool-facing errors add `Serialize` with `#[serde(tag = "_tag")]` and `#[serde(skip)]` on sources, and one function renders a crate error into `ErrorData` with the code chosen by variant and the error as `data`
16. Independent routes, schemas, files and rows accumulate through `Validated`
17. Locks scoped to one closure use `with_mut`, `get_cloned`, `set` or `replace` under `lock_value_accessors`
18. Shutdown drains on the first signal (`TaskTracker::close` then `wait`, watches cancelled, standalone streams closed) and abandons on the second
19. Unix interrupt, terminate and hangup and Windows ctrl-c streams join through `try_collect::<stream::SelectAll<_>>()` from one `cfg_select!` value
20. Watchers shared across sessions are `Weak<AbortOnDropHandle<()>>` leases in a map pruned by `strong_count`, each subscriber holding an `Arc`
21. Capabilities derive from the routers an app registered. A vendor's `_meta` vocabulary is a `Serialize` record of `Option` fields with `#[serde(rename = "<vendor>/<key>")]` in the app that sets it, written into `MetaObject` through serde, and the library holds no vendor key
22. Clients over an upstream are `serve_client_with_lifecycle_and_ct` under `ClientLifecycleMode::Auto { preferred_versions, legacy_version: Some(ProtocolVersion::LATEST_WITH_INITIALIZE) }`; notifications arrive through `Peer::listen(filter)`, `SubscriptionEnd::Lagged` re-listens on `acknowledged()` and resyncs, and an upstream without `initialize` receives `RequestMetaObject::with_client_context`. Child upstreams are `TokioChildProcess::builder(command).stderr(Stdio::piped()).spawn()` with stderr relayed line by line into `tracing` under a target
23. Version translation sits in the proxy endpoint alone: the meta scrub under one `const` prefix (`io.modelcontextprotocol/`, which rmcp keeps private), the `result_type` default on every result `strip_result_type_for_legacy_peer` strips, the capability rewrite for an upstream without `subscribe` or `logging`. A tool binary holds `Args` and `main` alone
24. Tests exist for tools alone: a dylint lint's example and UI snapshot under `tests/rust/tools/dylint/`, and a tool binary's cases under `tests/rust/tools/<tool>/`; a library crate holds no test target, `[[test]]` row or `#[cfg(test)]` module
