# [OUTPUTS]

Recorded output states what code did last time. Snapshots, characterization pins, and journeys become oracles through a second check, a label, or a reader.

## [01]-[SNAPSHOTS]

[REACH]:
- Output is the product and too large for a literal: diagnostics, formatted source, generated queries, command output, rendered interface
- Literals and inline annotations replace a snapshot wherever they state its fact

[KINDS]:

| [INDEX] | [KIND]         | [HOLDS]                                                 |
| :-----: | :------------- | :------------------------------------------------------ |
|  [01]   | Inline         | Expected text inside its test                           |
|  [02]   | File           | Golden file beside its input, regenerated by one switch |
|  [03]   | Selected lines | Ordered patterns on lines that matter, rest unmatched   |
|  [04]   | Delta          | Difference a variation makes against a base             |
|  [05]   | Visual         | Screenshot per element                                  |

[METHOD]:
- Read each new or changed snapshot against its input before accepting it

[FORMS]:

| [INDEX] | [FORM]                                                              | [SIGN_OF_FAILURE]                                           |
| :-----: | :------------------------------------------------------------------ | :---------------------------------------------------------- |
|  [01]   | Golden paired with a second oracle a person or machine supplies     | Snapshot diff as sole evidence of correctness               |
|  [02]   | Input, options, and output kept in one reviewable unit              | Snapshot naming a fixture kept elsewhere                    |
|  [03]   | Exit code and error stream recorded beside standard output          | Tool exiting 0 on an error while its test passes            |
|  [04]   | Variation snapshotted as a delta against its base                   | Near-identical goldens changing as one                      |
|  [05]   | Subject cut down to a small golden, new fixture over an edited one  | Diff too large to read, one fixture edit moving other tests |
|  [06]   | Nondeterministic values replaced by named placeholders in one place | Temporary paths, versions, or foreign line numbers          |
|  [07]   | Normalizer leaves a test's subject untouched                        | Golden unchanged when behavior breaks                       |
|  [08]   | Update switch refuses orphans, overwritten inputs, and stale lists  | Bulk accept, baselines written by a main-branch build       |
|  [09]   | Each accepted difference has a reason                               | Accept commit stating no cause                              |
|  [10]   | Visual difference removed at its origin (font, animation, pointer)  | Threshold raised in an unrelated change                     |

Row 01 second oracles are an annotation at the line under test, idempotence, semantic equivalence, and agreement across implementations.

## [02]-[CHARACTERIZATION]

[REACH]:
- Code with no tests and no source of truth must change
- Rewrite or port has its old implementation available
- External conformance corpus is partly failing

[KINDS]:

| [INDEX] | [KIND]                | [ORACLE]                                              |
| :-----: | :-------------------- | :---------------------------------------------------- |
|  [01]   | Golden master         | Current output through widest stable interface        |
|  [02]   | Classified difference | Old implementation, each difference accepted or filed |
|  [03]   | Expected-failure list | Corpus verdicts, known failures listed                |

[METHOD]:
1. Record current behavior through its widest stable interface before any change
2. Apply a break under each pin and see red
3. Replace pins with specification tests as each behavior is decided

[FORMS]:

| [INDEX] | [FORM]                                                             | [SIGN_OF_FAILURE]                                       |
| :-----: | :----------------------------------------------------------------- | :------------------------------------------------------ |
|  [01]   | Golden stays byte-identical through a refactor                     | Golden updated or approved during a refactor            |
|  [02]   | Feature's difference limited to intended lines                     | Difference across unrelated lines                       |
|  [03]   | Each difference from old code accepted with a reason or filed      | Unclassified difference that passes                     |
|  [04]   | Expected failure that passes fails its run, each skip has a reason | Skip pointing at a closed issue, skip that runs no test |

## [03]-[JOURNEYS]

[REACH]:
- Behavior exists only in an integrated system: real binary, protocol, browser, device, or remote service
- Variants differing in pure logic go to a lower scope
- Command-line tools take hermetic scripts of a real binary as a main style

[KINDS]:

| [INDEX] | [KIND]          | [CONTROLS]                                                       |
| :-----: | :-------------- | :--------------------------------------------------------------- |
|  [01]   | Hermetic script | Fresh work directory, empty home, local registry, pinned version |
|  [02]   | Browser, device | Seeded data per test, cleared state, fixed clock and zone        |
|  [03]   | Live service    | Dedicated account, unique names, request budget                  |
|  [04]   | Smoke           | Representative journeys before release                           |

[METHOD]:
- Reproduce a flake's cause before fixing it, then repeat that test in parallel

[FORMS]:

| [INDEX] | [FORM]                                                                   | [SIGN_OF_FAILURE]                                         |
| :-----: | :----------------------------------------------------------------------- | :-------------------------------------------------------- |
|  [01]   | Wait names an application state, registered before its trigger           | Sleep before a read, pause raised by trial                |
|  [02]   | Application with no readiness signal gets one                            | Readiness inferred from unrelated elements                |
|  [03]   | Assertion retries until a deadline where no idle signal exists           | Single read of a count or value after an action           |
|  [04]   | Polling helper has a deadline, injected sleep, and diagnostics           | Timeout with no context                                   |
|  [05]   | Retry wraps one idempotent action until its postcondition holds          | Global retry, retry around a side effect                  |
|  [06]   | Absence proven by a positive settled signal, then a count                | Fixed pause before counting                               |
|  [07]   | Names derived from their test, identifiers captured                      | First or latest result selected, test passing only alone  |
|  [08]   | Cleanup in fixture teardown, idempotent, before each retry               | Cleanup left to each test, retry failing on leftovers     |
|  [09]   | Locator is an owned identifier or role and label, inside a container     | Position or style selector, locator matching a second row |
|  [10]   | Journey and assertions in a test body, seeding and selectors in fixtures | Body of one helper call, assertion in a page object       |
|  [11]   | Steps named, traces and screenshots kept on failure                      | Local rerun needed to find a failed step                  |
|  [12]   | Skipped journey has an owner and an end date                             | Skip with neither                                         |
|  [13]   | Run fails when a suite registers no test                                 | Zero tests registered and a green run                     |
