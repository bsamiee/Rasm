# [RUST_PRINCIPLES]

Rules a crate-by-crate build of `libs/rust` follows, each stated once as a rule about the code. Rules `/Users/bardiasamiee/Developer/Rasm/CLAUDE.md` states (direct calls, one error type per failure contract with reasons as data, paired acquisition and release, derived labels, one declaration per fact, layers beneath only, no alias, no fallback hiding a cause, behavior from the count and kind of supplied parts, section dividers) and forms `[workspace.lints]`, `clippy.toml`, `tools/dylint` and `tools/ast-grep/rules/rust` force (thiserror enums with `#[source]` fields, `serde_path_to_error`, `nonpoison` locks, `TaskTracker`, `CancellationToken`, `AbortOnDropHandle`, `ArcSwap`, `DropGuard`, strum and enum-map derives, `let .. else`, let chains, `try` blocks, `try_collect`, trait aliases, `cfg_select!`, no `mod.rs`, no `pub use`, no `std::env`) are not repeated; these add the shapes that satisfy them on `nightly-2026-10-15` with the catalog rows at their newest release. Snippets are the target form. The existing crates set the quality floor (items 9 to 31 are their idioms), never the architecture: every crate, rebuilt or new, takes the shape these rules state. Where a sheet under `docs/research/coding/rust/` differs from this file or a lint row (`mod.rs`, a flat crate directory), this file and the lint row win.
