# [CREATIVE_CLOUD]

One Rasm application, `apps/creative-cloud`, with one stdio MCP server, `creative-cloud`, that drives InDesign, Illustrator, Photoshop, Acrobat, and Lightroom Classic for agents and replaces the paid and purchased products on this machine; then, through that application, the power-user configuration of each app, a master InDesign template, and its size catalogue. The Kelman and Typefool documents on Drive are the template's reference; nothing on Drive is reorganized, converted, downloaded, or deleted, and every font the template names is already installed. Execution starts at unit 1 of [08]. The design files of [02] hold the host facts, DOM names, and values the code uses; a builder reads them and the current Adobe documentation for its unit and writes code from them.

## [03]-[DECISIONS]

1. One server, `creative-cloud`, host-prefixed tools, one `.mcp.json` row, one allow row `mcp__creative-cloud__*`; the official `illustrator` row stays separate. Every capability is a tool; no panel control, dialog, menu item, shortcut, scripts-folder copy, `.psjs`, or `.idjs` is a unit of work.
2. The in-host plugins are transport only; tool logic sits on the Node side. The MCP boundary is `@effect/ai` over Effect `Schema`; no file imports `@modelcontextprotocol/sdk`.
3. One digital canvas, `Digital 3840x2160`, 16:9, on the 45 px module, shared by InDesign, Illustrator, and Photoshop; InDesign's named Web and Mobile screen formats are in scope, so the catalogue is 59 rows (21 document, 15 technical, 23 screen), `gui-indesign.md` [07].
4. The InDesign master template and every catalogue file are built by `indesign_build_template` and `indesign_build_size_catalog` from data files beside the code; each size is rebuilt through the `apply_grid` body and `page.adjustLayout` is never used; the catalogue is one book with the master as style source.
5. InDesign runs the Middle Eastern feature set; the ME preference pane and panels stand in place of scripting workarounds; `app.textDefaults` stays Latin and the Persian and Arabic value sets live in `rtl-defaults.json`.
6. `indesign_find_change` covers text and GREP modes and loads the five saved house queries by name; the earlier text-only contract was a mistake.
7. Fonts: every family the template names is installed (Drive premium folder for Latin, the Forge home-manager folder for Persian and Arabic, Adobe Fonts through Creative Cloud); no lane sources, installs, tags, or tournaments fonts; the Latin, Persian, and Arabic families are five keys of `families.json` the user sets once.
8. The unified swatch set exists: `99.Default Profiles/Shared/Default Palette.ase` on Drive, 92 values in two groups, already loaded in Illustrator; the template's colour block reads it as it stands, and no ramp, prefixed group, or adjudication is built.
9. Partial work is the baseline: Illustrator's saved layout is the strongest and is completed, not rebuilt; every app pass reads the live state first and lands the gap.
10. Lightroom Classic stays as the last host; Lua joins the repo in one change (toolchain, tag, targets, checker `selene`, writer `stylua`, `lua-language-server` typecheck, outline, rules, README) with the Lightroom SDK 14.3 `---@meta` definitions.
11. Acrobat: Action Wizard actions as data the server renders to `.sequ`, batch over folders, Combine presets from data, full forms behaviour, tagging and the accessibility checker through `execMenuItem`, five trusted functions in `rasm-trusted.js`; no Optimizer presets; alt text and structure edits outside Acrobat are out of scope.
12. Installed add-ons are integrated, never closed: Illustrator Mockup, Retype, Mapping, Masking; Photoshop Remove Tool and its advanced component. The AI-and-promo removal rule covers assistant, promo, help, and share surfaces alone.
13. One house keyboard-shortcut scheme, QWERTY by shape, the same letters in every app where the tool exists, owned by `gui-illustrator.md` [02.4].
14. Every app pass ends with its layout, toolbar, workspace, shortcut set, menu set, default template, and presets saved under `99.Default Profiles/<App>/` on Drive with hashes; that folder is the one Drive write this plan makes.
15. The InDesign Scripts panel stays open in the automations slot for the user's own scripts; Illustrator and Photoshop hold their Actions panels there; the plan installs nothing into them.
16. Nothing is written to a temporary place: inputs through the tools' own channels, outputs under `.artifacts/creative-cloud/`, data files beside the code that reads them. Nothing waits for the user's consent. No agent runs git; the user commits.
17. Toolchain rows land in unit 1 at their newest published versions, pinned in the catalog alone: `effect`, `@effect/ai`, `@effect/platform`, `@effect/platform-node`, `@effect/cli`, `vite`, `vite-uxp-plugin`, `bolt-uxp-utils`, `@adobe/cc-ext-uxp-types`, `@types/photoshop`, `fontkit`, `@types/fontkit`; `zod` only where `@effect/ai` declares it a peer. UPIA, the UXP Developer Tool, Bolt's template repository, and `.ccx` packaging are used by no target.
18. Illustrator scripts are hand-written ExtendScript `.jsx` files (ES3, the host's only public engine): no TypeScript compile chain, no esbuild, no swc, no shim package; an ast-grep family refuses the post-ES3 forms. The Node driver runs them through osascript.
19. UXP plugins install by the one route this machine proves for nine TK9 plugins and Sidekick: `deploy` copies the built folder into `~/Library/Application Support/Adobe/UXP/Plugins/External/<id>_<version>/` and rewrites the row in `PluginsInfo/v1/{PS,ID}.json`. No `.ccx`, no `package` target, no Creative Cloud desktop attempt.

## [06]-[INDESIGN_TEMPLATE_AND_CATALOGUE]

The grid rule, derived from the Kelman report, brochure, presentation, and colour-grid files and the School template on Drive (`gui-indesign.md` [07], the extraction paragraph and rows 03–24):

- Body size is 0.85 L on every deck and document; L per family: 7.5 for A6; 8.5 for A5 and Half Letter; 11.5 for A1, A2, B1, B2; 12 for A3, Tabloid, B3, boards, and technical sheets; 15 for Letter, Legal, A4, B4; 36 for A0 and B0; 45 px for the digital canvas.
- The type area's top sits at the f-height of the first line: top margin = first baseline − f, where f is read from the body font through `indesign_get_font_metrics` (`fTop`), never a constant.
- Twelve columns, gutter 1 L, sides 3 L, first baseline 3 L, rows in whole lines, row gutter 1 L on documents and 2 L on presentations, the lines per row the largest whole number that leaves bottom ≥ 4 L, folio at the last baseline + 3 L on print sheets and the footer line at last baseline + 4 L on the digital canvas.
- First baseline offset Cap Height on every text frame; baseline grid relative to the top of margin, view threshold 25 percent, shown; the document grid one module square, hidden, snap off; an f-height guide layer with one guide per baseline placed by `guides.add`.
- Image and caption grid: the image bottom sits on a baseline and the caption frame occupies the next line, anchored `ABOVE_LINE` in the document form and free-standing on the deck parents.
- The eight deck parents map to the Kelman 1280×720 deck pages and are refitted at 45 px on the digital canvas.

The formulas are `grid-calculator/README.md` "What we build ourselves", each tagged confirmed or derived; `@rasm/typographic-grid` implements them as pure functions with the `grid` target reproducing every catalogue row within 0.001 pt before any template is saved. The catalogue is the 59 rows of `gui-indesign.md` [07], carried in `page-sizes.json` seeded from `grid-calculator/data/page-sizes.csv`.

The style system is `gui-indesign.md` [06]: 40 paragraph styles chained from one `Base` with role names, 13 character styles of one attribute each, 9 object styles, 1 table and 4 cell styles, 8 GREP styles with their expressions, the indicator variable, one TOC style, 3 conditions, the traps table; the 5 saved GREP queries, `Default Preflight`, and the `Default Print` and `Default Digital` PDF presets are [07]. All of it is `styles-graph.json` beside `@rasm/indesign`. Kelman's flat styles and size-in-name convention are rejected; his geometry alone is adopted.

The Persian and Arabic value sets are `indesign-uxp.md` [07] and its closing paragraph: the World-Ready composer resolved at run time, `RIGHT_TO_LEFT_DIRECTION`, `FARSI_DIGITS` for Persian and `HINDI_DIGITS` for Arabic, kashidas off for Persian and medium on Arabic body, `OPENTYPE_POSITION_FROM_BASELINE`, no hyphenation; document level `pageBinding RIGHT_TO_LEFT` and every story `RIGHT_TO_LEFT_DIRECTION`. These are `rtl-defaults.json`.

Before `styles-graph.json` is written, the Kelman and Typefool IDML and INDD files on Drive are opened read-only through `indesign_execute` and `indesign_get_layout` (Typefool sits under `98.Templates/01.Presentation Templates/Branding Related Presentations` and `02.Documentation Templates/01.Business Related Templates`) and their page patterns (cover, contents, section, image-led, comparison, stylesheet, stylescape) land with measured geometry in `page-patterns.json`; the deck parents and the Typefool 15-field three-column grid derive from it.

Data files beside `@rasm/indesign`: `styles-graph.json`, `page-sizes.json`, `page-patterns.json`, `rtl-defaults.json`, `grid-presets.json`, `families.json`. Every value lives in one of them and none in code.

## [09]-[CODE_BAR]

`CLAUDE.md` governs: `[TOTALITY]`, `[FLOW]`, `[INDEPENDENCE]`, `[PURITY]`, `[BOUNDARY]`, `[DIRECTNESS]`, `[DEPENDENCY_POLICY]`. The model in the tree is `.claude/plugins/function-hooks/` and the TypeScript rebuild commit `341884d02`; the ten lines of `architecture.md` [01] map each to a hook file. Effect is the one result type in TypeScript: `Data.TaggedError` variants with `reason` fields, `Option` for absence, `Schema` at the boundary once; module banners `[IMPORTS]`, `[TYPES]`, `[CONSTANTS]`, `[OPERATIONS]`, `[EXPORTS]`, `_`-prefixed private bindings, exports at the end; data as `as const satisfies` tables or JSON beside the code; no module-level mutable state; a wrapper only where it adds a fact the API lacks. Every rule under `tools/ast-grep/rules/typescript/{syntax,effect}/` applies; the ExtendScript family over `scripts/*.jsx` (no class, no `for…of`, no object rest, no `JSON` without the host's own) and the Lua family land at their second recorded defect. In the UXP plugins Effect is bundled: ticks are `Schedule`, frames decode through `Schema`, the body runs behind `Effect.tryPromise`. Lua: `Result`-shaped tagged tables the consumer matches, a function table indexed by the frame `kind`, the SDK's `LrTasks`, `LrPathUtils`, `LrStringUtils` where a hand-written helper would go. Every host name, build, port, and path comes from the host table; every size, style, swatch, preset, and menu string from a data file.
