Strongest findings, ten lines:

1. Panel geometry is constants in one enum with `#available(macOS 26)` branches, never measured: width 310 on macOS 26 / 300 before, content inset 14, highlight inset 6/4, panel padding 6, row content height 18 text / 26 icon (MacControlCenterUI `Menu Internal/Menu Constants.swift`, `Types/MenuWidth.swift`, `Types/MenuItemSize.swift`); Maccy's equivalents are `Popup.itemHeight` 24/22 and `Popup.cornerRadius` 7/4.
2. Height is capped from `NSScreen.screens.first?.visibleFrame.height - 30` feeding a scroll view framed at `min(maxHeight, contentHeight)` that disables its own scrolling when content fits; Maccy computes the same in the store (`suitableHeight`/`preferredHeight`, floor of three rows) and calls `panel.verticallyResize(to:)`.
3. Nobody uses `NSViewRepresentable` for layout: measurement is `onGeometryChange(for:)` behind one modifier (Maccy `Views/HeightReaderModifier.swift`) or one `.onFrameChange` (Ice `UI/IceBar/IceBar.swift`), and MacControlCenterUI applies `.geometryGroup()` instead of measuring at all.
4. Rows set no font and inherit the panel default — across Maccy's 122 files only two `.font(.system(size:))` calls exist, both monospaced debug text; the one justified fixed size is 13pt bold/semibold for headers, pinned to the NSMenu font. Ice and boring.notch are the counterexamples (36/72/18/14pt literals).
5. Hover is one `HighlightingMenuItem` wrapper using `.onHover`, `selectedContentBackgroundColor`, a `continuous` 10pt radius on macOS 26 / 5pt before, and an `isEnabled` force-clear; press reproduces the NSMenu blink (80 ms off, 80 ms on, 100 ms before dismissal), not a scale. Rows need a near-transparent background or macOS 26 breaks hover (Maccy's own comment).
6. Animation is keyed to values, never imperative: `.animation(.default.speed(3), value: history.items)`, `.animation(.easeInOut(duration: 0.2), value: searchVisible)`, and one named panel-resize curve `.smooth(duration: 0.2, extraBounce: 0.25)` attached at the binding; content that can vanish lives inside a permanent container so the parent's child count never changes.
7. A stacked usage bar is a Swift Charts `Chart`/`BarMark` at height 20, `cornerRadius 2`, axis and legend hidden, colors via `chartForegroundStyleScale`, with per-mark `accessibilityLabel`/`accessibilityValue(…formatted(.byteCount(style:.file)))` (Cork `Cached Downloads Folder Info Box.swift`); a level bar is 22pt capsule with a 0.25pt stroke, deliberately unanimated because Apple does not animate its own. Determinate progress puts the label inside `ProgressView(value:total:) { Text }`, and the extension point for a custom shape is a `GaugeStyle`, not an ad-hoc `ZStack`.
8. macOS settings is a `TabView` of `Tab(_:systemImage:)` with `.tabViewStyle(.tabBarOnly)` at a fixed `.frame(width: 400, height: 350)`, each tab a `Form { Section }.formStyle(.grouped)` of `LabeledContent { control } label: { Label }`, sub-screens as sheets with a `.confirmationAction` Done (PDF-Archiver). Add/remove for a list is a `ControlGroup` of `plus`/`minus` icon buttons under the list at `.frame(width: 50)` plus `.onDeleteCommand` (Maccy), and the empty state is a 30–40pt `.tertiary` symbol with a `.headline`/`.secondary` label rather than the full-size `ContentUnavailableView` (Cork).
9. Concurrency: one `@MainActor final class` root store owning lazily built managers each handed the store (Ice) instead of `AppState.shared` reached from models (Maccy's defect); one stored `Task` per subscription driven by `for await` over `Defaults.updates` or `DistributedNotificationCenter.notifications(named:)`, cancelled in `deinit` (Loop); a multi-consumer `AsyncStream` keyed by UUID with `onTermination` unregistering (Loop `AccessibilityManager`); actors for updaters and remote entities; typed throws per failure domain and `withTaskGroup(of: Result<T, E>.self)` so independent failures accumulate instead of cancelling (Cork, the only project at `SWIFT_STRICT_CONCURRENCY=complete` and Swift 6.0). Cork's child-process `AsyncStream` omits `onTermination`, so cancellation leaks the process — the one gap to close in Relay's version.
10. Keychain: the prompt is caused by the login keychain's per-signature ACL, so every query sets `kSecUseDataProtectionKeychain: true` and pins `kSecAttrAccessGroup` read from the app's own `keychain-access-groups` entitlement via `SecTaskCreateFromSelf`/`SecTaskCopyValueForEntitlement`, matched by suffix and cached; `errSecMissingEntitlement` means unsigned build, any other hard status is an error and must not fall through to the login keychain; writes are update-or-insert and clearing is an explicit delete (iTerm2 `iTermUpgradeSafeKeychain.swift`, DuckDuckGo `KeychainType.swift`, `BWKeyStorage.swift`). Status item art measures 16×16 @1x / 32×32 @2x with `template-rendering-intent: template`, fitted at runtime into a 25×17pt box, code-drawn glyphs at `lineWidth: 2` in a 12×12 or 9×9 box; all four apps use `LaunchAtLogin.Toggle()` rather than calling `SMAppService` from a view, and Loop's hand-rolled version checks `SMAppService.mainApp.status == .enabled` before `register()` / `await unregister()`.
