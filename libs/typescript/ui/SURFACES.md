## [01]-[INTENT]

These laws foreclose coupling, narrowing, and re-derivation — every landing answers them before it lands:

- One engine per surface: each category holds exactly one owner; a second engine for the same surface class is the duplication defect.
- Variation is rows: apps differ by rows, cases, columns, and policy values on the owner — never by sibling components, boolean knobs, or per-app forks.
- `system/` stays app-blind: its owners assume no product, no sibling set, no deployment shape; anything product-shaped seats in `view/` or `viewer/`.
- State projects through the one atom bridge; a component never runs an effect or mirrors domain state.
- Appearance is token data: color, dimension, type, elevation, and motion resolve through the `token` authority as decode-gated values — a component carries zero literal appearance.
- Packages are the standard library: every category researches the ecosystem before a line is designed; hand-rolling what a maintained package carries is a defect, and thin wrappers that rename without adding domain value are the inverse defect.
- Admission ladder binds: a new instance is a row; a new owner inside a settled sub-domain is a design page; new nouns are a sub-domain; each rung earned by evidence the rung below cannot carry.
- Full-domain owners: each category models its whole concept at landing — a thin slice that covers the first consumer is COVERAGE naivety and gets rebuilt.
- Every admission lands its whole touch-point set: manifest row, README registry card, `.api/` catalogue, owning page — both directions, same pass.
