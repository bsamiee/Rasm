## Corrections and findings

- `IOApply<A, B, C>.Invoke` (decompile of `LanguageExt.DSL.IOApply`3`) calls `Ff.RunAsync(envIO)` and `Fa.RunAsync(envIO)` before it awaits either, so the two operands of the tuple `Apply` overlap. The book's overlap claim for `Apply` stays true under `IO`.
- The tuple extension `Apply` resolves on a `(IO<A>, IO<B>)` receiver without a cast, the same as on `Validation`.
- `Seq<A>` has no chunking member. `Enumerable.Chunk` on the `Seq` yields `IEnumerable<A[]>`; `toSeq(...).Map(toSeq)` makes `Seq<Seq<A>>`.
- `Seq<IO<A>>` does not convert to `Seq<K<IO, A>>` (no variance). `Map<K<IO, A>>(...)` with the explicit type argument produces the receiver `PartitionFallible` needs.
- Analyzer: `Option<bool> == Some(true)` fails MA0003 (unnamed `bool` argument); the checks use `Exists(...)`. `Task.GetAwaiter().GetResult()` fails VSTHRD002; wrap the task in `IO.liftAsync` and run it.
- `async () => { await task.ConfigureAwait(false); return unit; }` passed to `IO.liftAsync` compiles with zero diagnostics.

## What a project built on this file still needs

- A runtime record with `Has<Eff<RT>, T>` for each capability the workflow reads; the `Runtime` here is empty and exists only to show `RunAsync(rt)`.
- One closed code block per package that raises errors, and the host mapping from `Expected` codes to exit codes or HTTP statuses.
- A cancellation source at the host: `env.Token` is observed inside `IO.liftAsync`, and the host supplies it through `RunAsync(CancellationToken)` or an `EnvIO`.
- A concurrency bound chosen per fan-out: chunk width here, or a `Conduit` with `Buffer.Bounded(n)` when the producer is a stream.
