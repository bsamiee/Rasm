## [02]-[TOOLBAR]

Facts: Adobe, "Change toolbox layout in InDesign" (2026-06-02): "the positions of tools within the toolbox remain fixed and cannot be rearranged"; layout choice is `Preferences > Interface > Floating Tools Panel` = Single Column, Double Column, Single Row, or the double arrow at the top of the toolbox. Adobe, "Use the tools in the InDesign Toolbox" (2024-09-08): hidden tools sit under the visible tool's flyout; `Window > Tools` shows the panel; `Window > Utilities > Tool Hints` is a separate panel. The live `UITools` enumeration of 21.6.0.58 holds 35 tools; the toolbox adds three UI-only tools (Content Collector, Content Placer, Color Theme) and the footer controls. No customization dialog exists (no menu action containing `Toolbar` in the 4,843 read live).

Decision: `app.generalPreferences.toolsPanel = ToolsPanelOptions.DOUBLE_COLUMN` (current `SINGLE_COLUMN`; members read live `SINGLE_COLUMN=1163092844`, `DOUBLE_COLUMN=1162109804`, `SINGLE_ROW=1163096695`); readback `String(app.generalPreferences.toolsPanel) === "DOUBLE_COLUMN"`, the saved workspace's `<toolbar id="2" size-variant=…>` (today `vertical-narrow`; Illustrator's OWL writes `vertical-wide` for two columns, the InDesign value is recorded at [09] row 06), and a window-id screenshot with two icon columns. Rules the graph obeys: every measurement is written in `L`, the family module of the file being built ([07] size tables), and `build_template` and `build_size_catalog` resolve it to a unit string per file (`"1L"` → `"15pt"` on Letter, `"45px"` on the digital canvas); sizes are steps of the one ladder in [07] row 19 (size = 0.85 × leading), written as the step (`ladder=1 L` means leading 1 L, size 0.85 L); every text style `alignToBaseline true`, a leading that is not a whole module carries `gridAlignFirstLineOnly true` (first line snaps, block runs on its own leading), whole-module leadings snap every line; space before and after only in whole modules; indents, insets, offsets, and tab positions in L; the measure (type-area width) is `M`, resolved per file from the [07] geometry; stroke weights `rule = L/30` (0.5 pt at L = 15) and `hairline = L/60` (0.25 pt at L = 15), floored at 0.25 pt, the preflight `min_width`; the graph's value grammar is `"<n>L"`, `"M"`, `"rule"`, `"hairline"`, `ladder=<step> L`, and plain unit strings for the values no module governs (`"3pt"` form-field insets, `"0.001pt"` tolerances), and `styles-graph.json` carries the grammar in its `units` key so a consumer needs no second table; one root `Base` on `[No Paragraph Style]`, depth ≤ 3 tiers, nothing based on `[Basic Paragraph]`; character styles single-attribute on `[None]`; font families are `families.json` keys (`latin.sans`, `latin.serif`, `latin.mono`, `persian`, `arabic`), never literal names, the Persian and Arabic bindings stated after the paragraph table; Latin styles keep `Adobe Paragraph Composer`, Persian and Arabic styles take `Adobe World-Ready Paragraph Composer` (key string `$ID/HL Composer Optyca`, resolved by `find_key_strings`); ratios as data: H1 = 2 L, H2 = 1.5 L, Heading (the third level) = 1 L, Title = 3 L, Display = 4 L.
