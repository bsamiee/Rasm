# [RUST_PRINCIPLES]

Rules a crate-by-crate build of `libs/rust` follows, each stated once as a rule about the code. Snippets are the target form; a cited line names the current code the form replaces.

1. Each crate holds what it does and builds on whole layers beneath, and a category's crates stack by dependency: telemetry owns the process entry (options, the JSON layer over a caller's writer, reload filter, OTLP providers, resource, propagators, panic flush, exit code per error); the command composes `run` on telemetry and owns parsing, completions, man pages, config layers, the terminal decision, the runtime and the shutdown signal stream; the daemon composes `run` on the command and owns bind and address, `axum::serve` with graceful shutdown and the two-stage drain over a caller's drain and lifetime futures; MCP composes on the daemon and owns sessions, routers, notifications, progress, resource watches, elicitation, tasks, client and proxy. No type of an upper crate sits below it: no rmcp type below MCP (`allowed_hosts` feeds rmcp's host check and stays an MCP option), no axum type below the daemon, no codec below the frame, no site below the sun.
   `pub fn run<P, S, E>(served: Served, build: impl AsyncFnOnce(P, S, SocketAddr, CancellationToken) -> Result<(Router, impl Future<Output = ()>, impl Future<Output = Result<(), E>>), E>) -> ExitCode where P: Parser, S: Args + FromArgMatches + DeserializeOwned, E: Error, for<'error> sysexits::ExitCode: From<&'error E>`
2. A composition's choices are defaults one value overrides: a record with field defaults carries the route, the filter directives and the resource attributes, parsed rows (`listen`) stay clap rows of the layer's `Options`, and a caller states the fields it changes; a typed layer enters as a parameter, never a defaulted field.
   `#![feature(default_field_values)]` `pub struct Served { pub route: &'static str = "/", pub cli: Cli = Cli { directives: "info", defaults: "", attributes: Vec::new() } }`, written by a caller as `Served { cli: Cli { directives: "info,rmcp=warn", .. }, .. }` (the caller crate takes the gate too)
3. A catalog type stands wherever it states the value: `nalgebra::Point3<f64>` and `Isometry3<f64>`, `parry3d_f64::shape::TriMesh`, `geo_types::Geometry<f64>`, `arrow_array::RecordBatch`, `image::ImageBuffer`, `jiff::Zoned`, `uom::si::f64::Length`, rmcp's params and results; a crate record exists for a composition the catalog lacks, is built from those types, and is validated at construction through `nutype`, `bounded_integer` or private fields with one constructor returning the crate's error. A row sits at the release the catalog crates exchanging its type link (arrow, parquet and object_store at datafusion's and deltalake's releases, substrait at datafusion-substrait's), and where no release unifies (skrifa across parley, usvg and krilla; moxcms across image and jxl-oxide; nalgebra under colorimetry) the value crosses as bytes.
4. Geometry runs in `f64` on nalgebra and parry types and pixels in `f32` planes; a quantity enters and leaves through `uom` and the kernel runs on bare floats; independent rows run under `rayon` `par_iter` and collect once; randomness is a seeded `rand` generator a caller passes in; a tolerance is an `approx` value a caller states; time is `jiff` and a civil date in a zone is `jiff::Zoned`.
5. A host reaches a crate through a process the services crates serve (an MCP endpoint over `rasm-mcp`, a daemon over `rasm-daemon`) or a binary over stdio shipped inside the host package, since the catalog holds no in-process binding row; app content (presets, looks, captions, host paths, vendor keys, a render queue and its output naming) sits in the app that composes the crate.
6. A protocol fact is read from rmcp: `ProtocolVersion::KNOWN_VERSIONS` sliced from one declared floor into the `Cow<'static, [ProtocolVersion]>` the handler returns, `LATEST_WITH_INITIALIZE` for the legacy lifecycle, `has_initialize` for a version branch, `ErrorCode` and `ErrorData::invalid_params` for codes; the floor and the notifier's broadcast capacity are the two `const`s the crate declares (`DEFAULT_SUBSCRIPTION_CHANNEL_CAPACITY` sizes a client's `listen` buffer).
7. `ServerHandler` defaults stand: a session implements the methods its endpoint answers, `get_tool` where tools exist so `Mcp-Param-*` validation runs, and no macro rebuilds a `ClientRequest` from the parameters rmcp split. One generic instrumented call wraps each handler body, keyed by the method's `ConstString` type.
    `async fn served<M, T>(&self, context: &RequestContext<RoleServer>, call: impl Future<Output = Result<T, ErrorData>>) -> Result<T, ErrorData> where M: ConstString`
8. Elicitation builds its schema through `ElicitationSchema::from_type::<T>()`, asks a client with `initialize` through `Peer::create_elicitation` and a client without it through the parked `InputRequiredResult` with `request_state`, and decodes the answer through `serde_path_to_error` so a malformed answer names its path (`Peer::elicit` returns `Option<T>` and a bare `serde_json::Error`).
9. A call a client asks to run as a task is a `TaskManager` task (`CreateTaskResult`, `GetTask`, `UpdateTask`, `CancelTask`, `TaskContext::request_input`); the ledger of destructive calls finished after cancellation is one `watch::Sender<BTreeMap<_, _>>` edited through `send_modify` and read as a resource through `WatchStream::from_changes`, never a `Mutex<Map>` beside a `watch<()>` tick (`TaskManager` lists nothing and its tasks escape the drain).
10. Progress is `ProgressNotificationParam` from the first report, carried as `watch::Sender<Option<ProgressNotificationParam>>`; a tuple with a zero seed filtered out later is a sentinel. A client routes progress by token through `ProgressDispatcher`, never by filtering every notification.
11. Providers stay typed (`SdkTracerProvider`, `SdkMeterProvider`, `SdkLoggerProvider` share no trait and the tracer, the log bridge and the globals take each by type); per-signal outcomes are `(Signal, OTelSdkResult)` rows collected once into `Validated`, and each exporter is one clap row per `OTEL_<SIGNAL>_EXPORTER` variable.
12. A `clap` row exists for a variable no crate reads: `OTEL_TRACES_EXPORTER`, `OTEL_METRICS_EXPORTER`, `OTEL_LOGS_EXPORTER`, `OTEL_PROPAGATORS`, and `RUST_LOG` merged over program defaults. `OTEL_SERVICE_NAME` keeps a row because `Resource::builder()` lets `OTEL_RESOURCE_ATTRIBUTES` override it and falls back to `unknown_service`. `OTEL_EXPORTER_OTLP_*`, `OTEL_BSP_*`, `OTEL_BLRP_*`, `OTEL_METRIC_EXPORT_*` and `OTEL_TRACES_SAMPLER*` reach the SDK and the exporters untouched.
13. Span and metric keys come from `opentelemetry_semantic_conventions::{attribute, metric}`; a key the crate lacks or marks deprecated is one crate `const` read by the span and the metric alike. The instrumentation scope names the emitting crate through `env!("CARGO_PKG_NAME")` and `env!("CARGO_PKG_VERSION")`.
14. A span per request carries `otel.name`, `otel.kind`, the protocol fields and `Empty` slots recorded at the end, its parent extracted from the request meta through `global::get_text_map_propagator`, and the error path reads `set_parent`'s every case.
    `let (Ok(()) | Err(SetParentError::LayerNotFound | SetParentError::SpanDisabled | SetParentError::AlreadyStarted)) = span.set_parent(parent);`
15. An error variant carries the operation and the source as data, the operation a unit enum under `derive_more::Display`; a file error from `fs_err`, which states its operation and path, passes through one `#[error(transparent)]` variant, and context enters once where its source lacks it; a generic endpoint error enters as `Endpoint(#[source] X)`; a tool-facing error adds `Serialize` with `#[serde(tag = "_tag")]` and `#[serde(skip)]` on sources; one function renders a crate error into `ErrorData` with the code chosen by variant and the error as `data`; a catalog crate's error enters as the `#[source]` of the variant naming the operation that called it.
    `#[error("cannot {operation}")] Io { operation: Operation, source: io::Error }`, `#[display("bind {_0}")] Bind(SocketAddr)`
16. Independent results accumulate through `Validated::mapN` or `collect::<Validated<Vec<_>, _>>()` and bind through `.ok()?`; a local `impl From<E> for NEVec<E>` lets `?` lift one dependent error into the accumulating type; a `try_fold` over independent routes, schemas, files or rows is a defect.
    `Validated::from(filter).map4(traces, metrics, logs, |filter, traces, metrics, logs| (filter, traces, metrics, logs)).ok()?`
17. A lock scoped to one closure uses `with_mut`, `get_cloned`, `set` or `replace` under `lock_value_accessors`; state that changes together sits behind one `watch::Sender<BTreeMap<_, _>>`.
    `self.parked.with_mut(|waiting| waiting.extract_if(state..=state, retried).next().ok_or(Unserved::Unparked))`
18. Shutdown has two stages: the first signal drains requests (`TaskTracker::close` then `wait`), cancels watches and closes standalone streams, the second abandons; a future polled across phases is `pin!(future::maybe_done(..))` read through `take_output()`, and a value two futures read is `.shared()`.
    `future::select(pin!(future::join(drained, http.as_mut())), signals.next()).await;`
19. Signal streams join through `try_collect::<stream::SelectAll<_>>()` from one `cfg_select!` value.
    `let signals = cfg_select! { unix => [SignalKind::interrupt(), SignalKind::terminate(), SignalKind::hangup()].map(|kind| signal(kind).map(SignalStream::new)), windows => [windows::ctrl_c().map(CtrlCStream::new)] };`
20. A broadcast lag is a value answered by a resync of the listed state, never dropped; a watcher shared across sessions is a `Weak<AbortOnDropHandle<()>>` lease in a map pruned by `strong_count`, held by each subscriber as an `Arc`.
    `Err(BroadcastStreamRecvError::Lagged(_)) => Vec::from_iter(resynced(&filter, held.borrow().keys().cloned()))`
21. Capabilities derive from the routers an app registered, never from a fixed `enable_*` list; a vendor's `_meta` vocabulary is a `Serialize` record of `Option` fields with `#[serde(rename = "<vendor>/<key>")]` in the app that sets it, written into `MetaObject` through serde, and the library holds no vendor key.
22. A client over an upstream is `serve_client_with_lifecycle_and_ct` under `ClientLifecycleMode::Auto { preferred_versions, legacy_version: Some(ProtocolVersion::LATEST_WITH_INITIALIZE) }`; notifications arrive through `Peer::listen(filter)`, `SubscriptionEnd::Lagged` re-listens on `acknowledged()` and resyncs, and an upstream without `initialize` receives `RequestMetaObject::with_client_context`. A child upstream is `TokioChildProcess::builder(command).stderr(Stdio::piped()).spawn()` with its stderr relayed line by line into `tracing` under a target.
23. The proxy endpoint is the one place version translation lives: the meta scrub under one `const` prefix (`io.modelcontextprotocol/`, which rmcp keeps private), the `result_type` default on every result `strip_result_type_for_legacy_peer` strips, the capability rewrite for an upstream without `subscribe` or `logging`; a tool binary holds `Args` and `main` alone.
24. Tests sit under `tests/rust/libs/<category>/<crate>/<name>.rs`, wired by a `[[test]] path` row, one case per behavior over the public surface with `insta::assert_snapshot!`, `approx` for floats, `proptest` for an invariant over generated geometry, tables or frames, and `testcontainers` for a collector or service under `#[ignore]`; a crate with container cases adds the `[package.metadata.nx.targets."test:integration"]` row the bridge carries, and a library file holds no `#[cfg(test)]` module.
    `Options::augment_args(Command::new(env!("CARGO_CRATE_NAME"))).try_get_matches_from_mut([..])`

## [01]-[CRATE_USE]

Each catalog row owns logic its members state, and code reaches it through the member. Every named member exists in the crate at the version `Cargo.lock` pins after `cargo upgrade --incompatible`; a member a row's features gate names the feature the row takes. What stays by hand is named per family with the crate type it is written over, and nothing else is.

25. rmcp: `ToolRouter` and `PromptRouter` with `ToolRoute::new_dyn`, `with_route`, `list_all`, `ListToolsResult::with_all_items`; `SubscriptionFilter::builder()..build().supported_by(&capabilities)`; `StreamableHttpServerConfig` with `enforce_origin_validation`, `allowed_hosts`, `with_json_response` and `with_cancellation_token` for the drain; `StreamableHttpService::new(factory, LocalSessionManager, config)` mounted through `axum::Router::route_service`. By hand: cursor pagination over sorted rows as a generic fn (rmcp has `with_all_items` alone), the URI template resource router, request spans and the duration histogram, the parked elicitation.
    `mcp/lib.rs:88` hand version list → `KNOWN_VERSIONS`; `mcp/lib.rs:318-349` `dispatched!` → handler methods; `mcp/lib.rs:435` hand SSE close → `with_cancellation_token`; `server.rs:386-396` `paged!` → generic fn; `server.rs:363-371` fixed `enable_*` → derived capabilities
26. tokio family: `tokio::sync::{broadcast, watch, mpsc, oneshot}` by delivery shape (fan-out, latest value, queue, one reply), `WatchStream::from_changes` to skip the seed, `send_modify` and `send_if_modified` owning value and notification, `futures::future::{select, join, join_all, maybe_done, Either}`, `FutureExt::shared`.
    `server.rs:260-261` `Mutex<BTreeMap>` beside `watch<()>` → one `watch<BTreeMap>` as `mcp/lib.rs:207`; `mcp/lib.rs:168` progress tuple → `Option<ProgressNotificationParam>`
27. opentelemetry family: `Resource::builder_empty()` with `with_schema_url`, `with_service_name`, `with_detectors` gated on an exporter being set, `EnvResourceDetector` after the detectors and before the program attributes and the service-name row; `SpanExporter::builder().build()`, `MetricExporter`, `LogExporter` with no endpoint, header or timeout argument; `TracerProviderBuilder::with_batch_exporter`, `MeterProviderBuilder::with_periodic_exporter`, `LoggerProviderBuilder::with_batch_exporter`; `TextMapCompositePropagator` over `TraceContextPropagator` and `BaggagePropagator`; `OpenTelemetryTracingBridge::builder(&logs).with_tracing_span_attributes(TracingSpanAttributes::all())`; `JsonLayer::stderr()` with `with_opentelemetry_ids(true)` and `add_static_field` for `service.*`; `tracing_subscriber::reload::Layer` over the filter folded with `add_directive`.
    `telemetry/lib.rs:181` telemetry's own name as every span's scope → the emitting crate's scope; `mcp/lib.rs:238,255-260,297-299` metric and span keys written twice → one `const` each
28. validated and nonempty-collections: `Validated::Good`, `Fail(NEVec)`, `map2` to `map4`, `FromIterator`, `ok()`, `NEVec::try_from_vec` for a violation list that may be empty.
    `server.rs:291` `try_fold` over tool schemas → `collect::<Validated<_, _>>()`; `server.rs:167-219` route inserts chained through `Result<Self>` → accumulated
29. serde family: `serde_json::Value` inside a decoder alone, `serde_urlencoded::Deserializer::new(form_urlencoded::parse(..))` for template variables, `jsonschema::validator_for(&schema)` once per tool, `serde_json::to_string` for a resource body with `JSON_MIME_TYPE` from rmcp; an outcome `Option<Result<_, _>>` serializes as a tagged record, never serde's `{"Ok": ..}`.
    `server.rs:130,189` `Option<Result<ServerResult, ErrorData>>` serialized → tagged outcome record
30. axum and matchit: `axum::serve(listener, router).with_graceful_shutdown(stopping.cancelled_owned())`, `Router::route_service(route, service)`; `matchit::Router::insert` with `InsertError` as a source, `at(uri)` matching `MatchError::NotFound` exhaustively; `percent_encoding::percent_decode_str(..).decode_utf8()` with `Utf8Error` as a source.
    `mcp/lib.rs:422-426,443` route, response form, filter and layer fixed in `run` → `Served` defaults

## [02]-[LAYOUT]

31. `libs/rust/<category>/<crate>/` holds `Cargo.toml`, the crate root `lib.rs` beside it and one file per module beside the root; a category holds several crates of one concern, a crate several modules of one concept each, a module that would carry the crate's name is the root. Crate names keep the `rasm-<concern>` prefix, Nx projects and binaries share the package name.
32. `[dependencies]` rows sit under `# --- [RUNTIME]` and `[dev-dependencies]` rows under `# --- [TESTING]`, each `{ workspace = true }` in catalog order; a `[[test]]` row's path climbs to `tests/rust/libs/<category>/<crate>/<name>.rs` (`../../../../tests/rust/libs/services/telemetry/run.rs`).
33. Root `Cargo.toml`: `members = ["libs/rust/*/*", "tools/bridge", "tools/dylint"]`; `# --- [MEMBERS]` rows pair `path` with `version` in dependency order; a catalog row a crate takes sits in the section of its responsibility at the newest release with the features its role needs, `default-features = false` where a default pulls a second clock, TLS, UI or allocator crate (time under tracing-appender and tui-scrollview; chrono under solar-positioning, croner and calamine; clap under tzf-rs, oxipng and mermaid-rs-renderer; gui and rhai under fidget; cuda under opencv), and a comment stating the role and never the name alone; a row the plan adds (`ifc-lite-geometry`, `openusd-schemas`, `sea-query-sqlx`, `zarrs_object_store`, `zarrs_icechunk`, `krilla-svg`, `typst-layout`) enters the same way.
34. A consumer of a moved or rebuilt crate changes in the same run: `tools/bridge` (manifest and `main.rs`), `tests/rust/**` paths, `tools/dylint/examples/*` naming a crate item, an ast-grep rule's `files` or `ignores` scope, the `[MEMBERS]` row; `mise.toml [daemons]`, `.mcp.json` and the Nx inference read the binary name and `cargo metadata` and need no edit.

## [03]-[TARGETS]

A category and crate stand where the catalog's curated groups and the apps' kind of work state a general capability. The apps are Rhino 9 and Grasshopper 2 plug-ins and Blender extensions for architecture and computational design: modelling and fabrication, drawing sets and documentation, BIM and interchange, site, sun and weather, imaging, records, schedules and simulation results. A category holds several crates of one concern, a crate several modules of one concept each, each crate built on its catalog rows used fully and holding nothing those rows and the apps do not state; a crate runs after the crates in its `[AFTER]` cell. A row enters no crate where a host owns the work in-process (rapier3d-f64, urdf-rs, k, acadrust `import`), a machine tool binary owns it (duckdb, oxipng, docx-rs and comrak under pandoc, ast-grep-core, resvg CLI), a sibling row already states it (rstar under parry's `Bvh` and geo, binrw and color under palette, glam f32 under parry's glamx, twofloat, inari and dashu under the predicates their crates carry, hypher, icu, unicode-bidi and unicode-width under parley and typst, minijinja under typst `sys.inputs`, quick-xml outside E57 and CLF), a render queue, its farm client and its output naming are Darkroom's product in the app (process-wrap outside tests, progenitor, sysinfo, chumsky), or no kind of work states it (jagua-rs, geohash, h3o, geoarrow-expr-geo, adbc, arrow-flight, iceberg, apache-avro, iso_currency, rust_decimal, ktx2, intel_tex_2, croner, notify, ffmpeg-next, c2pa, lofty, gilrs, iced, wgpu, winit, every CRDT, DATABASES, SEARCH, MESSAGING, DEVICES, MACHINE_LEARNING, AUTHENTICATION, SECRETS and TRANSFER row other than object_store).
