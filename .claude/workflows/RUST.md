# [RUST_PRINCIPLES]

Rules a crate-by-crate build of `libs/rust` follows.

1. Each crate builds on whole layers beneath, and a category's crates stack by dependency with no type of an upper crate below it: no rmcp type below MCP (`allowed_hosts` feeds rmcp's host check and stays an MCP option), no axum type below the daemon
2. Composition choices (the route, the filter directives, the resource attributes) are field defaults on one record a caller overrides by field, parsed rows (`listen`) stay clap rows of the layer's `Options`, and a typed layer enters as a parameter
3. Catalog types stand wherever they state the value: `nalgebra::Point3<f64>` and `Isometry3<f64>`, `parry3d_f64::shape::{TriMesh, HeightField}`, `kurbo::BezPath`, `geo_types::Geometry<f64>`, `arrow::record_batch::RecordBatch`, `ndarray::Array2<f64>`, `petgraph` graphs, `jiff::Zoned`, `uom::si::f64::Length`, rmcp's params and results, and a crate record holds a composition the catalog lacks, built from those types. A row sits at the newest release unless the catalog crates exchanging its type link an older one (arrow, arrow-schema, parquet and object_store at datafusion's and deltalake's, with serde_arrow on the matching `arrow-*` feature and zarrs_object_store at that object_store; usvg and fontdb at krilla-svg's and typst's; dugong and manatee at merman-render's), and a row no Rasm crate exchanges takes its newest release. Where no release unifies, the value crosses as bytes or slices (font bytes for skrifa across parley, usvg, krilla and hayro; f64 triples across colorimetry's older nalgebra), and each duplicate Clippy's `multiple_crate_versions` fails sits in `clippy.toml` `allowed-duplicate-crates` with its linkage reason: a crate whose every copy is a normal dependency in the `cargo metadata` resolve, which keeps weak `dep?/feature` edges `cargo tree -d` drops, so a duplicate a dev or build dependency also links, as bindgen's itertools under highs-sys, takes no row
4. Geometry runs in `f64`: nalgebra values at every crate signature, parry's glamx values inside parry calls, crossing through nalgebra `convert-glam033` for vectors and points and glamx `nalgebra` for poses. An `f32` kernel (fidget's JIT, meshopt's error metric, stl_io, parley layout, colorgrad) widens on emit, takes its accuracy as a caller parameter and reads positions recentred on an origin its input holds, a bound computed only for input holding none, and sobol_burley's fixed-precision `f32` coordinates widen on emit. Paper space is `f64` millimeters on kurbo, a CRS transform runs through `proj::Transform` on geo_types values in x and y alone (proj's `Coord` binds no z) with height beside it, so a geocentric CRS crosses by hand, and a grid samples through ndarray-interp
5. Hosts reach a crate through a process the services crates serve (an MCP endpoint over `rasm-mcp`, a daemon over `rasm-daemon`) or a stdio binary inside the host package. The catalog holds no in-process binding row. App content (presets, looks, captions, host paths, vendor keys, a render queue and its output naming) sits in the app that composes the crate. Runs that drive a host or view a crate's output leave the owner's frontmost app and focus unchanged: hosts run in the background through Atelier's MCP tools and the `use-rhino`, `use-blender` and `watch-apps` skills, written PDF, SVG and raster output reaches the Read tool as PNG from `pdftoppm`, `resvg`, `vips` or `qlmanage -t`, and no run calls the shell `open`, `qlmanage -p`, an AppleScript `activate`, `AXRaise`, an `AXFrontmost` write or a System Events `keystroke` or `key code`
6. Protocol facts come from rmcp: `ProtocolVersion::KNOWN_VERSIONS` sliced from one declared floor into the `Cow<'static, [ProtocolVersion]>` the handler returns, `LATEST_WITH_INITIALIZE` for the legacy lifecycle, `has_initialize` for a version branch, `ErrorCode` for the code a variant renders and `ErrorData::method_not_found::<M>()` for a method the endpoint never advertised. The floor (rmcp's `known_up_to` states a ceiling alone) and the notifier's broadcast capacity are crate `const`s, and `Peer::listen` sizes a client's buffer at `DEFAULT_SUBSCRIPTION_CHANNEL_CAPACITY`
7. Endpoints are rmcp `ServerHandler`s, and sessions implement every request method an endpoint answers by calling the endpoint's (completion, prompts, resource lists and reads, tools, tasks, custom requests), `get_tool` included where tools exist so `Mcp-Param-*` validation runs (a proxy loads the whole upstream list through `Peer::list_all_tools` at start, on each tool-list change and on each broadcast lag, replacing the held list), and every client notification the endpoint handles (cancel, progress, roots, custom), while `subscribe` and `unsubscribe` hold and release the session's watch leases (rule 20), and `set_level` keeps its default under a `logging` capability no endpoint advertises. No macro rebuilds a `ClientRequest` from the parameters rmcp split; a proxy rebuilds each typed request through one generic forward and maps the answer through one trait over rmcp's response types. One generic instrumented call, named by the method's `ConstString::VALUE` and a custom request by its own method, wraps every request a session answers: `initialize` (through rmcp's `negotiate_initialize`, starting the session-duration clock) and `discover` (from the forwarded `get_info` and `supported_protocol_versions`) included, and `ping` alone keeps rmcp's default
8. Elicitation builds its schema through `ElicitationSchema::from_type::<T>()`, asks a client with `initialize` through `Peer::create_elicitation` and a client without it through the parked `InputRequiredResult` with `request_state`, and decodes the answer through `serde_path_to_error` so a malformed answer names its path (`Peer::elicit` returns `Option<T>` and a bare `serde_json::Error`)
9. Calls that declare the tasks extension, which a 2026 client sends in each request's `_meta` and `RequestContext::client_capabilities` reads first, are `TaskManager` tasks on a server whose build registered a tool router (`CreateTaskResult`, `GetTask`, `UpdateTask`, `CancelTask`, `TaskContext::request_input` answering the call's elicitation, `TaskContext::set_status_message` carrying its progress messages). `TaskManager`'s sweep aborts a task still running at its TTL, so a read-only task's TTL is the server's retention and a destructive task, which runs past `tasks/cancel` to its end, takes `None`. The ledger of destructive calls finished after cancellation is one `watch::Sender<BTreeMap<_, _>>` edited through `send_modify` and read as a resource through `WatchStream::from_changes`. `TaskManager` lists nothing and spawns each task detached, so its tasks escape the drain and end with the runtime
10. Progress is `ProgressNotificationParam` held as `watch::Sender<Option<ProgressNotificationParam>>`, its token set by the reader that delivers it: each relay of a request carrying a `progressToken` seeds the param or rewrites its token, so a resumed call reports to its new request, a task seeds its task id, and a report nothing seeded drops. A client routes upstream progress by token through `ProgressDispatcher`
11. Providers stay typed: `SdkTracerProvider`, `SdkMeterProvider` and `SdkLoggerProvider` share no trait, and the tracer, the log bridge and the globals take each by type
12. `clap` rows exist for variables no crate reads: `OTEL_TRACES_EXPORTER`, `OTEL_METRICS_EXPORTER`, `OTEL_LOGS_EXPORTER`, `OTEL_PROPAGATORS`, `RUST_LOG` merged over program defaults, `OTEL_SDK_DISABLED` setting every exporter to none, and the hidden rows of the OpenTelemetry environment carrier, one per field the configured propagators read, each a bare `env` naming its variable from the field so no literal spells a propagator field. `OTEL_SERVICE_NAME` keeps a row because `Resource::builder()` lets `OTEL_RESOURCE_ATTRIBUTES` override it and falls back to `unknown_service`. `OTEL_EXPORTER_OTLP_*`, `OTEL_BSP_*`, `OTEL_BLRP_*`, `OTEL_METRIC_EXPORT_*` and `OTEL_TRACES_SAMPLER*` reach the SDK and the exporters untouched
13. Span and metric keys come from `opentelemetry_semantic_conventions::{attribute, metric}`, and a key the crate lacks or marks deprecated (the `mcp.*` and `gen_ai.*` keys and `mcp.server.operation.duration`, deprecated as moved to the GenAI conventions) is one crate `const` the span and the metric read, beside the values the convention fixes and the crate omits: the `execute_tool` operation, the `tcp` transport, the `http` protocol name and the duration's advised bucket boundaries. The instrumentation scope names the emitting crate
14. Request spans hold `otel.name`, `otel.kind`, the protocol fields and `Empty` slots recorded at the end. Each carrier (the request `_meta`, the HTTP headers) is read through `global::get_text_map_propagator` into an empty `Context` over the dependency's `Extractor` for it (`HeaderExtractor`, one crate newtype over `MetaObject` serving `Extractor` and `Injector`), which reads only the fields the propagator asks for with no copy into a map, and a span takes a parent only where a carrier holds one: the `_meta` span, else the header span, the header span linked when both hold different spans; a request carrying neither keeps its tracing parent. The error path matches every `set_parent` case, and a span ending in failure sets `Status::error`. A request a span forwards (a proxy's upstream call) carries the current `Context` (the attached parent outside any span, the entered span's inside one), injected through the same newtype over the forwarded `_meta`, never the inbound carrier's
15. Tool-facing errors add `Serialize` with `#[serde(tag = "_tag")]` and `#[serde(skip)]` on sources, and one function renders a crate error into `ErrorData` with the code chosen by variant and the error as `data`
16. Independent routes, schemas, files and rows accumulate through `Validated`
17. Locks scoped to one closure use `with_mut`, `get_cloned`, `set` or `replace` under `lock_value_accessors`
18. Shutdown drains on the first signal and abandons on the second: in-flight requests finish (`TaskTracker::close` then `wait`) before the cancel, each task the cancel stops is awaited after it by the scope owning it (a watch `TaskTracker`, the server's graceful end for standalone streams), and the drain ends when every such scope has ended
19. Unix interrupt, terminate and hangup and Windows ctrl-c streams join through `try_collect::<stream::SelectAll<_>>()` from one `cfg_select!` value
20. Watchers shared across sessions are `Weak<AbortOnDropHandle<()>>` leases in a map pruned by `strong_count`, each subscriber holding an `Arc` for exactly its subscription's life: a legacy `resources/subscribe` in the session's `watch` map until `unsubscribe`, and a `subscriptions/listen` in its own stream, the leases `accepted_subscription_filter` takes parked on the session until that listen claims them, so no listen's lease outlives it or joins the legacy map
21. Capabilities derive from the routers an app registers while it builds, each held in an `arc_swap::ArcSwapOption` that is `None` until registered: a kind registered, even empty, is advertised with its `list_changed`, and a kind never registered stays absent for the process. A vendor's `_meta` vocabulary is a `Serialize` record of `Option` fields with `#[serde(rename = "<vendor>/<key>")]` in the app that sets it, written into `MetaObject` through serde, and the library holds no vendor key
22. Clients over an upstream are `serve_client_with_lifecycle_and_ct` under `ClientLifecycleMode::Auto { preferred_versions, legacy_version: Some(ProtocolVersion::LATEST_WITH_INITIALIZE) }` (the served versions without `initialize`, newest first); notifications arrive through `Peer::listen(filter)`, where `SubscriptionEnd::Lagged` re-listens on `acknowledged()` and resyncs, and outside a subscription through the client `Service::handle_notification`, which hands progress to `ProgressDispatcher`; an upstream without `initialize` receives `RequestMetaObject::with_client_context`. Child upstreams are `TokioChildProcess::builder(command).stderr(Stdio::piped()).spawn()` with stderr relayed line by line into `tracing` under a target
23. Version translation sits in the proxy endpoint alone: the meta scrub under one `const` prefix (`io.modelcontextprotocol/`, which rmcp keeps private), the `result_type` default on every result `strip_result_type_for_legacy_peer` strips, the capability rewrite dropping `logging` and, for an upstream with `initialize`, resource `subscribe`. A tool binary holds its parsed arguments and `main` alone: a derived `Args`, or a hand `CommandFactory` and `FromArgMatches` pair where the derive cannot construct the value the binary runs (a wrapper's program and arguments parsed straight into one `Command` under one `trailing_var_arg` positional, so every token after the program reaches it)
24. Tests exist for tools alone: a dylint lint's example and UI snapshot under `tests/rust/tools/dylint/`, and a tool binary's cases under `tests/rust/tools/<tool>/`; a library crate holds no test target, `[[test]]` row or `#[cfg(test)]` module
