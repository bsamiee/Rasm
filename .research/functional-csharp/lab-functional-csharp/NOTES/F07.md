## Corrections and findings

- `par(Format, "Hey")` with a static method group fails CS0411 (`par<T1, T2, R>` cannot infer `T2` and `R` from a method group). `fun(Format)` with the same method group resolves to the `fun(Action)` overload and fails CS1503. `fun<string, string, string>(Format)` compiles, and so does `par(static (string greeting, string name) => ..., "Hey")` without `fun`: explicit lambda parameter types are what inference needs. The doc names `fun` as the form that gives a lambda its `Func` type at the call site and keeps the book's advice to expose delegate values.
- MA0003 fires on a `bool` literal passed to `par` (`par(ParseBooks, false, ...)`), so the parser exposes `const bool SkipHeader`/`KeepHeader`. A `bool` literal passed to a curried delegate (`Curried(true)`) does not fire MA0003.
- MA0089 rejects `string.Replace(string, string, StringComparison)` when both arguments are single characters; the lab uses the `char` overload.
- The plan's `ConnectionIO` stub compiles as `internal interface ConnectionIO { public Seq<T> Query<T>(SqlTemplate template, object parameters); }` (IDE0040 requires the `public` modifier). The trait is read through `Has<Eff<RT>, RT, ConnectionIO>.ask`, the cached accessor class in `LanguageExt.Traits`; `Has<Eff<RT>, ConnectionIO>.Ask` cannot be called through the interface.
- `IO.lift(owner.ToFin(new OwnerNotFound()))` is the boundary that turns `Option` absence into a typed error inside the `Eff` query; `Eff<RT, A>.SelectMany` has no `Fin<B>` overload, so a `Fin` enters a LINQ query over `Eff` through `IO.lift(Fin<A>)` or `Eff<RT, A>.Lift(Func<Fin<A>>)`.
- `Lookups<RT>` is a generic static class so the `par` specializations are fields; CA1000 does not fire on an `internal` generic type.
