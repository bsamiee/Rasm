## Corrections with evidence

- The plan named `Lens.Compose` and `Lens.tuple` for composition. `DECOMP/sigs/Lens.txt` has no `Compose`; `tuple` pairs two lenses over a tuple, it does not chain them. Composition is `Prelude.lens(la, lb)` (overloads up to ten lenses in `DECOMP/sigs/Prelude.txt`). The doc uses `lens(Account, AllowedOverdraft)`.
- The plan spelled the prepend as `Cons` or `transaction.Cons(Transactions)`. Only the extension form resolves (`LanguageExt.Pretty.Cons<A>` shadows the bare name, as `LAB-NOTES.md` records). The doc uses `transaction.Cons(Transactions)`.
- The book said "Calling `Tail` on an empty list is a programming error". `Seq<A>.Tail` on an empty sequence returns an empty sequence and `Head` returns `None` (both executed). The sentence now states that.
- The book's `With` used nullable optional parameters with `null` as the "not supplied" marker. The doc uses `Option<AccountStatus>` and `Option<decimal>` optional parameters with `= default` and `IfNone`, which removes the `null` marker the corpus rejects. The prose sentence about `null` was replaced by one sentence about `Option` and `IfNone`.
- `toSeq(IList<A>)` copies through `value?.ToArray()` (decompile at `Prelude.toSeq`), so the boundary copy is eager for a `List<T>` argument: the sample adds to the source list after `toSeq` and the `Seq` keeps `Count == 1`. `Strict()` exists on `Seq<A>` but is not needed for a list argument, so the doc does not name it.
- `Map<K, V>.Add` throws `ArgumentException` for a present key and `SetItem(K, V)` throws for an absent key (decompile comments, executed through `Try.lift`). The doc states both in one sentence. `TryAdd` and `AddOrUpdate` exist and are left out to keep one path.
- Analyzer rulings met here: IDE0090 requires target-typed `new(...)` in an expression-bodied method whose return type is the created type (`new Circle(...)` and `new AccountState(...)` were rejected). RCS1161 requires explicit enum values (`Requested = 0, Active = 1, Frozen = 2`).
