## Members verified (compiled and executed)

- `IO<A>` as a lazy argument: `Pick<A>(bool, IO<A>, IO<A>)` returns the chosen effect; the unchosen `IO.lift` never runs (an `Atom<int>` counter stays at its prior value). The eager overload `Pick<A>(bool, A, A)` in the same class resolves beside it without ambiguity.
- `Prelude.memo(Func<A>) : Memo<A>` with `Memo<A>.Value`: two reads of `Value` run the function once (`computed.Value == 5` after `Twice`).
- `Option<A> | Option<A>`: compiles, and the right operand is evaluated before the operator runs (the database read counter advances even when the cache hits).
- `Option<A> || Option<A>`: compiles because `Option<A>` declares `operator true`, `operator false`, and `operator |`. The right operand is skipped when the left is `Some` (counter unchanged) and evaluated when the left is `None` (counter advances).
- `Option<A>.IfNone(A)` and `Option<A>.IfNone(Func<A>)`: both return `A`; the `Func<A>` form runs the fallback only on `None`.
- `IO.lift(Func<A>)`, `IO<A>.Map`, `IO<A>.Bind`, `RunSafe() : Fin<A>`: building `Doubled` and `Summed` leaves the counter at zero; running them advances it.
- `Try.lift(Func<A>)`, `Try<A>` LINQ (`from`, `let`, `from`, `select`) through `SelectMany(Func<A, Try<B>>, ...)`, `Try<A>.Run() : Fin<A>` (`TryExtensions.Run`). Malformed JSON and an invalid URI arrive as `Error` with `IsExceptional == true`. A missing property, thrown by `JsonElement.GetProperty` inside the `let` clause, is also captured: `TryExtensions.Run` wraps `runTry()` in its own `try`/`catch`, so a throw from a bind function still returns `Fail`.
- `System.Text.Json.JsonDocument.Parse(string)` and `JsonElement.GetProperty(string).ToString()` compile from the BCL with a fully qualified name (no file-level `using`; the namespace is not in the global usings).
- `Reader.ask<Env>()`, `Reader.asks<Env, A>(Func<Env, A>)`, `Reader.local<Env, A>(Func<Env, Env>, Reader<Env, A>)`, `Reader<Env, A>` LINQ over `ask` and another `Reader`, instance `Reader<Env, A>.Run(Env) : A`, instance `Reader<Env, A>.With<Env1>(Func<Env1, Env>) : Reader<Env1, A>`.
- `ReaderT.ask<IO, Env>()`, `ReaderT<Env, IO, A>` LINQ with an `IO<B>` in a `from` clause (`SelectMany(Func<A, IO<B>>, ...)`), `ReaderT.with<Env, SubEnv, IO, A>(Func<Env, SubEnv>, ReaderT<SubEnv, IO, A>)`, `ReaderT<Env, IO, A>.Run(Env) : K<IO, A>` then `.As().RunSafe()`. Building the `ReaderT` runs nothing (counter at zero before `Run`).
- `IO<A>.Bracket(Use:, Fin:)` around `System.Diagnostics.Stopwatch.StartNew` passed as a method group to `IO.lift`; `Fin` writes the elapsed time into an `Atom<TimeSpan>` (`elapsed.Value > TimeSpan.Zero`).
- `use(Func<A>)` for an `IDisposable` (`Connection`, and `Transaction` through the method group `connection.BeginTransaction`), `IO.lift(fun(Action))` as the commit step, `IO.fail<A>(Error)` inside a `use` scope. Every `Connection` is disposed on success and on failure; the open `Transaction` is rolled back by `Dispose` on failure and committed on success.

## Corrections with evidence

- CORRECTION to the plan: `use(Func<A>, Action<A>)` runs the release action on every exit, including a failed effect. With `use(() => connection.BeginTransaction(), static t => t.Commit())` and an `IO.fail` inside the scope, `Transaction.Committed` advanced for the failing run as well (`committed=2` after one success and one failure, `RolledBack == 0`). A commit therefore does not belong in a release action. The doc uses `use(connection.BeginTransaction)` (dispose rolls back an open transaction) and an explicit `IO.lift(fun(transaction.Commit))` step after the statements, which runs only on success.
- CORRECTION to the plan: `Option | Option` compiles but is eager, so it cannot stand for the lazy `OrElse`. The `||` form is the lazy alternative (`operator true` on `Option<A>`). The doc shows `|` as the eager fallback and `||` as the deferred one; `BiBind` and `Match` were not needed.
- `use(() => connection.BeginTransaction())` fails IDE0200 (lambda can be removed); the method group `use(connection.BeginTransaction)` resolves to `use<A>(Func<A>) where A : IDisposable`.
- `IO.lift(System.Diagnostics.Stopwatch.StartNew)` as a method group resolves to the `Func<A>` overload (no ambiguity with `Func<Fin<A>>`).
- Analyzer rulings met here: IDE0060 rejects an unused `int id` parameter on a query that embeds the id in a literal statement (the doc's `DeleteOrder` is a property); a `bool` argument is named (`takeLeft: true`); string comparisons use `string.Equals(..., StringComparison.Ordinal)`.
- The `JsonDocument` bound inside the `Try` query is never disposed. CA2000 did not fire (the value is returned from the lifting lambda and bound as a range variable). A project that parses large documents disposes it at the host.
