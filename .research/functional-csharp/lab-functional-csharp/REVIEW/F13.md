1. **Location** line 221.
   **Claim** "`Map<K, V>` is the production form of this model. `Map` reconstructs the same shape with
   transformed leaf values. `Aggregate` threads an accumulator through both subtrees."
   **Evidence** `Map` and `Aggregate` were the hand-rolled tree functions of the removed code block. After
   the added first sentence, both read as members of `Map<K, V>`, and neither exists: `ilspycmd -t
   'LanguageExt.Map`2'` has `Select<U>(Func<V, U>)` (line 1433) and `Fold<S>(S, Func<S, K, V, S>)`
   (line 1755), and no `Map` or `Aggregate` member. The brief requires every identifier in prose to exist.
   **Correction** replace the three sentences with:
   "`Map<K, V>` is the production form of this model. `Select` rebuilds the same shape with transformed
   values. `Fold` threads an accumulator through the tree. An insertion reconstructs only the nodes on the
   path to the insertion point and reuses every untouched subtree."

   **Claim** "`Seq<A>` is the production form of this model, with `Head`, `Tail`, and `Cons`."
   **Evidence** two defects. `Seq<A>` has no `Cons` member: `sigs/Prelude.txt:4656` declares
   `Cons<A>(this A head, Seq<A> tail)` on the element, and `sigs/Seq_1.txt` lists `Add(A)` only; LAB-NOTES

   falls into `CloneCons`, which copies the buffer. The diagram at lines 195-201 prepends twice from one
   original and line 201 states a shared tail, which holds for the model and not for `Seq<A>`.
   **Correction** replace the added sentence with:
   "`Seq<A>` reads the same two cases through `Head`, `Tail`, and `Match`, and the element-level `Cons`
   prepends."
   Leave lines 193-207 as the model's diagram and costs.

3. **Location** line 209.
   **Claim** "Index work goes through `Lst<A>`, which provides `Insert`, `RemoveAt`, and `SetItem`."
   **Evidence** placed directly under the bullet "Insert or remove at index `m`: `O(m)` traversal and `m`
   rebuilt prefix nodes", the sentence assigns that cost to `Lst<A>`. `Lst<A>` is a balanced tree:
   `ListModule.Insert` (decompile lines 84-99) descends by index and wraps every rebuilt node in
   `Balance(Make(...))`, and `ListItem<A>` carries `Height` and `Count`. Index work is logarithmic.
   **Correction**
   "Index work goes through `Lst<A>`, which provides `Insert`, `RemoveAt`, and `SetItem` over a balanced
   tree."

4. **Location** line 99 (the paragraph beginning "Public setters plainly allow property replacement").
   **Claim** the whole paragraph, including "Expose `IEnumerable<T>` or `IReadOnlyList<T>` when callers do
   not need mutation operations" and "These measures support functional use but cannot universally enforce
   deep immutability, particularly across types whose implementation is outside the current code."
   **Evidence** the text is not in the source chapter (`buonanno-functional-csharp/chpater-9.md`); it is a
   fold-in of `painter-functional-csharp/chpater-2.md` lines 161-170, with that file's bullet list run into
   one paragraph. It restates what the file already says: line 66 ("Immutability must extend through every
   referenced value"), line 89 ("Remove property setters"), line 97 ("An immutable top-level object
   containing a mutable list is still mutable"), and line 145 ("No C# technique can make mutation
   absolutely impossible"). The `IEnumerable<T>`/`IReadOnlyList<T>` sentence offers a BCL alternative
   against line 92 ("Store collections in immutable collection types such as `Seq<A>`"), which breaks the
   one-path rule. Three `-ly` adverbs ("plainly", "universally", "particularly") break the added-prose rule.
   **Correction** delete the paragraph. If it predates the LanguageExt integration and must stay, delete at
   minimum the two sentences that collide, leaving:
   "Public setters allow property replacement. Private setters limit replacement by callers, but do not make
   the object graph deeply immutable: code inside the class can still assign properties, a referenced list
   can still change, and a nested object can expose its own mutation operations. Construct a value
   completely, then do not reassign or mutate it, and apply the same discipline to every nested object."
