## [02]-[SEQUENCE]

1. Read the requested guidance, its references, the related agents, and the rules that use its instructions
2. Identify each distinct instruction, its source, and the decision it changes
3. Read the primary sources of the question and the results of actual work, excluding repositories and binaries unrelated to the question
4. Classify opportunities as duplicate guidance, incorrect behavior, missing condition, unnecessary coupling, or useful capability
5. Resolve each finding from its owning source, and reproduce disputed behavior in a scratch project under the scratchpad
6. Edit the owning passage, move detail before deleting its old copy, and update the affected routes and agents together
7. Preserve earlier conditions and mechanisms from file history unless evidence supports changing them
8. When the mechanism changes supported behavior, update affected assets, templates, scripts, configuration, and rule families
9. Record each finding, its evidence, disposition, and owning passage in the report, with superseded findings apart from final decisions
10. Report the changes, their sources, unresolved questions, and checks run

Keep everyday routing, semantic limits, and correction criteria in `SKILL.md`. Put a substantial task-specific procedure or mechanism in a reference only when an agent needs it to complete that category of work. Keep invocation details with the mechanism they enable; keep reusable scaffolds language-agnostic. Agents own scope, file ownership, and execution, and reference the shared criteria instead of repeating them.

## [04]-[CAPABILITIES]

Add a capability when it completes a real task, simplifies an existing mechanism, or corrects a misleading instruction. State the selection criterion beside the supported form.

Derive reusable guidance from the correction that exposed a limitation: identify its condition, the supported operation, and the related forms with the same contract. Integrate those forms into the existing category instead of preserving an isolated workaround or research account. Confirm the guidance against retained templates, real rule consumers, and public invocation.

Prefer direct tool and package operations over wrappers. Keep declarative rules when they express the correction clearly, and use the bindings when computation makes the YAML harder to maintain. Preserve the distinction between a syntax match, a type fact, and behavior equivalence.
