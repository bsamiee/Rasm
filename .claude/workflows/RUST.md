# [RUST_PRINCIPLES]

Rules a crate-by-crate build of `libs/rust` follows.

## [01]-[LAYERS]

Crates build on whole layers beneath them, and hosts and apps compose them from outside:
- Categories stack crates by dependency, and no crate holds a type of a crate above it
- Crates below `rasm-mcp` hold no rmcp type and crates below `rasm-daemon` no axum type, `allowed_hosts` staying an MCP option
- Crates exchange catalog types: nalgebra, parry shapes, kurbo paths, geo_types, arrow batches, ndarray, petgraph, jiff, uom, and rmcp
- Geometry runs in `f64` with nalgebra at every signature and parry's glamx values inside parry calls
- `f32` kernels widen on emit, take accuracy from the caller, and read positions recentred on an origin their input holds, else a computed bound
- Paper space is `f64` millimeters on kurbo
- Hosts reach a crate through a served process (an MCP endpoint, a daemon) or a stdio binary inside the host package
- Crates name, bind, and couple to no host application, and the catalog holds no in-process binding row
- App content (presets, looks, captions, host paths, vendor `_meta` keys, a render queue and its output naming) sits in the composing app
- Crates restate no `libs/dotnet` or `libs/python` capability: `Rasm.Drafting` standards, grading, filters, or codec pipelines
- Runs view written PDF, SVG, and raster output as PNG from `pdftoppm`, `resvg`, `vips`, or `qlmanage -t`, leaving the frontmost app unchanged

## [02]-[LAYOUT]

Crates sit at `libs/rust/<category>/<crate>/`, and root `Cargo.toml` holds the catalog rows they take:
- Categories hold crates of one concern, and crates hold modules of one concept each
- Crate roots `lib.rs` hold the crate error and core value, each module one file beside the root
- Module families sit in a folder beside a file of the family's name holding shared code (`authoring.rs` beside `authoring/`), never `mod.rs`
- Modules take their concept's name, never the crate's or an imported crate's (`transmission.rs` for glTF, `gridded.rs` for GRIB)
- Crates export no name another crate exports for another concept
- Crate names take the `rasm-<concern>` form
- Manifests list `[dependencies]` under `# --- [RUNTIME]`, `[dev-dependencies]` under `# --- [TESTING]`, each `{ workspace = true }` in catalog order
- Catalog rows hold a comment stating their role, a feature only a caller's argument reads (typst-kit `embedded-fonts`) sitting on that caller's row
- Row comments state a cost no feature removes as what the row adds beside the workspace pick it duplicates ("adds `time` 0.3 beside jiff")
- Catalog rows sit at an older release only where crates exchanging their type link it
- Values cross as bytes or slices where no release unifies (font bytes, PDF bytes, `f64` triples)
- `allowed-duplicate-crates` rows hold crates with every copy a normal dependency in `cargo metadata`, naming each copy's linking crates
- Tool binaries hold their parsed arguments and `main` alone
- `.config/mise.toml` `[daemons]`, `.mcp.json`, and Nx inference read binary names and `cargo metadata`, needing no edit on a rebuild
