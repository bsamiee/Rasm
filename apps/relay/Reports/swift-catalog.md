## [01]-[PANEL_CONVENTIONS]

- Width is a constant per OS, not measured: `.macOS26 = 310`, `.macOS11Thru15 = 300`, selected by `#available` in `MenuWidth.currentPlatform()` and applied once as `.frame(width: width?.width)` on the menu root (MCCUI `Sources/MacControlCenterUI/Types/MenuWidth.swift`, `Menu/MacControlCenterMenu.swift:125`).
- Padding constants live in one enum, not at call sites: `menuHorizontalContentInset = 14`, `menuHorizontalHighlightInset = 6` on macOS 26 else `4`, `menuPadding = 6`, `menuItemPadding = 4`, `menuItemContentStandardHeight = 18` (MCCUI `Sources/MacControlCenterUI/Menu Internal/Menu Constants.swift`).
- Row height is an enum of named cases with a computed `contentHeight`/`paddingHeight`/`boundsHeight`, so a row never hardcodes a number: `.standardTextOnly` 18, `.controlCenterIconItem` 26, `.controlCenterSection` 20, plus `.auto` and `.custom` (MCCUI `Sources/MacControlCenterUI/Types/MenuItemSize.swift`, `Controls/MenuCircleButton/MenuCircleButtonSize.swift`: menu 26, prominent 38).
- Maccy reaches the same result with two `#available(macOS 26)` constants on the store: `Popup.itemHeight` 24 on macOS 26 else 22, `Popup.cornerRadius` 7 else 4, with the comment that the radius is chosen so an inset row matches the panel curvature (MACCY `Maccy/Observables/Popup.swift`).
- Typography: rows set no font at all and inherit the panel default; semantic fonts appear only where a role differs — `.caption` for the index badge (MACCY `Maccy/Views/ListItemView.swift`), `.body` for preview text (`Maccy/Views/PreviewItemView.swift`). Across Maccy's 122 files only two `.font(.system(size:))` calls exist, both for monospaced debug text (`Maccy/Settings/AdvancedSettingsPane.swift:17,27`).
- The one justified fixed size is the header, pinned to the AppKit menu font: `.font(.system(size: 13, weight: .bold))` for a header and `.semibold` for a section label, via `MenuStyling.headerFontSize` (MCCUI `Sources/MacControlCenterUI/Menu Items/MenuHeader.swift:128`, `MenuSectionText.swift:51`).
- Hover feedback is one reusable wrapper, not per-row code: `HighlightingMenuItem` holds `@State isHighlightedInternal`, flips it in `.onHover`, force-clears it when `isEnabled` goes false, and fills a `RoundedRectangle(cornerSize: 10, style: .continuous)` on macOS 26 else radius 5, inset by `menuHorizontalHighlightInset` (MCCUI `Sources/MacControlCenterUI/Menu Abstracts/HighlightingMenuItem.swift`).
- Hover colors are semantic: `Color(NSColor.selectedContentBackgroundColor)` and `selectedMenuItemTextColor` for the menu style; the Control Center style uses `Color(white: 0.3, opacity: 0.4)` dark / `Color(white: 0.9, opacity: 0.2)` light and disables at `.opacity(0.4)` (MCCUI `Menu Internal/Menu Constants.swift`, `Menu Items/MenuCommandStyle.swift:37-65`).
- Press feedback reproduces the NSMenu blink rather than a scale: clear highlight, `Task.sleep(seconds: 0.080)`, set, sleep 80 ms, then act; dismissal waits a further 100 ms so the panel closes before the action runs (MCCUI `Menu Items/MenuCommand.swift`, `userTapped()`). An icon-button alternative is a `ButtonStyle` with `configuration.isPressed` driving `.scaleEffect(0.95)` and `.animation(.easeInOut(duration: 0.2), value:)` (NOTCH `boringNotch/components/Live activities/BoringBattery.swift:78`).
- Rows must set a hit-testable background or hover breaks: Maccy paints `.white.opacity(0.001)` on unselected rows with the comment that macOS 26 broke hovering when no background is present (MACCY `Maccy/Views/ListItemView.swift`). Every row also carries `.contentShape(Rectangle())` (MCCUI `Menu Abstracts/HighlightingMenuItem.swift`).
- Nobody measures with `NSViewRepresentable`. Maccy reads size with `onGeometryChange(for:)` wrapped in one `SizeReaderModifier` and writes through a `Binding` built from a key path on the store (MACCY `Maccy/Views/HeightReaderModifier.swift`). Ice uses one `.onFrameChange(update: $frame)` modifier (ICE `Ice/UI/IceBar/IceBar.swift:306`). MCCUI applies `.geometryGroupIfSupportedByPlatform()` instead of measuring, to stop child layout from animating independently.
- Height cap is derived from the screen, not a literal: `NSScreen.screens.first?.visibleFrame.height - 30`, with a comment explaining why `screens.first` and not `NSScreen.main`, feeding `MenuScrollView(maxHeight:)` whose frame is `min(maxHeight, contentHeight)` and which disables scrolling when content fits, drawing `chevron.compact.up/down` affordances in 5pt strips (MCCUI `Menu/MacControlCenterMenu.swift:161-186`, `Menu Items/MenuScrollView.swift`).
- Maccy computes the panel height in the store, not the view: `suitableHeight(for:)` sums list + header + extras + footer, `preferredHeight(for:)` clamps between a floor of three rows (`3 * Popup.itemHeight`) and the user's saved `windowSize.height`, then calls `panel.verticallyResize(to:)` (MACCY `Maccy/Observables/Popup.swift`).
- State changes animate by value, not by imperative `withAnimation`: `.animation(.default.speed(3), value: appState.history.items)` on the list and `.animation(.easeInOut(duration: 0.2), value: appState.searchVisible)` on the panel root (MACCY `Maccy/Views/ContentView.swift`). MCCUI names the panel-resize curve once as `Animation.macControlCenterMenuResize = .smooth(duration: 0.2, extraBounce: 0.25)`, with a comment that it matches the macOS 26.2 window resize speed, and attaches it at the binding: `$isExpanded.animation(.macControlCenterMenuResize)` (MCCUI `Utilities/VisualEffect.swift:144-156`, `Menu Abstracts/HighlightingMenuDisclosureGroup.swift:99`).
- Appear/disappear glitches are prevented structurally: content that may vanish sits inside a permanent `MenuSection` container so the parent stack never changes child count, documented in the demo (MCCUI `Demo/Demo/MenuView.swift:52-62`).
- Dismissal flows through an environment binding rather than a window call: `EnvironmentValues.isMenuBarExtraPresented: Binding<Bool>`, injected once by the menu root and set to `false` by a command (MCCUI `Menu Internal/IsMenuBarExtraPresentedEnvironmentKey.swift`, `Menu/MacControlCenterMenu.swift:143`).
- Refresh on open: Ice's panel is `async` on the way in — `func show(section:on:) async` prepares the item image cache before ordering the window front (ICE `Ice/UI/IceBar/IceBar.swift:154`), and the content view triggers scroll indicators once with `.task { scrollIndicatorsFlashTrigger += 1 }`. Maccy loads on the panel's `.task { try? await appState.history.load() }` and, because a `FloatingPanel` is not a scene, synthesizes `scenePhase` from `NSWindow.didBecomeKey`/`didResignKey` filtered on the window identifier (MACCY `Maccy/Views/ContentView.swift`).
- Panel chrome: `RoundedRectangle(cornerRadius: 10)` filled with `Color(NSColor.windowBackgroundColor).opacity(0.25)` over an `NSVisualEffectView(.underWindowBackground, vibrancy: true, blendingMode: .behindWindow)`, bordered only in dark mode with two 0.5pt strokes, content padded 10 with `VStack(spacing: 8)` (MCCUI `Controls/MenuPanel.swift`, `Menu Abstracts/HighlightingMenuItem.swift` visual effect). Maccy swaps the whole background by OS: `GlassEffectView()` on macOS 26 else `VisualEffectView()` (MACCY `Maccy/Views/ContentView.swift`).
- The scene modifiers that make a window panel behave: `.menuBarExtraStyle(.window)` plus `.windowResizability(.contentSize)`, with a comment that the resizability modifier is optional and affects height animation (MCCUI `Demo/Demo/DemoApp.swift`).

## [02]-[PROGRESS_AND_USAGE_BARS]

- A stacked usage bar is a `Chart` of `BarMark`s, not a `ZStack` of rectangles: height 20, `.cornerRadius(2)`, `.chartXAxis(.hidden)`, `.chartLegend(.hidden)`, colors bound by `.chartForegroundStyleScale([...])`, and a hand-built legend of 8×8 `Circle`s with `.font(.footnote).foregroundStyle(.secondary)` (CORK `Cork/Views/Start Page/Sub-Views/Cached Downloads Folder Info Box.swift`).
- The Control Center slider/level bar is 22pt tall and capsule-shaped: `sliderHeight = 22` documented as "fixed to mirror that of macOS's Control Center… never found at variable heights", `.cornerRadius(20)` with a `RoundedRectangle(cornerRadius: 20).stroke(borderColor, lineWidth: 0.25)` overlay, white fill on a clear track, and a knob `Circle` of exactly `sliderHeight` (MCCUI `Controls/MenuSlider/MenuSlider.swift:35-40,380-445`).
- That file also records that Apple does not animate its own level bars, so the animation is left commented out (MCCUI `Controls/MenuSlider/MenuSlider.swift:440-444`).
- Determinate progress uses `ProgressView(value:total:) { Text(...) }.progressViewStyle(.linear)` — the label goes inside the initializer and the style places it; no manual `HStack` of label and bar (CORK `Cork/Views/Mass App Adoption/Mass Adoption Stages/Mass Adoption Stage - Adopting.swift:30-38`, `Cork/Views/Updating/Sub-Views/Complete Updating/Update All Packages View.swift:45`). Indeterminate is `ProgressView()` with `.progressViewStyle(.circular)` (ICE `Ice/Settings/SettingsPanes/GeneralSettingsPane.swift:247`).
- Where the built-in styles are the wrong size, the extension point is a `GaugeStyle`, not an ad-hoc view: `MiniGaugeStyle: GaugeStyle` draws two `Circle`s with `lineWidth: 10`, `lineCap: .round`, `.rotationEffect(.degrees(-90))` and `.animation(.easeOut, value: configuration.value)` (CORK `Cork/Styles/Gauge - Mini Gauge.swift`, used at `Cork/Views/Services/Service Detail/Sub-Views/Service Modification Buttons.swift:136`).
- Apple's own vocabulary for a capacity bar is `Gauge` + `.gaugeStyle(.linearCapacity)` ("a bar that fills from leading to trailing edges as the value increases"), with `.accessoryLinearCapacity` as the compact variant; `ProgressViewStyle` offers only `.linear` and `.circular` (developer.apple.com/documentation/swiftui/gaugestyle, .../progressviewstyle). `Gauge` is the right type when a value has a range and a current-value label; `ProgressView` when it is a task's completion.
- Numbers in labels come from a `FormatStyle`, never string interpolation of a computed unit: `.formatted(.byteCount(style: .file))` for sizes, `.formatted(.list(type: .and))` for joined lists (CORK `Cork/Views/Start Page/Sub-Views/Cached Downloads Folder Info Box.swift:27`, `Modules/Packages/PackagesModels/Models/Brew Package.swift:101`).
- Accessibility on a bar: hide the decorative text, label the mark, and put the value in `accessibilityValue` formatted — `.accessibilityHidden(true)` on the overlay annotation, `.accessibilityLabel(markAccessibilityLabel)`, `.accessibilityValue(size.formatted(.byteCount(style: .file)))`, and `.accessibilityElement(children: .contain)` on the chart (CORK, same file, lines 70-100).
- Counterexample to avoid: a bar whose width is `CGFloat(((CGFloat(CFloat(level)) / 100) * (width - 6)))` and height `(width - 2.75) - 18`, colored with literal `.white`/`.red`/`.green`/`.yellow` and no accessibility at all (NOTCH `boringNotch/components/Live activities/BoringBattery.swift:29-60`).
- Semantic color for a level: derive from state in one computed property (`batteryColor` above is the right shape, the literals are not); Cork tints status by severity with `.tint(.red)` / `.tint(.orange)` (CORK `Cork/Views/Sidebar/Components/Sidebar Package Row.swift:44-47`).

## [03]-[SETTINGS_WINDOW]

- The macOS-shaped settings screen is a `TabView` of `Tab(_:systemImage:)` with `.tabViewStyle(.tabBarOnly)`, sized once with `.frame(width: 400, height: 350)`; each tab is a `Form { Section { … } header: { Text(...).foregroundStyle(.secondary) } }.formStyle(.grouped)` (PDFA `ArchiverLib/Sources/ArchiverFeatures/Settings/Settings.swift`, `SettingsMacView`).
- Every row inside that form is `LabeledContent { control } label: { Label(title, systemImage:) }`, with `Picker` narrowed by `.labelsHidden().pickerStyle(.menu)` and actions rendered as trailing `Button("Change…")` / `Button("Configure…")` (PDFA, same file, `generalPreferences`).
- Sub-screens are sheets, not new panes: `.sheet` over a `NavigationStack` with `.frame(minWidth: 500, minHeight: 400)` and a `ToolbarItem(placement: .confirmationAction) { Button("Done") }` (PDFA, same file).
- Apple's article uses the `Settings` scene wrapped in `#if os(macOS)` beside the main scene, and passes selection to menu commands with `.focusedSceneValue(...)` read by `@FocusedValue`, declared with `extension FocusedValues { @Entry var selectedItemID: UUID? }` (developer.apple.com/documentation/swiftui/building-and-customizing-the-menu-bar-with-swiftui).
- Where a settings window needs a sidebar it is `NavigationSplitView` with a `List(selection:)` over a `CaseIterable` identifier enum, `.navigationSplitViewColumnWidth(...)`, `.scrollDisabled(true)`, a removed sidebar toggle, and a `switch` on the identifier in the detail; Ice sizes the sidebar and its rows from `@Environment(\.sidebarRowSize)` (190/210/230 wide, 26/32/34 tall, 13/15/16pt) rather than one literal (ICE `Ice/Settings/SettingsView.swift`). Note Ice uses `Window(...)` with `.commandsRemoved()`, `.frame(minWidth: 825, minHeight: 500)` and `.defaultSize(width: 900, height: 625)` instead of the `Settings` scene (ICE `Ice/Settings/SettingsWindow.swift`).
- Ice's form primitives are worth copying rather than its window choice: `IceForm` takes `EdgeInsets` (default 20) and `spacing` (default 10) and promotes itself to a `ScrollView` only when measured content exceeds the container; `IceSection` is a `GroupBox` that interleaves `Divider()`s between children via `_VariadicView.Tree`; `IceLabeledContent` wraps `LabeledContent` giving the label `maxWidth: .infinity, alignment: .leading` and `layoutPriority(0)` against the control's `1`; a form-scoped `ToggleStyle` renders every `Toggle` as a trailing `.switch` at `.controlSize(.mini)` (ICE `Ice/UI/IceUI/IceForm.swift`, `IceSection.swift`, `IceLabeledContent.swift`).
- Add/remove affordances for a sidebar list sit under the list as a `ControlGroup` of two icon buttons, `Button("", systemImage: "plus")` and `"minus"`, constrained to `.frame(width: 50)`, with `.onDeleteCommand` on the `List` for the keyboard path; adding opens a `.fileImporter` with `.fileDialogDefaultDirectory` (MACCY `Maccy/Settings/IgnoreSettingsPane/IgnoreApplicationsSettingsView.swift`). Rows are `Label(title:icon:)` at `.frame(height: 32)`, and the explanatory text below is `.foregroundStyle(.gray).controlSize(.small).fixedSize(horizontal: false, vertical: true)`.
- Loop places the same affordance above the list as a labelled button row with `Button("Remove", role: .destructive)` (LOOP `Loop/Settings Window/Loop/ExcludedAppsConfiguration.swift:19-26`), which is the alternative when the buttons need words.
- One empty state, sized for its container: Cork defines `InlineContentUnavailableView` (horizontal, 30pt symbol) and `SmallerContentUnavailableView` (vertical, 40pt symbol), both `.foregroundStyle(.tertiary)` on the symbol and `.font(.headline).foregroundStyle(.secondary)` on the label, used instead of the full-size `ContentUnavailableView` inside panels and lists (CORK `Cork/Views/Shared/Inline Content Unavailable View.swift`, used in `Cork/Views/Installation/Sub-Views/Presenting Search Results.swift`).

## [04]-[CONCURRENCY]

- Cork is the strict-concurrency reference: `SWIFT_VERSION=6.0` with `SWIFT_STRICT_CONCURRENCY=complete` in a shared xcconfig (CORK `xcconfigs/Project.xcconfig:48-49`). Loop runs Swift 5 mode with the Xcode 26 easings: `SWIFT_APPROACHABLE_CONCURRENCY = YES` and `SWIFT_UPCOMING_FEATURE_MEMBER_IMPORT_VISIBILITY = YES` (LOOP `Loop.xcodeproj/project.pbxproj`).
- The root store is `@MainActor final class` owning lazily-built sub-managers, each handed the store — no manager reaches a global: `private(set) lazy var itemManager = MenuBarItemManager(appState: self)` and eight siblings (ICE `Ice/Main/AppState.swift`).
- Views read stores through the environment, not a singleton: `@Environment(AppState.self) private var appState`, `@Bindable var item: FooterItem` (MACCY `Maccy/Views/ListItemView.swift`, `Maccy/Views/FooterItemView.swift`). Apple's shape is `@State private var model = DataModel()` on the owning view with `@Observable final class DataModel` (developer.apple.com article above).
- Actors own the long-lived, non-UI machinery: `actor UpdateChecker`, `actor UpdateInstaller`, `actor BackupManager`, `actor WindowRecords` (LOOP `Loop/Updater/*`, `Loop/Window Management/Window Manipulation/WindowRecords.swift`), and Cork models a remote entity as `public final actor BrewTap: Identifiable, Hashable, ModifiableActor, LoadableActor` (CORK `Modules/Packages/PackagesModels/Models/Brew Tap.swift:25`).
- One stored `Task` per long-lived subscription, cancelled in `deinit` — not a `Task {}` at each call site: `private var observationTask: Task<(), Never>?` started in `init` over `for await launchAtLogin in Defaults.updates(.launchAtLogin, initial: false)` with `guard !Task.isCancelled, let self else { break }`, and `deinit { observationTask?.cancel() }` (LOOP `Loop/App/LaunchAtLoginManager.swift`).
- System notifications are consumed as an `AsyncSequence`, replacing observer tokens: `for await _ in DistributedNotificationCenter.default().notifications(named: .AXPermissionsChanged)` inside one stored task (LOOP `Loop/Utilities/AccessibilityManager.swift:24-38`).
- A multi-consumer `AsyncStream` is the publish surface of a `@MainActor final class`: continuations keyed by `UUID` in a dictionary, an optional initial value yielded on subscribe, `continuation.onTermination` hopping back to the main actor to remove the entry, and `deinit` finishing every continuation after clearing the dictionary (LOOP `Loop/Utilities/AccessibilityManager.swift:40-75`).
- Child-process streaming shape: build the `Process`, attach `Pipe`s, `try task.run()`, then return `AsyncStream { continuation in … }` where `readabilityHandler` yields typed output cases, `handler.readabilityHandler = nil` on empty data, and `task.terminationHandler` clears both handlers and calls `continuation.finish()` (CORK `Modules/TerminalSupport/Logic/Shell Commands.swift:178-320`). A second overload returns `(stream: AsyncStream<TerminalOutput>, process: Process)` so a caller can terminate the process (same file, :328).
- That code is missing `continuation.onTermination`, so cancelling the consuming task leaves the child running — the gap to close in our version: set `onTermination` to `task.terminate()` and clear the handlers there too.
- Timing uses `Duration` and `ContinuousClock`, never `Date` or a repeating `Timer`: `private static let restartWindow: Duration = .seconds(2)`, `private var restartTimestamps: [ContinuousClock.Instant]`, then `let windowStart = ContinuousClock.now - Self.restartWindow; restartTimestamps.removeAll { $0 < windowStart }` for a sliding rate limit (LOOP `Loop/Utilities/Event Monitoring/BaseEventTapMonitor.swift:16-95`). Sleeps are `try await Task.sleep(for: .milliseconds(250))` / `.seconds(0.15)` throughout Loop, Ice and Maccy.
- Typed throws are used where one function has one failure domain: `func loadDetails() async throws(BrewTap.TapInfoLoadingError) -> TapInfo`, with the private helpers it calls declaring the same error type so the chain needs no mapping (CORK `Modules/Packages/PackagesModels/Logic/Taps/Load Tap Details.swift:40,135,165`; also `Load Up Installed Packages.swift:88`, `Get Adoptable Packages.swift` ×4).
- Independent work runs in a task group whose element is a `Result`, so one failure never cancels the rest: `await withTaskGroup(of: Result<BrewPackage, BrewPackage.PackageLoadingError>.self)` collecting into `Set<Result<…>>` (CORK `Modules/Packages/PackagesModels/Logic/Package Loading/Load Up Installed Packages.swift:114-135`, `Logic/Taps/Load up Tapped Taps.swift:67`).
- `@MainActor` is applied to the type when the type is UI-owned (`@MainActor final class AccessibilityManager`, `LaunchAtLoginManager`, `AppState`), and to the single method when the type is not (`@MainActor func select(flags:)` on Maccy's `AppState`, MACCY `Maccy/Observables/AppState.swift:53`). Hops back to the main actor inside a closure are `Task { @MainActor in … }` (MACCY `Maccy/Observables/Popup.swift`, LOOP `AccessibilityManager.swift`).

## [05]-[RESULT_AND_ERRORS]

- Errors are enums with associated values, nested in the type that raises them, conforming to `LocalizedError, Hashable, Identifiable`: `public extension BrewPackage { enum PackageLoadingError: LocalizedError, Hashable, Identifiable { case triedToThreatFolderContainingPackagesAsPackage(packageType:) … case packageDoesNotHaveAnyVersionsInstalled(packageURL: URL) … } }` with `errorDescription` switching to localized keys (CORK `Modules/Packages/PackagesModels/Errors/Package Loading Error.swift`). A cancellation case is part of the enum (`case taskCancelled`, CORK `Logic/Taps/Load Tap Details.swift:34`), so callers match it instead of catching `CancellationError` separately.
- Nested errors compose by association, not by string: `case failedWhileTryingToDetermineIntentionalInstallation(folderURL: URL, associatedIntentionalDiscoveryError: IntentionalInstallationDiscoveryError)` (same file).
- OSStatus-style failures carry the raw code as a variant payload: `enum BitwardenKeyStorageError: Error { case failedToSaveKey(status: OSStatus), failedToRetrieveKey(status: OSStatus), failedToCleanKey(status: OSStatus), failedToEncodeKey, failedToDecodeKey }` (DDG `macOS/LocalPackages/BWIntegration/Sources/BWManagement/BWKeyStorage.swift`).
- Independent failures accumulate through `Result` rather than short-circuit: `blocks.map { Result(catching: $0) }`, then `results.compactMap { if case .failure(let e) = $0 { return e } ; return nil }`, then `throw MigrationError.combinedError(errors)` (ICE `Ice/Utilities/MigrationManager.swift:311-323`). The same idea appears as `typealias BrewPackages = Set<Result<BrewPackage, BrewPackage.PackageLoadingError>>` (CORK `Modules/Packages/PackagesModels/Models/Brew Package.swift:21`) and `typealias BrewTaps = Set<Result<BrewTap, TapLoadingError>>`.
- A `Result` arriving from a framework boundary is lifted with `.get()` inside one `do`, not unwrapped with a `switch`: `let url = try result.get()` in `.fileImporter`'s completion, with `defer { url.stopAccessingSecurityScopedResource() }` and one `catch` that sets presented error state (ICE `Ice/Settings/SettingsPanes/GeneralSettingsPane.swift:152-167`).
- Standard-library members these projects use where an app tends to hand-roll: `Result(catching:)` and `Result.get()` (above); `Optional.map` for derived display values — `selectionIndex.map { "\($0 + 1)" }` (MACCY `Maccy/Views/ListItemView.swift`); `zip` for paired teardown — `for (url, started) in zip(self, didStart) where started` (NOTCH `boringNotch/extensions/URL+SecurityScoped.swift:41`); `Dictionary(grouping:)` for de-duplication by key (CORK `Modules/Packages/PackagesModels/Logic/App Adoption/Get Adoptable Packages.swift:246`); `.formatted(.list(type: .and))` instead of `joined(separator:)`; `Date.FormatStyle` extended once as a named style rather than a `DateFormatter` per call site (CORK `Modules/Packages/PackagesModels/Models/Brew Package.swift:468`, `Cork/Extensions/DateStyle - AppStorage Support.swift`); `date.formatted(date: .abbreviated, time: .standard)` for display (ICE `Ice/Settings/SettingsPanes/AboutSettingsPane.swift:37`, LOOP `Loop/Updater/Views/UpdateView.swift:118`); `Duration`/`ContinuousClock` as in section 4. No project in this set uses `RelativeDateTimeFormatter`; `Date.RelativeFormatStyle` via `.formatted(.relative(presentation:))` is the current spelling.
- Where a completion handler is unavoidable, the payload is `Result`: `private var completionClosure: ((Result<URL, Error>) -> ())?` and `let finish: (Result<(), Error>) -> ()` (LOOP `Loop/Updater/UpdateDownloader.swift:19,79`, `UpdaterAuthorizationCoordinator.swift:129`).
- Anti-pattern present in the same corpus: error text smuggled through `String` payloads — `case couldNotReadContentsOfParentFolder(failureReason: String, folderURL: URL)` and `case failedWhileReadingContentsOfPackageFolder(folderURL: URL, reportedError: String)` (CORK `Errors/Package Loading Error.swift`), and `throw .couldNotUntap(tapName:failureReason: untapResult.standardErrors.formatted(.list(type: .and)))` (CORK `Logic/Taps/Remove Tap.swift:198`). Also a swallowed failure: `case .failure(let error): print("Failed to select application: \(error)")` (MACCY `Maccy/Settings/IgnoreSettingsPane/IgnoreApplicationsSettingsView.swift`).

## [06]-[KEYCHAIN_AND_LOGIN_ITEMS]

- The cause of repeated prompts, stated in code: login-keychain items are gated by an ACL that trusts only the exact code signature that wrote them, so after an upgrade the running binary's signature differs and the first read shows the "wants to use your confidential information" dialog; data-protection items are instead authorized by the app's `keychain-access-groups` entitlement, which is stable across any build the same team signs (ITERM `sources/Keychain/iTermUpgradeSafeKeychain.swift`, header comment).
- Therefore every query sets `kSecUseDataProtectionKeychain: true`. DuckDuckGo makes the choice a type: `enum KeychainType { case dataProtection(AccessGroup), case system }` whose `queryAttributes()` returns `[kSecUseDataProtectionKeychain: true]`, optionally plus `kSecAttrAccessGroup`, or `[kSecUseDataProtectionKeychain: false]` for the system keychain (DDG `SharedPackages/Common/Sources/Common/KeychainType.swift`).
- Pin the access group explicitly and read it from your own entitlement instead of hardcoding it: `SecTaskCreateFromSelf` + `SecTaskCopyValueForEntitlement(task, "keychain-access-groups")`, then `groups.first(where: { $0.hasSuffix(".com.googlecode.iterm2") }) ?? groups.first` — matched by suffix, not array position, cached in a `static let` because the signature cannot change while the process runs. The comment records that relying on the implicit default group made a migrated item read back as `errSecItemNotFound` on a later launch (ITERM, same file, `accessGroup` and `dataProtectionQuery`).
- `errSecMissingEntitlement` is the expected result on an unsigned or ad-hoc build; treat it as "data-protection unavailable, consult the login keychain", and treat any other hard status as an error rather than as absence — never fall through to the login keychain on a hard error, because that masks unreadable as missing (ITERM, `copyGenericPassword` / `planAfterDataProtectionRead`).
- Item shape for a secret an agent must read without UI: `kSecClass: kSecClassGenericPassword`, `kSecAttrSynchronizable: false`, `kSecAttrService`, `kSecAttrAccessible: kSecAttrAccessibleAfterFirstUnlock`, `kSecValueData`, `kSecUseDataProtectionKeychain: true`; reads add `kSecReturnData: true` and `kSecMatchLimit: kSecMatchLimitOne`; `errSecItemNotFound` maps to `nil`, any other status to a typed error (DDG `BWKeyStorage.swift`).
- Write as update-or-insert, never delete-then-add, so a transient failure cannot destroy the prior value; clear a secret with an explicit delete rather than writing empty `Data`, which does not round-trip reliably (ITERM, `setGenericPassword` / `deleteGenericPassword` comments).
- Migrating an existing login-keychain item: write the data-protection copy, read it back byte-for-byte, and only then delete the login copy — if either half fails, leave the login copy and still return its value, so the worst case is "keeps prompting" rather than "secret lost" (ITERM, MIGRATION SAFETY comment).
- Login items: all four menu bar apps depend on `sindresorhus/LaunchAtLogin-Modern` and render one `LaunchAtLogin.Toggle()` in settings rather than calling `SMAppService` from a view (ICE `Ice/Settings/SettingsPanes/GeneralSettingsPane.swift:88`, MACCY `Maccy/Settings/GeneralSettingsPane.swift:23`, NOTCH `boringNotch/components/Settings/SettingsView.swift:162`, CORK `Tuist/Package.swift:25`).
- Loop's hand-rolled equivalent is the shape to copy if we avoid the dependency: a `@MainActor final class` driven by `for await` over the setting, a `guard enabled != (SMAppService.mainApp.status == .enabled) else { return }` idempotence check, `try SMAppService.mainApp.register()` (synchronous throws) versus `try await SMAppService.mainApp.unregister()` (async throws), and a `start()` that reconciles at launch (LOOP `Loop/App/LaunchAtLoginManager.swift`).

## [07]-[MENU_BAR_ICON]

- Measured assets. Loop's `menubarIcon.imageset` is 16×16 @1x, 32×32 @2x, 48×48 @3x with `"template-rendering-intent": "template"` (LOOP `Loop/Assets.xcassets/menubarIcon.imageset/`, `Contents.json`). Maccy's `StatusBarMenuImage.imageset` is 16×16 @1x / 32×32 @2x, `idiom: "mac"`, with a second pair keyed `appearances: [{ appearance: "luminosity", value: "dark" }]` and the same template intent (MACCY `Maccy/Assets.xcassets/StatusBarMenuImage.imageset/Contents.json`); its alternate icons (`clipboard.fill`, `paperclip`, `scissors`) use the identical 16/32 pair.
- Ice ships its control-item art as a single 40×40 PNG declared at `scale: "2x"` with 1x and 3x slots empty, template intent set — i.e. a 20pt drawing at 2x, then resized at runtime (ICE `Ice/Assets.xcassets/ControlItemImages/IceCube/IceCubeStroke.imageset/Contents.json`, and `Dot*`, `Ellipsis*`).
- The runtime fit box is 25×17 points: `let ratio = max(originalWidth / 25, originalHeight / 17); let newSize = CGSize(width: originalWidth / ratio, height: originalHeight / ratio)` applied both when decoding a catalog image and when a user supplies a custom icon (ICE `Ice/MenuBar/ControlItem/ControlItemImage.swift:32-40`, `Ice/MenuBar/ControlItem/ControlItem.swift:353-363`).
- Stroke weight for code-drawn glyphs, measured from Ice's chevrons: `lineWidth: 2` at 12×12 for the large chevron and `lineWidth: 2` at 9×9 for the small one, `image.isTemplate = true` (ICE `Ice/MenuBar/ControlItem/ControlItemImage.swift:66-90`) — roughly a 1:6 to 1:4.5 stroke-to-box ratio, matching Apple's status glyph weight.
- `isTemplate` is the mechanism, not a color choice: set unconditionally for SF Symbols (`NSImage(systemSymbolName:accessibilityDescription:)` then `isTemplate = true`) and made a user setting for imported artwork (`image?.isTemplate = generalSettingsManager.customIceIconIsTemplate`, surfaced as a "Apply system theme to icon" toggle) (ICE `ControlItemImage.swift:28-45`, `GeneralSettingsPane.swift:169`).
- In a SwiftUI scene the label is `MenuBarExtra(Bundle.main.appName, image: "menubarIcon", isInserted:)` for catalog art (LOOP `Loop/App/LoopApp.swift:18`) or `systemImage:` for a symbol (MCCUI `Demo/Demo/DemoApp.swift`, NOTCH `boringNotchApp.swift:32`); `isInserted:` is a bound setting so the user can hide the icon, and Apple documents that the binding flips to `false` if the user drags the item out (developer.apple.com/documentation/swiftui/menubarextra).
- `.symbolRenderingMode` does not appear on any status item in this corpus — it is used only for in-panel symbols, paired with `.symbolVariant(.fill)` and `.imageScale(.large)` (NOTCH `boringNotch/components/Shelf/Views/ShelfView.swift:85-88`). Menu bar templates are monochrome by definition, so the renderer choice is `isTemplate`, not the symbol mode.
- Retina handling is the asset catalog's job (16/32/48 at 1x/2x/3x above) plus one resize against the measured menu bar height; nothing draws into an `NSImage` at a scale it computed itself except Ice's chevrons, which use `NSImage(size:flipped:)` so AppKit supplies the backing scale (ICE `ControlItemImage.swift:69`).

## [08]-[SMELLS]

- No `NSViewRepresentable` for layout. Measurement is `onGeometryChange(for:)` (MACCY `Maccy/Views/HeightReaderModifier.swift`) or one `.onFrameChange` modifier (ICE `Ice/UI/IceBar/IceBar.swift`); `NSViewRepresentable` appears only for what AppKit alone provides, `NSVisualEffectView` (MCCUI `Utilities/VisualEffect.swift`, MACCY `Maccy/Views/VisualEffectView.swift`).
- No `GeometryReader` wrapping a whole panel to compute sizes: MCCUI caps height from `NSScreen.visibleFrame` and lets `min(maxHeight, contentHeight)` do the rest; Ice's `IceForm` uses the measured height only to decide whether a `ScrollView` is needed.
- No fixed pixel fonts for body text. The corpus counterexamples are Ice (`.font(.system(size: 36))`, `size: 18`, `size: 72`, `size: 14` across `PermissionsView`, `AboutSettingsPane`, `MenuBarSearchPanel`) and boring.notch (`size: 60`, `size: 22`, `size: geometry.size.width/3.5`); the pattern to follow is Maccy's, which sets almost no font and uses `.caption`/`.body` where a role differs, and MCCUI's single documented exception of 13pt for headers that must match NSMenu.
- No `switch` ladder where a transform suffices: `selectionIndex.map { "\($0 + 1)" }` over a five-line `if let` (MACCY `ListItemView.swift`), `results.compactMap { if case .failure(let e) = $0 … }` over an accumulating loop (ICE `MigrationManager.swift:316`), `Dictionary(grouping:)` over nested loops (CORK `Get Adoptable Packages.swift:246`). Cork's own `SelectionAppearance.rect(cornerRadius:)` style — a small enum with one computed shape — is what replaces a ladder at the call site (MACCY `Maccy/Views/ListItemView.swift:4-29`).
- No string-typed errors. Present as a defect in Cork (`failureReason: String`, `reportedError: String`) and worth a rule: a variant payload is a value the consumer can match, a rendered message is not.
- No parsing of a child process's stderr by prefix to classify severity: `if line.hasPrefix("Warning:") || line.hasPrefix("Error:") || line.hasPrefix("==>")` building a mutable `currentSectionInErrorBlob` (CORK `Modules/TerminalSupport/Logic/Shell Commands.swift:110-140`). Classify from exit status and a structured output format instead.
- No `print` on a failure path, and no `return []` on a failed `task.run()` (CORK, same file, :88 and :94) — an unlaunchable process is a typed error, not an empty result.
- No `AsyncStream` without `onTermination`: cancelling the consumer must terminate the child process (gap in CORK `Shell Commands.swift`, done correctly for a different resource in LOOP `AccessibilityManager.swift:70`).
- No singleton reached sideways from a model: `AppState.shared.navigator.select(...)` and `AppState.shared.popup.needsResize = true` inside `History.searchQuery.didSet` (MACCY `Maccy/Observables/History.swift:22-35`) versus Ice's constructor injection (`MenuBarItemManager(appState: self)`).
- No `class X: Sendable` asserting what the compiler cannot check: `@Observable class AppState: Sendable` with mutable stored properties compiles only in Swift 5 mode (MACCY `Maccy/Observables/AppState.swift:8`). Under Swift 6 the honest spelling is `@MainActor @Observable final class`.
- No `DispatchQueue.main.async` inside SwiftUI code where a main-actor hop is meant: present in MACCY `Maccy/Observables/Popup.swift:176` and NOTCH `boringNotchApp.swift:34`; the corpus's correct form is `Task { @MainActor in … }`.
- No animation applied imperatively where a value keys it: prefer `.animation(_:value:)` and `$binding.animation(_:)` (MACCY `ContentView.swift`, MCCUI `HighlightingMenuDisclosureGroup.swift:99`) over a bare `withAnimation` around a state write.
