# Keychain prompts

Agent task: Relay Keychain access prompt defect, root cause and fix, 2026-09-13

**Root cause (two compounding causes, both evidenced)**

1. Ad-hoc signature. `codesign -dr -` on the existing build: `designated => cdhash H"15ad885f…"`; my fresh build: `cdhash H"b77b1d98…"`. `security dump-keychain -a` shows the `Claude Code-credentials` item trusts Relay only as `requirement: cdhash H"15ad885f…"` with partition list `apple-tool:, cdhash:15ad885f…`, which is what one "Always Allow" wrote, and every rebuild is a different app to it. The private item `Claude Code-credentials-47f2cc90` trusts only `/usr/bin/security` (Claude Code created it: the binary at `~/.local/share/claude/versions/2.1.270` writes with `security add-generic-password -U -a … -s … -X …`, no `-T`). Both items carry partition ID `apple-tool:`, which is why the dialog demands the login password rather than a click. `security find-identity -v -p codesigning`: 0 identities, no Apple Development certificate, no team in Xcode.
2. Read count. One `freshUsage` performs three `SecItemCopyMatching` data reads: `observeSelection` (default store), `owner.read()`, `credentials(in:)`. `RelayStore.refresh()` runs on every panel open, wake, and every 60 s while the panel is visible, for every connected account; `reconcileSelections` adds one more at launch and after sign-in. With two accounts (one default, one private) that is 6 prompts per refresh on an untrusted build, matching "10+" after one sign-in plus a panel open.
