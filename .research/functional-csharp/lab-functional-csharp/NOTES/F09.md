## Corrections and findings

- `Fin<A>` has no `Filter` or `Where` (decompile of `Fin<A>` and `FinExtensions`). The `T -> bool` step on `Fin` is `guard` inside a LINQ query through `Fin<A>.SelectMany(Func<A, Guard<Error, Unit>>)`. The plan's "`Filter` on `Option` and `Fin`" holds only for `Option`.
- `Seq<A>.Average(Func<A, B>)` is ambiguous (CS0121) between `FoldableExtensions.Average<T, A, B>(K<T, A>, Func<A, B>)` and `System.Linq.Enumerable.Average<TSource>(IEnumerable<TSource>, Func<TSource, decimal>)`. `FoldableExtensions.AverageT` has the identical body (`T.Average(f, ta)`) and no Linq twin, so `AverageT` is the name the library keeps free of that clash (not compiled here). The doc keeps one path: `Average` from `System.Linq` on an `IEnumerable<Person>` receiver.
- `Seq<A>` has no `OrderByDescending` or `Sort(Func)` of its own (`Prelude.Sort<OrdA, A>` needs an `Ord` trait type). Ordering uses `System.Linq.OrderByDescending` and `toSeq` when a `Seq` result is required.
- Analyzers IDE0120 and RCS1077 reject `.Select(p => p.Earnings).Average()` and require `.Average(p => p.Earnings)`, so the data-flow sample has three stages instead of the book's four.
- IDE0040 requires `public` on interface members.
- `OptionT<M, A>.Match<B>(Func<A, B> Some, Func<B> None)` returns `K<M, B>`; a `None` branch that must fail the effect cannot return `IO<A>` without nesting, so the boundary conversion uses `Run().As().Bind(option => IO.lift(option.ToFin(error)))`. No `IO<Option<A>>` local appears in the doc or in the lab.
