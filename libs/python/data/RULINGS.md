# [PY_DATA_RULINGS]

`python/data` rulings settle package-scoped decisions.

## [01]-[PACKAGES]

- `arro3-*` admits as the slim-carrier fast path with its split predicate named — a leg needing only IPC or compute kernels on an already-Arrow operand rides arro3, and any acero, dataset, or flight surface keeps `pyarrow` the owner; `arro3-io` owns the folder's transport-band IPC codec (`tabular/interop#CARRIER` `wire_bytes`), and the lakehouse CDF re-import is REFUTED for arro3 substitution because the partition split needs `sort_by` and `isin`, neither of which `arro3.compute` spells; re-opens only if arro3 grows an engine surface or the missing kernels.
- The GeoArrow family splits from GDAL on format coverage — a format the `geoarrow-rust-io` readers spell natively (`FlatGeobuf`, `GeoParquet`, `GeoJSON`, `GeoJSON`-lines, `CSV`, `PostGIS`) rides the native band and its writer arm, and pyogrio keeps the OGR long tail; SHAPEFILE is refuted native — the rust surface publishes no shapefile reader or writer — so it stays a GDAL row permanently. In-frame kernels split on vectorized availability: a verb GEOS spells vectorized stays a shapely arm, and only the ellipsoidal metric family the rust surface alone vectorizes rides the geoarrow export leg; re-opens on a rust surface release adding a format or on GEOS gaining vectorized ellipsoidal metrics.

## [02]-[SHAPE]

Discriminant: the fold depends on `pyarrow` alone, so the tier-0 page holds it and `columnar` becomes the scan base above that floor rather than its peer; re-opens only if the folder admits a keyer that cannot import `interop`.
- Manifest rows whose interpreter marker no supported floor satisfies stay ADMITTED and become UNREACHABLE, so each owning page carries an import-time `find_spec` row per provider and refuses every selection naming an unresolved module with `BoundaryFault(import_=)` carrying it — admission records intent, the gate records the floor, neither deletes the other. Ungated lazy imports defer the failure into an offloaded thread, where the rail reports a provider crash instead of a provisioning fact.
- Floor gates bind every surface naming the gated coordinate, never the dispatch arm alone — an instrumentation roster, a seam declaration, or an option constant dereferenced off a gated distribution each crash on the import that gate forecloses, so every such surface derives from the gated row set and reads the same floor.
- Residence names the engine PREFERENCE and reach decides it where the caller named none — the verbatim-selection law binds a selection a caller actually made, so a NAMED provider below the interpreter floor still refuses by module while an unnamed residence lands on whichever engine this floor resolves. Deriving the engine from residence alone tied a whole residence class to one distribution, so a manifest marker on that distribution refused every ref of that class while a reachable second engine addressing the same residence sat unmined; the wrong move is reading this carve as licence to swap a named provider.
- Every provider surface a residence class can address is reached by every engine that class admits — an engine hardcoding one residence's handle makes a sibling engine the sole arm for the others, so a floor marker on the sibling takes the whole class down; the store handle is the residence's, never the engine's.
- Caller-selected providers ride through verbatim: reach refuses the cells that provider cannot serve and dispatch honours the selection, so no arm swaps an accelerator in behind the caller. Implicit swaps hide substitution and the substitute's own reach from the receipt, answer a request nobody made — worse across residence classes — and degrade silently, an unpartitioned serial pull for a partitioned request where a typed refusal names the missing operand.
- A provider carrying its OWN store client takes the branch envelope as one pre-constructed config VALUE, never a branch-local mirror of the provider's settings types — the runtime `store_handle` fold reaches an `obstore` handle alone, so a Rust-core or native store beside it (an icechunk `Repository`, a tensorstore kvstore) otherwise runs provider retry, timeout, and cache defaults no page states while a sibling leg against the same bucket carries the pinned ones; the axes the branch decides derive from the branch constants and every other axis keeps the provider default rather than a re-asserted number.
- Transport-band transforms — IPC compression, a federated plan re-serialize, re-framing — never reach the identity fold: a codec is a transport or egress parameter and a gate hands original bytes onward untouched, so wire volume drops while every content key and foreign-plan validation stays unchanged.
- Versioned and transactional store owners emit only the snapshot-identity `ContentKey` as the durable receipt — the version-control engine (branch-merge policy, retention orchestration, table-protocol governance, the reuse ledger) is the C# `Rasm.Persistence` at-rest owner's, `lakehouse` and `virtual` each declining their half; a data-side owner holding any of that state is the rejected move, routed to Persistence; re-opens only on a version decision no Persistence wire carries.
- Store span-kind law: outbound store and network I/O legs open spans `kind=SpanKind.CLIENT`, local-path legs stay `INTERNAL`, and sibling I/O legs carry one span each — folded multi-leg spans and INTERNAL outbound legs drop the client-boundary evidence a distributed trace joins on.
- Capability bounds answer as reach-matrix rows read ahead of every provider call, hook fire, and retry envelope — never as the provider's own exception lifted onto the rail, which reaches a caller indistinguishable from a transport failure and carries no reason a matrix row states as data. Matrix keys are the owner's own closed axes, so cells grow with the axes rather than with the arms, and each row's member value IS the operator-facing evidence.
- Receipts name WHAT they measured beside the number: one slot carrying rows on one arm and files on another strands every consumer folding the family, so a per-arm measure rides a `(quantity, unit)` pair over a closed vocabulary while provider-reported file, byte, and snapshot evidence keeps its own typed slot.
- Every receipt contributor spells `domain`, `kind`, and `key` into its facts as the SAME pair it hands `Metrics.record` beside the identity it minted — those three are the durable evidence residence's lifted columns and `domain` is its partition column, so a contributor omitting them writes every row it ever produces into one nameless partition no predicate prunes and strands its durable evidence from the live series it mirrors.
- Non-transactional planes enter the transactional owner as a FORMAT row whose unreached cells are refusal rows, never a writer hanging off the residence family — a second commit path drifts from the reach gate, the commit veto, the retry envelope, the span, and the receipt the moment any one of them changes, and a derived degradation stops deriving the instant a row states its losses by hand.
- Evidence-plane writes take an owner's receipt-free write half, which answers the file and byte evidence it landed — minting a scan-plane receipt for an evidence commit enters the receipt stream as a foreign-domain row and prices a residence's own storage against the plane that merely wrote it, so the two halves stay split and a caller's query keeps the receipt.
- Commit receipts report the operation's OWN churn off the provider's commit log, never a snapshot roster read as that operation's evidence — a current-file listing counts every file the table holds, so one append prices the whole plane, the metric spine reads size as a commit rate, and an additive ledger re-prices the residence per write; state facts ride the op whose whole job is state, and the ledger's operation-keyed slot keeps a stock row and a flow row from summing.
- Every column a residence partitions or clusters on is TOTAL by construction, filled from the producer's own identity where a receipt case carries no such fact — a partition value is a filesystem path segment, so an empty one writes a directory no predicate names and no compaction reaches, and the cases carrying no producer fact are exactly the fault and drain evidence an incident reconstruction reads.
- Clustering and retention are a residence's MAINTENANCE phase on the composing deploy plane's own cadence, never ops folded into ingest — a clustering pass carries no partition scope unless one is passed, so an ingest-folded pass rewrites every file the plane holds on every drain, and the phase axis is what keeps one row set answering both plans while a format refusing a pass derives an empty one.
- Residence commits prove the SUBJECT they write into, never only its format — the dataset kind rides the opened handle and the residence row names it, because an evidence stream admitted on format alone lands inside whichever caller table happens to share that format.
- Durable-plane reconstruction folds COLUMN-WISE at the provider, never row-wise into the host language — analytics residences carry no cardinality ceiling by law, so decoding one row-wise allocates an object per evidence row to produce a handful of aggregate slots, which is the exact cost the residence exists to avoid; one projection serves both the row-wise and vectorized readers so their numeric admission and axis mapping cannot drift.

- Layout crosses as ONE transform vocabulary each arm projects onto its provider's grammar; a per-format spec object forks that declaration the moment a second residence arms, and a transform a format cannot spell refuses by name rather than vanishing from the planted table.
- Every engine's profile harvest carries its PROVIDER's raw payload into one decoder and widens the shared band for none of them — a case re-stating a fact its own payload answers strands two copies, and an engine measuring no cpu, blocked, or IO fact reports zeros it can prove, since aliasing wall latency onto them invents evidence a cost fold then prices.
- Profile bands grow only where every engine answers the new fact or honestly reports zero; per-engine profile fields are the rejected form.
- Consumers needing the rows an owner's operation moves compose that owner and read its receipt payload — re-opening the provider behind the owner forks a second reader of one surface, strands every format the owner arms and the consumer never re-derives, and drifts the moment the owner's own read changes. - `ResidenceRow` answers the estate residence floor `libs/.planning/RULINGS.md` fixes and extends it with the columns only a WRITE plane decides, so this folder owns the extension and never a peer's shape — a deploy plane decides charts and doors, a read plane decides relations and accessors, and obliging either to carry a write plane's layout roster demands coordinates its own plane has no decision behind.
