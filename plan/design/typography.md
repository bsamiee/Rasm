# [TYPOGRAPHY]

The typographic system: the grid mathematics, the font metrics that feed it, the five family roles, the style graph, the page patterns, the page-size catalogue, and the build procedures that write them into InDesign. `libs/typescript/typography` holds the pure mathematics, the preset parser, the font-metric reads, and the catalogue rows. `apps/creative-cloud/server/indesign/` holds the data files and the tool bodies that apply them.

Every measurement resolves through the module `L` of the file being built. The value grammar is `"<n>L"`, `"M"` (the measure, the type-area width), `"rule"` (`L/30`), `"hairline"` (`L/60`), `ladder=<step> L`, and plain unit strings for values no module governs (`"3pt"` form-field insets, `"0.001pt"` tolerances). Stroke weights floor at 0.25 pt, the preflight `min_width`. Sizes are steps of one ladder, size = 0.85 × leading, written as the step: `ladder=1 L` means leading 1 L and size 0.85 L.

## [01]-[GRID]

Grid Calculator Publishing Edition 1.4 is a native InDesign SDK plug-in pair (`GridCalculator.InDesignPlugin`, `GridCalculatorUI.InDesignPlugin`, `com.DesignersBookshop.*`, universal arm64 and x86_64, signed `Developer ID Application: Abraham Georges (5ZCTQ6T4SQ)`). It drives InDesign in process, carries no scripting bridge, and writes native settings alone, so its documents open without it. The computation below was recovered from the arm64 slice of the UI plug-in with Ghidra headless over a locally built macOS decompiler. The build is unoptimised, so InDesign `PMReal` operators are calls: `operator/` 0x157c8, `operator*` 0x15a7c, `operator-` 0x28080, `operator+` 0x17c4c, `Round` 0x15abc, `floor` 0x37d70, comparisons at 0x14140 and 0x15808, decimal quantise 0x152f0. Rules the modes obey. Quick mode breaks the document grid: it allows custom margins in Value mode, a type-area grid inside the margins, custom columns and rows with numeric width and gutter, and it is the only mode that supports Alternate Layout masters. Vertical Value mode exists on master `GC-1` alone, because one document holds one baseline grid and every later master moves its vertical margins in whole leadings. Horizontal Value mode is available on every master and disables the columns dropdown, so columns come from Custom Setup. Modular and Smart mode are tied to the document grid, share their state, and refuse Value mode and type-area grids; Modular sets the grid width and height through Calculate and sets margins freely in grid lines; Smart takes column and row counts and leaves the remainder as margins. Switching between the Quick family and the Modular family resets the layout. Columns divide the type area, subcolumns split main columns, secondary columns are a second layout on guides, and rows carry the same three levels. Lock keeps the column and row settings while one margin edit moves the type area. Image-lines are guides at the x-height, H-height, or a custom height above each baseline, and are placed on their own layer. Indents, exdents, and tabs are based on the em, the horizontal grid width, or a custom value. Units are millimetres, inches, and points and pixels; leading always displays in points and its field accepts a unit suffix.

No formula stays unknown. The seven experiments of `plan/research/grid-calculator/README.md` [08] remain as readback checks: run in the installed panel on a scratch document, each reads the document back through the DOM and confirms the recovered row it names, and the readbacks become the oracle fixtures of [11].

The vendor's web Layout Wizard computes its horizontal unit by a different algorithm from the plug-in and is not an oracle for `u_h`: it takes the greatest common divisor of width, inside, outside, and gutter at the entered precision. Its inch path multiplies inch values as millimetres and is broken. Its vertical unit does come from the leading fit and does agree with the plug-in.

## [02]-[COVERAGE]

Grid Calculator is the functional reference for the grid layer. Every function it offers has a carrier here, and the overlapping ones collapse into fewer contracts with one input shape: `apply_grid` takes either a preset text or the same fields as named inputs and covers all three setup modes, `build_template` and `build_size_catalog` call the same `apply_grid` body, and the `typography` library holds the mathematics once for every caller. The result is a superset with a smaller surface.

## [03]-[PRESETS]

The preset grammar was recovered from the UI plug-in's string table at 0x221c83–0x222860 and checked against three preset files the vendor's wizard produced. A preset is `Key: value;` one per line, newline separated, `Type:` first, then a global block, then one `[GC-n]` block per master, then two guard lines: `/*********** DO NOT REMOVE OR CHANGE THIS SEPARATOR ***********/` and `/*WARNING: Please do not change the format of this file, otherwise it can cause the application to malfunction*/`. The grammar is one codec, `Preset: Schema.Codec<Preset, string>`: the text splits into lines (`SchemaGetter.split`), each line decodes through a `Schema.Union` of `Schema.TemplateLiteralParser` members (a global entry over `GLOBAL_KEYS`, a master entry over `MASTER_KEYS`, the `[GC-n]` header, the two guards, a blank), and a fold groups the lines into `{global, masters}`; encoding runs the same codec backwards, so a text preset and a named input reach the same code and a decode failure is a `SchemaIssue` whose `Pointer` names the line. `Level`, `Measure`, `Custom`, and `TypeareaGrid` are the value codecs of the structured keys. `grid-presets.json` holds the named presets as JSON in the same key vocabulary with the parsed equivalent beside each, and a round trip through parse and render reproduces the text byte for byte apart from `Date`.

Worked reading of the A4 wizard preset: `H. Module 2: 42` is the module count across the width, `H. Module 3: 5` the module size in millimetres, `H. Subdiv 2: 1` the subdivisions per module, `H. Subdiv 3: 5` the subdivision size; the vertical four are the same, where the subdivision size equals the leading, `4.243 mm = 12.027 pt`. Margins, column widths, and gutters are integers in subdivision units, which the vendor calls lines.

Neither Liquid Layout nor Adjust Layout produces a catalogue row. A Liquid rule is one per page; Scale opens gaps on an aspect change, Re-center drops content, and Guide-based reflows without scaling. Adjust Layout moves ruler guides proportionally and scales type as overrides alone. Neither re-fits a baseline grid. Every row is rebuilt from its own geometry through the `apply_grid` body.

Page sizes are derived, not stored. `standardSheet(standard)` in `page-sizes.ts` computes a portrait sheet in its standard's unit from the standards' rules. ISO 216:2007 clause 4.1 states the halving principle, each size the size above it divided into two equal parts parallel to the shorter side, clause 4.3 the basis of the A series, A0 an area of 1 m² at the √2 ratio, so A0 is `round(1000 · 2^(−1/4)) × round(1000 · 2^(1/4)) = 841 × 1189` mm, and clause 4.4 places the B series at the geometric means between adjacent A sizes, so B0 is the rounded geometric mean of A0 and 2A0, `1000 × 1414`; ISO 269 places the C series at the geometric mean of the A and B sizes of the same number, `917 × 1297`. Every smaller size is `(floor(h / 2), w)`: the standard's tables were computed by halving the size above and rounding down to the whole millimetre (Markus Kuhn, "International standard paper sizes", cl.cam.ac.uk/~mgk25/iso-paper.html, under "Calculating the dimensions"), and that rule reproduces A0 to A10, B0 to B10, and C0 to C10 as the standards print them. ASME Y14.1 builds the engineering series on Letter, `8.5 × 11` in, each size the previous rotated with its short side doubled, `(h, 2w)`, through E `34 × 44`, with F `28 × 40` its own row, and the architectural series by the same doubling from A `9 × 12` through E `36 × 48`, with E1 `30 × 42`, E2 `26 × 38`, and E3 `27 × 39` their own rows. Legal `8.5 × 14`, Half Letter `5.5 × 8.5`, the `48 × 24` board, the digital master `3840 × 2160`, and the twenty-three screen formats InDesign ships are literal rows. Millimetres and inches convert at InDesign's own `72 / 25.4` and `72`.

`pageSizes(fTop)` returns the 59 rows as `PageSize`: a `Sheet` (`name`, `family`, `intent`, `width`, `height`, `unit`, `module`) with the grid its family's rule computes (`margins`, `columns`, `rows`, `firstBaseline`, `lastBaseline`, `folio`, `footer`, the technical `sheet` member holding the four border values, the drawing area in modules, and the title-strip width, `parents`, `swatchColumn`). A row's name is its label and the sheet's dimensions in its own unit, `A4 210x297`, `ANSI C 22x17`, `Web 600x300`. The module ladder per size class is one table by ISO index, shared by the A and B series (36, 11.5, 11.5, 12, 15, 8.5, 7.5 with their row counts and row gutters), and the US, board, and digital rows carry their module, row count, and row gutter beside their sheet; technical sheets carry `columns.count` 0, `rows.count` 0, and `folio` absent. The three rules are the document rule, the technical-sheet rule, and the screen rule above, matched exhaustively on `family`, so the catalogue closure of [11] is the derivation itself: the standards' dimensions against `data/page-sizes.csv` and 59 distinct names.

`fTop` is the f-height: the top of the ascender of lowercase f, the tallest point of a normal lowercase line. It is the measure the reference documents use for their type-area top, and it is read per face. For Neue Haas Grotesk Text Pro 55 it reads 0.749 with `capHeight` 744 per 1000 units, which gives `f = 0.749 × 12.75 = 9.54975`, written 9.550 at InDesign's 0.001 pt precision, inside the 0.001 pt closure tolerance. ## [07]-[STYLES]

Rules the graph obeys. Every measurement is written in `L` and resolved to a unit string per file, so `"1L"` becomes `"15pt"` on Letter and `"45px"` on the digital master. Sizes are ladder steps. Every text style sets `alignToBaseline true`; a leading that is not a whole module also sets `gridAlignFirstLineOnly true`, so the first line snaps and the block runs on its own leading, while whole-module leadings snap every line. Space before and after are whole modules alone. Indents, insets, offsets, and tab positions are in `L`. The measure `M` is the type-area width of the file. `styles-graph.json` carries the value grammar in its `units` key, so a consumer needs no second table. One root `Base` sits on `[No Paragraph Style]`, the depth is at most three tiers, and nothing is based on `[Basic Paragraph]`. Character styles are single-attribute on `[None]`, every other attribute `NothingEnum.NOTHING`. Font families are `families.json` keys, never literal names. Latin styles keep `Adobe Paragraph Composer`; Persian and Arabic styles take `Adobe World-Ready Paragraph Composer`, whose key string is `$ID/HL Composer Optyca` and which resolves at run time through `find_key_strings`. Heading ratios are data: H1 = 2 L, H2 = 1.5 L, Heading = 1 L, Title = 3 L, Display = 4 L.

Digits. Arabic roles take `HINDI_DIGITS` (٠١٢٣), Adobe's Arabic default, because `DigitsTypeOptions.ARABIC_DIGITS` means Western 0–9. Persian roles take `FARSI_DIGITS` (۰۱۲۳, U+06F0–06F9).
