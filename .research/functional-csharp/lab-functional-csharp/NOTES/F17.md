# F17 notes: Indefinite Loops

Lab `.scratch/lab-f17` (namespace `Lab.F17`), copied to `.scratch/lab-functional-csharp/F17`. Build: zero diagnostics. Run: exit 0. Doc: `.scratch/functional-csharp/17-indefinite-loops.md`, every `csharp` block is the lab class text (diffed line for line).

## Members verified (compiled and executed)

- `Trampoline.Pure(A)`, `Trampoline.More(Func<Trampoline<A>>)`, `Trampoline<A>.Run()` at depth 100000 (`RunUntil` counting to the limit and `FirstPositionAtZero` over 100000 deltas).
- `Trampoline<A>.Bind(Func<A, Trampoline<B>>)` chained after a depth-100000 trampoline, then `Run()`.
- `Seq<A>.At(int)` (the `FoldableExtensions.At(Index)` form, `int` converts to `Index`) returning `Option<A>`, `Option<A>.Match(Some:, None:)` where both arms return `Trampoline<Option<int>>`; the `None` arm is `Trampoline.Pure(Option<int>.None)` because `Trampoline.Pure(None)` infers `Trampoline<OptionNone>`.
- `Monad.recur<IO, S, S>(seed, s => ... ? IO.pure(Next.Done<S, S>(s)) : io.Map(x => Next.Loop<S, S>(next)))` then `.As()` returning `IO<S>`, `RunSafe()` returning `Fin<S>` at depth 100000; an already-finished seed returns unchanged after zero transitions (an `Atom` counted the effect runs: 100000 and 0).
- `IO<A>.Bind(a => tail(Recurse(...)))` after `IO.lift(...)` at depth 100000, exited through `Try.lift(io.Run).Run()` returning `Pure(0)`.
- `IO<A>.RepeatUntil(Schedule, Func<A, bool>)` with `Schedule.spaced(TimeSpan.FromMilliseconds(1))`: the effect ran until the predicate held (`Atom` from 3 to 0, result `Pure(0)`). The decompile shows `RepeatUntil(Schedule, pred)` iterates `schedule.PrependZero.Run()` and returns the last value when a finite schedule is exhausted; `spaced` is unbounded, so the predicate alone ends the loop.
- `LanguageExt.List.unfold<S, A>(S, Func<S, Option<(A, S)>>)` under `toSeq`: the decompile calls the unfolder first and yields `Item1`, so the initial state is not emitted and `None` on the first call yields an empty sequence (`IsEmpty` checked). The one-argument `unfold<S>(S, Func<S, Option<S>>)` yields the initial state before calling the unfolder, which is why the doc uses the tuple form.
- `Seq<A>.Last` and `Seq<A>.Head` are properties of type `Option<A>` (`states.Last`, not `Last()`); `Seq<A>.Map(Func<A, B>)`; `Seq<A>.Fold(S, Func<S, A, S>)` with a named-tuple accumulator `(Messages: Seq<string>(), State: initial)`; `Seq<A>.Add`; `Seq<string>()` as the empty form.
- `toSeq(IEnumerable)` is lazy and memoizes: `Last`, `Map`, and `Fold` over one `Seq` ran `advance` 3 times for 3 states; a second `toSeq(unfold(...))` then `Head` ran it once more (4). `Head` on the second sequence pulled one state only.
- `==` between `Fin<Session>` and `Pure(new Session(...))` and between `Option<Session>` and `Some(new Session(...))` for a positional record.

## Corrections with evidence

- The plan's `Monad.recur` shape spelled the transition as `IO.pure(Next.Loop(next))`. The doc's transition is an `IO<int>` argument mapped into `Next.Loop` so the loop is effectful, which is the section's point; `IO.pure` remains on the `Done` arm.
- The plan's row said "repeated enumeration of an unfold reruns the transition". The run shows that one `Seq` built by `toSeq` does not rerun `advance` on a second pass; a second `toSeq(LanguageExt.List.unfold(...))` does. The doc states both.
- `Trampoline.Pure(None)` does not compile into `Trampoline<Option<int>>` (`OptionNone` inference); `Trampoline.Pure(Option<int>.None)` does.
- A `bool` positional record argument is named at the call site (`new Session(5, HasExited: true)`, MA0003) in lab code; the doc blocks pass computed `bool` expressions and need no name.
- `Match(Some: ..., None: ...)` on `Option<int>` compiles with the `Some` lambda capturing `deltas` and the `None` lambda `static`.
