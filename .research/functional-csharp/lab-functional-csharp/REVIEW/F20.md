1. **Location** line 18.
   **Claim** "`commute` applies a commutative update against the live value."
   **Evidence** `ilspycmd -t 'LanguageExt.STM'`: `Transaction.Commute` does
   `RefState refState = state[id].Map(f); state = state.SetItem(id, refState); commutes.Add((id, f));
   return refState.UntypedValue;` — it reads the *in-transaction* value, not the live one, and returns
   that. The library doc comment on `STM.Commute` says "At the commit point of the transaction, `f` is
   run *AGAIN* with the most recently committed value". `CommitCommutes` applies `commute.Fun` to the
   global latest state. `commute` never reads the live value at the call site.
   **Correction** replace the clause with: "and `commute` applies its function inside the transaction
   and applies it again at the commit point against the last committed value."

2. **Location** line 18 and the `Transfers.Move` block, read together with `.scratch/lab-functional-csharp/NOTES/F20.md` line 21.
   **Claim** (notes) "`commute` returns the committed value at the end of the transaction, not a stale in-transaction value".
   **Evidence** `atomic(Func<R>, Isolation)` routes to `RunTransaction<R>(Func<R> op, …)`, which calls
   `ValidateAndCommit(transaction, isolation, op(), long.MinValue)`. `CommitCommutes` only overwrites
   `result` when `returnRefId == commute.Id`, and `returnRefId` is `long.MinValue` here, so the value
   returned by `atomic` is whatever `commute` returned in-transaction. Only the
   `atomic(Func<CommuteRef<R>>)` overload passes a real `returnRefId`. The lab probe is uncontended, so
   in-transaction and committed values coincide and the probe cannot distinguish them.
   **Correction** in the notes, replace that bullet with: "`commute` returns the in-transaction value.
   `atomic(Func<R>)` passes `returnRefId = long.MinValue`, so `CommitCommutes` never substitutes the
   committed value into the transaction result; the uncontended probe cannot tell them apart. Only
   `atomic(Func<CommuteRef<R>>)` returns the committed value." No doc change beyond item 1.
