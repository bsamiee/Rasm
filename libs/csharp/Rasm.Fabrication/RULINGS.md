# [RASM_FABRICATION_RULINGS]

`Rasm.Fabrication` rulings settle package-scoped decisions.

## [01]-[PACKAGES]

- `lib3mf` and `OpenCAMLib` enter as vendored native builds — do NOT re-shop NuGet for a managed replacement: no free managed package owns full-extension 3MF write or cutter-location computation (managed 3MF entries stop at core-spec read, the commercial one fails the license gate), so a challenger enters only by owning the full concern under the license gate, never by matching the name.
- `RectangleBinPack.CSharp` stays admitted — no kernel algebra subsumes it: `OffsetOp.Minkowski` and `ArrangementOp.PlanarOverlay` build a configuration SPACE while the search over that space is this package's own concern, and `SearchOp.Rectangular` isolates the provider behind the one `StockNest.Pack` entry so the integer-frame lane never competes with the configuration-space walk; a challenger enters only by owning bounded rectangular multi-stock assignment whole.

## [02]-[SHAPE]

- Simulation reads its motion source off `SimulatePolicy` as one closed `MotionSource`, never a second entry parameter: a posted `CutProgram` folds controller semantics and a `RobotCell` folds the posed-station census `Kinematics/cell` resolves, so a new motion modality is one case and one arm rather than a sibling `Execute`.
- Provider kinematics stay behind `Kinematics/cell` whole — `Verify/simulate` consumes a provider-free `CellPosedStation` census and names no `Robots` type, so the `Rhino3dm` alias boundary has exactly one crossing in the package and posed display meshes leave as a kernel `BoundingBox` and a count.
- Cell cycle time reads `Program.Duration` off the look-ahead planner, never a re-derivation from `MotionDynamics`, which has no answer for a serial chain; per-station elapsed and travel measure against the PRIOR posed station, so the ledger sums to the planner's own clock.
- Planar sweep stays axis-free — `Move` carries no tool axis, so the swept-solid guard is exact for every admitted move; an oriented-move atom lands only with a typed refusal for unsupported axes in the same change, and a silent planar approximation of an oriented cut is the rejected form.
- Abandonment is `FabricationFault.RunAbandoned(FabConcern, Done, Witness)` — the offset-56 case `Process/faults` mints — raised on the abandoning folder's own `FabConcern`, never a rethrown `OperationCanceledException`, never the `PolicyInadmissible` policy/parameter-admission arm wearing a cancel, and never a kernel-band `GeometryFault.RunAbandoned` borrow (its `Kind` slot names geometry a fabrication run has no value for); a `Fin`-declaring entry that throws on cancel is partial and escapes the run fold. `Process/owner` stage boundaries and `Nesting/nfp`'s pair-memo leg are the landed producers, and an interior leg with no run-grain fraction states its structural zero at the site.
- A kernel fold whose rejected arm returns a SUCCESS carrying an empty result is read through its whole result carrier, never its collection row — `Toolpath/partition` projects `CloudVoronoiResult` and gates `Receipt.Status`, because the cells row alone made a degenerate dual byte-identical to a caller that asked for no depth. Discriminant: the identity fallthrough on `AtomProjection.Rows` yields the whole carrier from the SAME fold, so the gate costs no second run. Reopens only where a rail's rejected arm faults instead of succeeding empty.
- `Toolpath/surface` holds NO layout algorithm and NO layout-topology evidence — the key space is caller-minted and the generator injected, so a kernel field tracer composes inside that generator at the composition root and a topology column on `SurfacePathReceipt` is refused twice: the generator returns drives alone, so the column has no producer, and a slot shaped for one of the fifteen layouts the key space spans is dead under the other fourteen.
