# [INDESIGN]

Everything the application knows about Adobe InDesign: the installed host, the UXP plugin that carries jobs into it, the frame protocol between them, the rules every job body obeys, the tool contracts the MCP server publishes, the data files those tools read, the install and retirement steps, and the pass that configures the application itself.

Host values come from the host table the server reads at start from the installed bundle: `<indesign.bundlePath>`, `<indesign.bundleId>`, `<indesign.version>`, `<indesign.processName>`, `<indesign.prefsFolder>`, `<indesign.installFolder>`, `<indesign.featureSet>`.

Row 06 is generated, never written. A `generate` target runs `sdef <indesign.bundlePath>` for the dictionary of [01] row 25, reads it with `fast-xml-parser`, decodes the dictionary shape through one Effect `Schema`, and emits the file with `ts-morph`. Naming is mechanical: a class's name gives the interface (`text frame` → `TextFrame`), its `plural` gives the collection property (`text frames` → `textFrames`), `inherits` gives the `extends` clause, `access="r"` gives `readonly`, `<type>` children give a union, and `description` gives the TSDoc line. Return types are reconciled against live reads before the emitted file is trusted, because the dictionary states some of them differently: `find key strings` declares `<result type="text">` where the host returns the array of [01] row 18. The generator is unit 3's research step, and its gates are that the emitted file compiles and that its enumeration table equals the table `plugin.create` builds at run time.

Job dispatch is a record from kind literal to handler, not a string table: the record's key type is the union of kind literals of the `job` frame schema, so a kind with no handler fails the typecheck. `execute` is the one handler that takes code as a string.

Executor scope, around every job: `Effect.acquireRelease` reads `app.scriptPreferences.userInteractionLevel` and `measurementUnit`, sets `UserInteractionLevels.NEVER_INTERACT` and `MeasurementUnits.POINTS`, and restores both values on release, including the error path. A mutating handler runs its synchronous body through `app.doScript(fn, ScriptLanguage.UXPSCRIPT, [], UndoModes.ENTIRE_SCRIPT, '<tool>')` for one undo step; an asynchronous body ignores the undo mode, so a handler that exports or reads a file is a separate job with `undo: 'none'`.

### [02.1]-[AUTOCORRECT]

`execute` transforms the agent's code before running it. Two passes run in order, collection indexing then enum values, each parsing with acorn, mutating the tree, and printing with astring; a parse failure returns the code unchanged. Notes are built before mutation so nested accesses describe the original source, deduped, capped at ten with a count of the remainder, and returned in the result as `autocorrections`, on success and on failure alike, so the agent never debugs code that differs from what ran.

| [INDEX] | [RULE]                   | [FORM]                                                                                                                                                                        |
| :-----: | :----------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
|  [01]   | Collection indexing      | `collection[i]` becomes `__item(collection, i, "Pages")` with the helper `const __item = (c, i, n) => c?.constructor?.name === n ? c.item(i) : c[i];` prepended once           |
|  [02]   | Collection class names   | A 58-row map from property name to runtime class name; every collection reports the capitalized property name, `xmlElements` reports `XMLElements` and `xmlTags` `XMLTags`     |
|  [03]   | Array guard              | A variable assigned from `.getElements()`, `.everyItem()`, an `all[A-Z]` property, or an array literal is an array and is never rewritten; a variable assigned both kinds is dropped |
|  [04]   | Index guard              | String and template indices are skipped; write contexts (`c[i] = x`, `c[i]++`, `delete c[i]`) are skipped; the base is evaluated once inside the helper                        |
|  [05]   | Enum assignment          | `obj.prop = <literal>` becomes `obj.prop = Enum.CONST` where the map of [02.2] binds `prop` to `Enum` and `<literal>` names one of its constants; no helper stands between the assignment and the host |
|  [06]   | Enum owner basis         | The owner comes from the map, which the dictionary states per property, so no current value is read to decide whether a slot is an enum slot                                   |
|  [07]   | Dual-typed enums         | `Leading` and `UIColors` properties read back as a number and a three-element array; the map names their enumeration whatever the slot currently holds, so neither takes a case |
|  [08]   | FourCC recognition       | An integer above 1,000,000,000 and below 2,200,000,000 is treated as a FourCC code                                                                                             |
|  [09]   | Candidate enums          | Candidates are the enumerations the map binds to the assigned property name; a value matching none of their constants is left for InDesign to reject rather than replaced with an unrelated constant |
|  [10]   | Name matching            | Exact constant name first, then upper-cased with underscores stripped (`"points"`, `"allCaps"`, `"SimpleWideArrowHead"`), accepted when exactly one constant matches           |
|  [11]   | Operator restriction     | Only `=` is rewritten; `+=` and its siblings on an enum property are left to fail                                                                                              |
|  [12]   | Missing enum imports     | An `EnumName.CONSTANT` reference for a known enum not destructured from `require('indesign')` joins that destructuring, or a new `const { … } = require('indesign');` line is prepended, sorted and deduped |
|  [13]   | Missing `app` import     | A bare `app.` member access with no `app` import and no local `app` declaration adds `app` to the destructuring                                                                |

### [02.2]-[ENUM_TABLE]

`plugin.create` walks `require('indesign')` and records every exported object whose members are enumerators: `{name, constants: [{name, value}]}`. `Object.entries(Enum)` yields constant names and FourCC integers in-process, so the table is the running build's own, never a checked-in copy.

The table serves three consumers: the autocorrect enum pass, the `list_enums` tool, and the readback that renders an enumerator as `String(value)`.

A property's owning enumeration comes from the dictionary of [01] row 25, generated beside `indesign.d.ts` as one map from property name to enumeration. The dictionary names each enumeration and enumerator by its four-character code while the run-time table holds JS names against FourCC integers, so the two join on the code: `1716995704` is `fWFx`, `flex fixed`, in enumeration `fWtH`, and `1716994420` is `fWAt`, `flex auto`, in enumeration `flAE`, the two integers [04] records as belonging to an enumeration registered under no global name. The join binds every property to its enumeration and every AppleScript enumerator phrase to its JS constant, so the enum pass reads the owner instead of guessing it from the current value's `constructor.name`. The map's gate is unit 3's research step: the generated table equals the table `plugin.create` builds at run time. Constant descriptions, the reverse FourCC index, and the method-parameter map serve no consumer and are not built.

## [03]-[FRAMES]

Plain JSON text frames over `ws://localhost:39218`. The server binds the IPv4 literal `127.0.0.1` because `localhost` as a bind host resolves to `::1` alone and refuses IPv4 loopback; the plugin dials `localhost` because a UXP forum answer of 2025-03-04 reports an address with no name resolution failing. `NodeSocketServer.layerWebSocket({host: '127.0.0.1', port})` gives the `SocketServer`, `SocketServer.run(handler)` forks one handler fiber per connection, and frames pass through `Socket.readerString` and `Schema.fromJsonString(Frame)` decoded with `Schema.decodeUnknownEffect`.

`Frame` is one `Schema.Union` on `type` in the server's `frames.ts`, imported by both plugins.

| [INDEX] | [FRAME]  | [DIRECTION]    | [FIELDS]                                                                                                                               |
| :-----: | :------- | :------------- | :-------------------------------------------------------------------------------------------------------------------------------------- |
|  [01]   | `hello`  | Plugin → server | `{plugin, version, host: {name, version}, uxp, app, dom}`, `app` from `app.version` and `dom` from `app.scriptPreferences.version`     |
|  [02]   | `beat`   | Both           | `{}`, sent every 5 s by each side                                                                                                      |
|  [03]   | `state`  | Plugin → server | `{modalState, activeDocumentId, modified}`, sent on `afterContextChanged`, `afterSelectionChanged`, `afterOpen`, `afterClose`, `afterNew`, `afterSave` |
|  [04]   | `job`    | Server → plugin | `{jobId, kind, body}`, the body decoded by the handler's own schema                                                                     |
|  [05]   | `done`   | Plugin → server | `{jobId, value, autocorrections?}`, `value` the handler's JSON-serializable result or a path under `.artifacts/`                       |
|  [06]   | `failed` | Plugin → server | `{jobId, rejection: HostRejection}`, the rejection a tagged error with a `reason` field, never a rendered message                       |

Link states, one tick per second on each side through `Schedule.spaced('1 second')`, the only place a transition happens:

| [INDEX] | [SIDE]  | [STATE]                        | [TRANSITION]                                                                                                                                       |
| :-----: | :------ | :----------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------- |
|  [01]   | Server  | `listening`                    | A socket arrives and its first frame decodes as `hello` → `attached{identity, lastBeat}`; any other first frame, or a second socket, closes that socket |
|  [02]   | Server  | `attached{identity, lastBeat}` | `beat` refreshes `lastBeat`; `state` updates `identity.state`; a dispatch → `busy`; `now - lastBeat > 10 s` or a close → `listening`                 |
|  [03]   | Server  | `busy{identity, job, lastBeat}`| `done` or `failed` for `job.id` → `attached`; a stale or closed link → `listening` and the in-flight job answers `TransportClosed`                   |
|  [04]   | Plugin  | `idle`                         | Tick → `new WebSocket(url)` → `dialing{since}`                                                                                                     |
|  [05]   | Plugin  | `dialing{since}`               | `onopen` → send `hello` → `attached`; `onclose` → `idle` after 2 s, handlers detached before the socket is abandoned                                |
|  [06]   | Plugin  | `attached`                     | `beat` every 5 s; a `job` frame → `busy{job}`; 10 s with no server `beat` → `close()` inside `Effect.try` → `idle`                                  |
|  [07]   | Plugin  | `busy{job}`                    | The handler settles → `done` or `failed` → `attached`; the server sends no second job while `busy`, so the plugin holds no refusal branch           |

Timing figures and their source, all measured in Sidekick 1.0.27 and its plugin 1.0.22 against this host: server beat interval 5000 ms (`multi-client-bridge.js` `HEARTBEAT_INTERVAL`), plugin heartbeat expiry 10000 ms, reconnect delay 2000 ms, hello acknowledgement timeout 5000 ms (`uxp-index.pretty.js` `Connection` defaults). A connection refused surfaces as `onclose`, the same event a dropped live connection produces, so the plugin keeps a `socketOpened` flag to tell the two apart; UXP sockets deliver queued events late, so all four handlers are nulled before a socket is abandoned; `close()` can throw, so every call sits inside `Effect.try`.

In-flight job and deadline: one job per host is in flight, the `Ref<Option<InFlight{jobId, startedAt}>>` created in `main` and passed to the handlers, and a tool call whose host is busy answers `HostBusy{host, jobId, startedAt}` with no queue. The server forks the run with `Effect.forkDetach` and joins under `Effect.timeoutOrElse` failing with `DeadlineExceeded{host, jobId}` at `timeoutMs` from the tool input; the `job` frame carries no deadline and the plugin compares no clock, because a synchronous DOM call cannot be interrupted and `entrypoints.commands.cancel` is reserved for future use. After a deadline the in-flight `Option` stays `Some` until the host reports completion, and a late frame clears it and is otherwise discarded. An MCP cancellation interrupts the handler fiber and answers nothing; the host job runs to completion.

Result size: `jobs.ts` measures a success value's JSON text before the toolkit hands it to the layer and, above 200,000 characters, writes `.artifacts/creative-cloud/indesign/results/<jobId>.json` and answers `{kind: 'file', path, bytes, sha256}`. Images never cross the socket: the plugin exports to `.artifacts/creative-cloud/indesign/<jobId>/<name>.<ext>` under `fullAccess` and the frame carries the path.

## [06]-[CAPTURE]

Resolution is never chosen by the caller. A vision model downsamples every image to a fixed budget, so each capture renders to fill that budget and no further.

`dpi = clamp(round(min(maxLongEdgePx / longEdgeIn, sqrt(maxPixels / areaIn))), 48, 600)`, with `detail` at `{1568 px, 1,150,000 px}` and `preview` at `{768 px, 300,000 px}`. The long-edge cap binds for a thin region, the pixel cap for a page-shaped one, so the smaller of the two decides. `preview` is refused for a region or an object capture, where the point of the capture is detail. Every image result carries `{widthPx, heightPx, dpi}`.

The host renders at that resolution through `exportResolution`, so no downscaler exists on the server and `wasm-vips` is no catalog row. A capture whose page was floored to 216 pt reports `contentWidthPx` and `contentHeightPx` beside the page pixels and leaves the Paper-masked padding in the file; nothing re-encodes the image.

Each source page's `appliedMaster` content is placed first and the spread's own items after, both back to front from `allPageItems` reversed and filtered to direct children, each item skipped when its resolved box is disjoint from the rectangle, otherwise `duplicate(tmpSpread)` followed by a relative `move(undefined, [dx + "pt", dy + "pt"])` that maps the rectangle's top-left onto the page's top-left. An object capture also reports every sibling whose resolved box intersects the object's, as `{id, name, type}`. `effectivePpi` comes from the contained graphic first and the item second, and caps the dpi only when the capture is single-material: isolated, or with no overlap. Capping at a raster's own resolution with sharp text or vector art in the frame would soften that content.

Layout reads return a content area per page computed from the page side: a `LEFT_HAND` page takes `left = margins.right` and `right = pageWidth - margins.left`, a `RIGHT_HAND` or single-sided page takes `left = margins.left` and `right = pageWidth - margins.right`, and both take `top = margins.top` and `bottom = pageHeight - margins.bottom`. Those four numbers go straight into `geometricBounds`. Page and item counts are paged by cursor, never truncated in silence.

Font metrics come from `@rasm/typography`, never from the host. A family key resolves through `families.json` to a PostScript name, and the name resolves to a file over the scan roots `/Library/Fonts`, `/System/Library/Fonts`, `/System/Library/Fonts/Supplemental`, `~/Library/Fonts`, and `~/Library/Application Support/Adobe/CoreSync/plugins/livetype/.r`, walked three levels deep, where an extension-less file whose name matches `/^[a-f0-9-]{8,}$/i` is an Adobe Fonts face. The index caches under `.cache/typography/font-index.json`. A name that resolves to no file answers `{kind: 'rejected', reason: 'FontNotFound', scanned}` and a face whose OS/2 table carries no `sxHeight` or `sCapHeight` answers `{kind: 'rejected', reason: 'MetricsMissing', field}`; neither measures a substitute glyph.
