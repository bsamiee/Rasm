# Codex provider
Agent task: verify and raise the OpenAI/Codex provider of Relay against the installed app-server, 2026-09-13

Tested against app-server `codex-cli 0.154.0-alpha.6.2` inside `/Applications/ChatGPT.app` (bundle id `com.openai.codex`, app 26.908.40834); `mdfind` and `urlForApplication(withBundleIdentifier:)` both resolve to it. Protocol read from its own `codex app-server generate-json-schema --experimental` bundle and from headless stdio runs with a throwaway `CODEX_HOME` (no sign-in, no desktop launch).

Flows (all work; fixes noted):
- Sign-in: `account/login/start {type: chatgpt}` returns `{loginId, authUrl, type}`, `account/login/completed {loginId?, success, error?}` is the completion (schema + `account_processor.rs`); the desktop's own `loginWithChatGpt` uses the same call, so `auth.json` in the account's `CODEX_HOME` is shared. Works. The login-completed waiter was already registered after the URL opened; unmatched notifications are buffered, so nothing is lost.
- Identity: `account/read {refreshToken:false}` gives `{account: {type, email, planType} | null, requiresOpenaiAuth}`; `getAuthStatus {includeToken, refreshToken}` is still accepted (live: `{authMethod, authToken, requiresOpenaiAuth}`, `AuthMode` is `rename_all = "lowercase"`, so `"chatgpt"` matches). JWT path `https://api.openai.com/auth` with `chatgpt_account_id`, `chatgpt_user_id`, fallback `user_id` matches `codex-rs/login/src/token_data.rs`. Works.
- Usage: `account/rateLimits/read {excludeResetCreditDetails}`; response `rateLimits`, `rateLimitsByLimitId` keyed `codex`, `ordinaryUsageAllowed: bool | null`, `accountId`, windows `{usedPercent: int32, windowDurationMins: int64?, resetsAt: int64?}`; `resets_at` is unix seconds (`codex-rs/protocol/src/protocol.rs`), 300 and 10080 are the 5-hour and weekly windows. Signed out it answers -32600, mapped to `requestRejected` after identity already fails with `signInRequired`. Works.
- Session start: `model/list {includeHidden, cursor}` pages by `nextCursor`; `gpt-5.6-luna` is listed unhidden with efforts low..max, so the ladder picks `low`; the Codex pricing page lists Luna at 250-2,000 messages per 5-hour window against 25-200 for Terra, so it is the least costly current model. `thread/start` accepts every field sent (`ephemeral`, `runtimeWorkspaceRoots`, `selectedCapabilityRoots`, `baseInstructions`, `developerInstructions`, `config` including every `features.*` key; unknown feature keys are accepted, a float `project_doc_max_bytes` is refused, Relay encodes integral doubles as integers). `turn/start` accepts `effort` and `serviceTierForTurn` ("default" is the documented standard tier), `turn/completed {threadId, turn: {id, status, error}}` with status `completed | interrupted | failed | inProgress`, `thread/unsubscribe` returns `{status}`. Fixed: the text input carried `textElements`, the wire field is `text_elements` with default `[]`, so the field is gone; a failed turn now carries the typed `codexErrorInfo` code and `unauthorized` reports sign-in required.
- Select: `CODEX_ELECTRON_USER_DATA_PATH` is read by the desktop as its userData path (`app.asar`), and only with it set does it keep `CODEX_HOME` after loading the login shell environment and take a per-path single-instance lock, so one instance per account is the app's own design; its multi-instance launcher runs `open -n --env CODEX_HOME --env CODEX_ELECTRON_USER_DATA_PATH ... --args --user-data-dir=<path>`. Fixed: Relay now passes the same `--user-data-dir` argument. `launchDate` equality is sound: pid plus microsecond start time, and `Date` round-trips `codex-desktop.json` exactly (tested). `foregroundAccount` requires a live tracked pid, a dead selected instance clears the selection, a live one is re-verified through `account/read` before it is reported. Works.
- Sign-out and removal: `account/logout` returns `{}` and emits `account/updated`; the desktop-must-close gate runs once per action and the shared `logOut` tolerates `signInRequired`. Works.

Plumbing fixed: `CodexConnection.request` no longer spawns a `Task` inside `withCheckedContinuation`; a reply slot (`unclaimed`, `arrived`, `awaited`) exists before the write, so a reply landing during the write is kept and a `finish` during the write is seen, no leak or double resume. `CodexClient` operations are `Task`s (cancel, connection cancel, await completion) instead of a continuation array; four-line `switch` ladders became `Result.bind` chains (async bind, `flatMap` stays the stdlib form). `CodexFailure` carries typed causes (`storage(any Error)`, `desktopLaunch(any Error)`, `signInPageUnopened`, `signInRefused(reason:)`, `turnFailed(code:message:)`); `userMessage` is read only by the store. `NativeProcess` and `JSONValue` checked and unchanged: `JSONDecoder` reports `typeMismatch` for `1` as `Bool` and `true` as `Double` (tested), integers above 2^53 lose precision as `Double` but no id in use is numeric, `Int(exactly:)` is right for the second and minute fields.
